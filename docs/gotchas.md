## 8. Gotchas (proven, keep)

- **mupdf 1.28.1 wasm:** `needsPassword()` re-locks an authenticated doc (engine passes `session.locked`); a comma cannot appear in a password (save-option syntax, refused up front); `garbage=compact` renumbers objects and breaks cross-save undo (use `garbage=yes`); markup/Line/Ink `getRect()` throws (quad/line/ink union used); icon Stamp `/Rect` is resized to the icon aspect; `setLayerVisible` is neither journaled nor saved; `encodeCharacter` returns 0 on subset fonts; ToUnicode still maps the whole font after `subsetFonts()` (membership proves nothing); `addImage` caches (replace→undo→replace dangles unless grafted from a scratch doc); pre-auth parses cache undecrypted strings (reopen after unlock); native `abandonOperation` restores content but drops pre-existing redo; `Link.setBounds` takes RAW `/Rect` space (inverse page transform); `/Dest` shadows `/A` (delete it before `setURI`); links are not in `getAnnotations()`; an unchanged `setBounds` still journals; `setURI` has no scheme policy; `validateChangeHistory` is not an oracle; `pdfTime` misses PDF-2.0 offsets without a trailing `'`; outline `item()` reports no children and `down()` on a leaf empties the cursor (walk with `loadOutline()`); `resolveLink` repoints a dangling destination, so page-delete repair reads every outline/link reference before `deletePage`; `new PDFDocument` + `addPage` alone leaves the page tree empty (`insertPage` required); a rolled-back write is not byte-identical (empty object slots remain — assert page-content bytes) and a page wrapper held across a rollback keeps a stale empty annot (destroy every page wrapper in `finally`); annot `setRect` takes page space and writes the file `/Rect` through the page CTM + `/RD` (`[100,100,300,200]` on 612×792 → `[99,591,301,693]`; pypdf/Preview read the file rect); stext truncates a variable-font name at `[` (`VUFEHT+NotoSansHebrew[wdth,wght`; same-font matching strips the axis suffix); checkbox/radio On appearances are regenerated from `/MK` as `/ZaDb 32 Tf` with no `/Resources` (`/AcroForm /DR` only has `/Helv`; open item).
- **Electron/macOS:** spawn the real Electron binary, never the shim (SIGKILL orphaned a window that overwrote a fixture); macOS reserves ⌘H, ⌥⌘H (Hide Others), ⌘M, ⌥⌘M, ⌘Q, ⌘W and ⌘, (check this list before assigning an accelerator); menu accelerators need real keys (AppleScript), CDP `Input.dispatch*` never blurs; single instance lock (second instance exits 3); drive `wait` must guard `isDestroyed()`; drive opens `hello.pdf` by default; worker refusals reject in `request()` (catch them so they reach STATE); the human's app and drives share nothing but the lock; dev and packaged builds share userData `pdf4all-p0` (recovery journal + `trusted-certs.pem`), so dev runs see a packaged install's state; `session.webRequest` never sees worker custom-protocol loads (`worker.js`, `mupdf.js`, `.wasm`) — offline evidence for the worker comes from the protocol-handler log and the in-worker CSP probe; Node scripts set `process.exitCode`, never `process.exit()` (a piped report over 64 KiB gets truncated); `scripts/verify-save.py` takes `--password=Y` (the space form once raised FileNotFoundError).
- **Harness:** `packDrive` whitelist keys `page,x,y,text,key,alt,dx,dy,handle,escape,shift`; `expect` = subset deep match with exact array lengths; help rows pinned at 11 (`p2-shell`, `p3-drive`, `help-fields.jsonl` lines 4–5 — the count went 6→7 Redaction, 9→10 Verify Signatures, 10→11 Direct editing; every new Help row updates all three); a normal launch paints the startup `hello.pdf` first, so a canvas>0 wait passes early — wait on the target document title; repeated CDP evals of a global `const` throw "already declared" (wrap polls in an IIFE); the P0 smoke probe expects exactly one canvas outside `#thumbs`; `nav.links` deep-equalled in `tests/p3-drive.test.mjs`; seven Forms-mode steps on `nav.pdf` sit inside its GoTo link (paint link targets under field targets); `tests/p1-open.test.mjs` had a single-instance journal flake (fixed).
- **mupdf journal (more):** without `enableJournal()` (called right after `disableJS()` at open) `beginOperation()` silently does nothing; `hasUnsavedChanges()` stays true after `saveToBuffer`, so dirty = journal position vs a `savedPosition` baseline moved by `{op:'saved'}`; `getJournal`/`canUndo`/`canRedo` throw while an operation is open, `abandonOperation` twice or with none open throws, and `endOperation` must never follow an abandon; begin + any write + abandon wipes the redo branch (an empty abandon keeps it), so all validation runs before `beginOperation` and `mutate()` cuts `savedPosition` only when the branch was actually cut.
- **mupdf caches and page tree (more):** caches go stale — `getAnnotations` after undo/redo, `getWidgets` after direct COS edits (`page.update()` does not refresh), a Link's `getBounds` right after `setBounds`; `loadPage` returns the cached page while any handle is open, so destroy page wrappers and reload; an undone write also leaves empty xref slots, so after undo compare content or decoded streams, never file bytes; `rearrangePages(p)` makes new page i = old page `p[i]` (out of range throws `cannot find page N`) and nested ops fold into the outer journal op; undo/redo replies carry the step name and the renderer's `PAGE_STEPS` must include `insert pages`; a link/outline to a deleted last page prints `cannot find page N in page tree` on the next load; grafted widgets are not in `/Fields`, so the engine registers them itself.
- **mupdf spaces, search, missing API (more):** page space is y-down with `/Rotate` applied (`getTransform` `[1,0,0,-1,0,792]`) while pypdf is PDF y-up; text-annot `getRect`/`setRect` are y-down, a fresh in-memory annot's `getBounds` is y-up but y-down after reload, and search quads share `setQuadPoints`' y-down space; `structuredText.search()` rejects `{maxHits}`/`{max_hits}`, so call `search(needle)` and cap hits yourself; rotated text extracts in drawing order and a partial-string hit is per-character quads (tests union them); members documented "only mutool run" are absent from the wasm (every `PDFWidget` sign/validate member, `createSignature`, `PDFPage.process`/`clip`, `wasPureXFA`, `saveJournal`, `setJSEventListener`, `findPageNumber`, `lookupDest`, `verifyEmbeddedFileChecksum`, `get/setEditingState`), so XFA is detected by reading `/AcroForm /XFA` through the object API.
- **mupdf forms and widgets (more):** `getFieldType` returns lowercase names; `getValue` on a radio kid returns the group value (per-kid state from `/AS`, on-state only from the `/AP /N` keys); `setTextValue`/`setChoiceValue`/`toggle()` always return 1 and validate nothing, so the engine enforces every bound; a widget whose page was destroyed throws `annotation not bound to any page`; widgets have no `setValue`, so value sanitising is COS delete only; `/Ff`, `/TU` and `/V` are read inheritably kid-first, so parent writes are invisible when kids shadow the keys; `getLabel()` falls back to `/T` (`FieldItem.tu` is the raw key); a combo `/V` is a string (use `widget.getValue()`); radio kids share one name, so identify them by object; `update()` writes `/AP` without `/NeedAppearances` but never synthesizes one for a widget that has none; button `/AP` is regenerated from `/MK` on fill (create-time streams are discarded), so authored buttons need explicit `/AP /N` states plus `/MK /BC [0] /BG [1] /R rot` (and `/BS /W 1`); moving a `/Rect` needs `/AP /N` and `/D` deleted, then `update()`; `refreshAppearance` keeps an existing `/AS`, so a button default must put `/AS` in the create dict; a `/DA` naming `/Helv` resolves only through `/AcroForm /DR` (a generator using the page's `/F1` writes a `/DA` with no `/DR` font); `info.xfa` is detected but blocks nothing and MuPDF happily authors fields into XFA, `/NeedAppearances` and certified documents, so designer refusals run before any COS write; deleting a signature field dict without its `/AcroForm /Fields` and page `/Annots` refs leaves a dangling ref, `wasRepaired` turns true, and our validate rejects the output.
- **mupdf links and outlines (more):** `getBounds` returns y-down page space, `createLink` takes page space and `getLinks` y-flips rects (the file `/Rect` pypdf reads is authoritative); `getLinks` skips entries with no `/Rect`, no `/Dest`/`/A`/`/AA`, or a JavaScript action, so its indexes drift against `/Annots`; `createLink(rect,'file:///…')` writes `/GoToR`; `setURI` turns `javascript:` into `/S/URI` and `file:` into `/GoToR` (reported as a page link) and throws on `'#page=99'` and `''`, so check scheme and page first; `isExternal` is a regex, not an allowlist; pass a plain object to `formatLinkURI` (there is no `LinkDestination` class; `formatLinkURI(fitDest(2))` = `'#page=3&view=Fit'`); `deleteLink` on the same live page records no journal step; a numeric `/Dest` resolves to a stale index after page delete; `/Annots` object numbers survive `garbage=yes`; outline `insert()` inserts before the cursor, `update({uri: undefined})` clears the destination, and delete removes the whole subtree.
- **mupdf encryption, signatures, history (more):** save option `permissions=` alone fails (`invalid pdf option`) but works with `encrypt=aes-256`, and `/P` feeds RC4 key derivation, so custom-`/P` RC4 fixtures come from pypdf; `authenticatePassword` returns 0/2/4 (fail/user/owner); an owner session's `hasPermission` ignores `/P`, so compare raw bits via `permissionBitsOf` (print 4, edit 8, copy 16, annotate 32, form 256); `encrypt=keep` re-encrypts with the source algorithm, RC4 included; `info.signatures` counts only `/Sig` fields with a `/V`, and any such field makes the document signed → read-only → unredactable; `info.versions` = `countVersions()`−1 and a full rewrite collapses `/Prev` to one revision; mupdf writes `/ByteRange [0 0 0 0]` back at variable width (hence the fixed-width 10-digit sentinels), and only one `saveToBuffer('incremental')` works per opened document (a second points `/Prev` at the previous buffer), so reopen from bytes between incremental saves.
- **node:crypto:** `createPrivateKey({type:'pkcs12'})` fails on Node 22 and on Electron's Node 24 (hence `src/sign/pkcs12.ts`); `X509Certificate.checkIssued()` + `verify()` accept a CA:FALSE issuer, so every issuer must have `x509.ca === true` (`fixtures/p5/signed-false-ca.pdf` guards it).
- **Content writing and redaction (more):** run widths use the full advance `tx = ((w0 − adj/1000) × Tfs + Tc + Tw) × Th` with `Tz`/`Tc`/`Tw` tracked; `Tw` applies once per single-byte code 32 in simple fonts and never in CID fonts (without it a `Tc 1.5` line was off 1.5 pt per character); base-14 fonts map — and € only by glyph name (`editAdvance` falls back to the standard-14 font by name); content streams concatenate, so an earlier element ending in an unmatched `q … cm` blanks appended text (hence `unbalanced-content`; upgrade path: emit the inverse residual CTM), while an unclosed `BT` is harmless; `editPrivatise` is not idempotent — privatise shared/inherited `/Contents` once per stream element, with exactly one `editSplice` per element (overlapping edits give `write-failed`); `applyRedactions` keeps a touched shared Form/Image placement (private filtered copy, `Do` kept, original still readable elsewhere), so sharing is judged per placement and any other unmarked placement refuses `shared-content`; it strips `/ActualText` and `/Alt` from redacted StructElems itself, so preview's struct count is pessimistic, not wrong; moving a redact mark needs `annot.clearQuadPoints()` or MuPDF redacts the old quads, `setRect` on a quadded mark grows it 1 pt, and `hasQuadPoints()` is a type capability, so read `getQuadPoints().length`.
- **Electron/build (more):** a module worker drops messages that arrive while `mupdf.js` is still instantiating wasm, so `src/renderer/worker.ts` posts `{ready:true}` and the renderer waits for it before sending the PDF; `Menu.setApplicationMenu(null)` removes the macOS app menu and kills ⌘Q/⌘W, so keep the native app/edit/window menus and never bind ⌘H, ⌥⌘H, ⌘M, ⌥⌘M, ⌘Q, ⌘W or ⌘,; every `.js` served under `app://` needs a `src/policy.ts` asset-map entry and a `localAsset` assert in `tests/p0.test.mjs` — a missing one is a silent 403 that kills the renderer only in the real app (`node --test` imports `build/` directly), so `npm run smoke` is the real guard; tsconfig has `rootDir` `src` / `outDir` `build` and `app://` serves only `build/renderer/`, so code shared by worker and main lives in `src/renderer/` (main/policy import `./renderer/limits.js`), and `engine.ts` must keep re-exporting every name tests import (a missing ESM re-export is a SyntaxError that kills the whole test file); `src/renderer/limits.ts` is the single source of `MAX_PDF_BYTES`/`MAX_SAVE_BYTES`/`MAX_REDACT_SOURCE_BYTES` (`policy.ts` and `engine.ts` re-export) except a deliberate `MAX_SAVE_BYTES` copy in the sandboxed CJS `src/preload.cts` with no drift test, and `worker.ts` `PROBE_MAX_BYTES` 1,000,000 is the P0 probe bound, not the open ceiling.
- **Renderer (more):** `createLatestGuard` (newest open wins, checked after fetch and after `arrayBuffer`) and `createGate` (the one-slot `workerGate`) live in `engine.ts`; `drain()` must check its generation right after the await, before `remember()` and clearing `inFlight`, or a stale page lands in the new document's cache; the seam owns every request's `id` as the worker correlation key, so item ids travel in separate fields (`annotId`, `widgetId`, `outlineId`, `linkId`, `layerId`); `request()` rejects on every `ok:false` reply, so `reply.ok === false` branches are dead code — catch the rejection and map `refusalOf(err).reason` into STATE and the dialog (missed twice: stale `sign.last`, stuck "Verifying…"); with no printers `webContents.print` fails at once, so the fallback is a native Save dialog `<name>-print.pdf` + `printToPDF`, and print failures map by substring of Chromium's `failureReason` (`cancel` → cancelled; no printer(s)/no valid printer/not found → `no-printer`; else `failed`), so a Chromium wording change silently becomes `failed`; a second `showModal()` on an open `<dialog>` throws, so the Escape keydown handler returns early while a dialog is open, and dialogs use native cancel and focus restore, no hand-rolled trap.
- **Shell CSS/DOM traps:** the page-number input blurs after Enter or it swallows menu chords; `body` needs `grid-template-columns:minmax(0,1fr)` so nowrap rows do not widen past the window; CSP `style-src 'self'` forbids inline style attributes (`element.style` is fine); `#thumbs` stays the bounded scroll container; fit zoom measures `#viewport`, so panels use no width transitions; no CSS transform/zoom on `#page`, `#canvas` or their ancestors; leaving Annotate resets `aria-pressed` tools; `role=radio` needs `aria-checked`; a hidden panel returns focus to its tab.
- **Direct manipulation (more):** the renderer px→pt round trip is inexact (4342 of 10025 integer cases, e.g. 499.99999999999994), so round to 0.01 pt or check rects with `pick()` ±0.05; the 3 px drag threshold is in CSS px, so click-vs-drag drive steps hold only at a pinned zoom; a drive's window-dispatched `pointerup` never reaches a `#page` listener, so drags listen on `window` without `setPointerCapture`; `preventDefault` on `pointermove` cannot stop a selection that `mousedown` began, so call it on `pointerdown` or in a `selectstart` listener; never mark a selected target `.active` (`.hit-target.active` has `pointer-events:none`), use `.selected`; object `targetId`s include the op byte offset, so re-resolve them at `pointerup`; the stale-scan guard compares `ContentScan.docGeneration` (the renderer's open counter), not the engine's generation; compare transforms in tests with `.map(v => v + 0)` because strict `deepEqual` separates −0 and 0.
- **Drive scripts (more):** one JSON object per line (`#` comments), step `{cmd, contents?, expect?}`; `open`/`save-to`/`save-in-place`/`print-to`/`wait`/`state` run in main and every other `cmd` goes to the renderer's `runEditRequest(op, contents)`; line-level `path`/`to`/`from`/`images`/`range` answer native pickers and persist across later lines, so order steps so a stale `to`/`images` is never reused; a bare `{expect}` re-checks the last STATE; per-step timeout 60 s, no global timeout; exit 0 iff every expect matched; usage `node scripts/drive.mjs <jsonl> [--gui] [--out=<dir>] [--report=<json>]` after `npm run build`; keys outside the `packDrive` whitelist go in `contents` (`wait` uses `ms`), so a new gesture modifier must join the whitelist; a pending `wait` resolves on any unsolicited STATE and `driveDirectGesture` returns silently on a miss, so every gesture step needs an `expect` that would fail; `expect` arrays (`matches()` in `src/main.ts`) also need exact order and primitives compare with `===` (no ≥, contains or +1), so adding an element to a STATE array breaks old scripts, and refusal text must be exact; number bases follow the dialogs: `insert.after` 0..n, `labels.from`/`link.page`/stamp pages 1-based, `goto`/`page`/`index`/`pages.ids` and click/gesture pages 0-based, stamp pages omitted or `''` = all; dialog ops (`insert`, `watermark`, `header-footer`, `labels`, `link`, `bookmark`) open the dialog when `contents` is null, otherwise fill it and call its own save function; `--drive` implies smoke and always opens `hello.pdf` first, so no-document refusals, the dirty discard box and the close prompt cannot be driven and are checked in code; `save-to` is Save a copy and leaves the document dirty, while only `save-in-place` clears dirty and it writes back to the opened path, so open the `${OUT}` copy first.
- **Harness/host (more):** `P1_THUMBS` fires only when the sidebar is open (≥ 2 pages), so `--expect=P1_THUMBS` on a one-page file times out by design; the P0 isolation probe's single `canvas:not(#thumbs canvas)` must also be first in DOM order, and its width is compared with `renderer.pixelWidth` (dpr-aware), not 612; userData `pdf4all-p0` holds `pending-saves.json` and `cleanupOrphans` at `whenReady` unlinks the temps listed there even when another process owns them, so every Electron-spawning test needs a unique `--user-data-dir` (`node --test` runs ~7 files in parallel); driving the GUI with osascript hangs if the human closes the window, so prefer drive scripts and do keystroke walks only when the human is away.

## 9. Oracles

`npm test` (node --test) · `scripts/drive.mjs` STATE expects · `verify-roundtrip.py`/`verify-save.py` (pypdf + `qlmanage` pixels, flags in §2) · `verify-edit-region.py` · `verify-redact.py` (independent extraction + object inspection) · `verify-sign.py` (pyHanko: INTACT / ENTIRE_FILE / trusted, DocMDP level; stricter than the app on keyUsage) · fixture sha256 (`checks/fixtures.sha256`, `PINNED_SHA256`, provenance scan) · real-CDP shots (`checks/shot-direct*.mjs`, `scripts/gui-shell-check.mjs`) · `scripts/measure.mjs` budgets in the packaged app · `--smoke --expect`. Evidence rules: a drive script passes 3 consecutive runs each exiting 0 ("passed once" is not evidence); no duplicate clicks or sleep steps to hide settle bugs (every command awaits settle, a human's first click must work); render saved outputs (pixmap) to catch state leaks — structural or regex checks are not enough. `hello.pdf` oracle: 1 page 612×792, base-14 Helvetica 36 pt, 615 B, sha256 `229ca948…5b94`, regenerated byte-identically by `fixtures/make-hello.py`; `StructuredText.asText()` is exactly `"PDF4All\n\n"` and pypdf `extract_text()` is `"PDF4All"` (use `includes()`/`trim()`), Helvetica renders as embedded Nimbus Sans, and there is no "Hello" (search tests use PDF4All; Hello must give 0 hits). `fixtures/form2.pdf`: only the checkbox and radio widgets carry `/AP`, so the merge oracle is "every widget that had `/AP` keeps one".
- **Memory and timing:** memory gates read `getAppMetrics` `peakWorkingSetSize` (KiB) of the large Tab process (renderer + worker) only; "600 MB" is decimal ≈ 572 MiB, and the second ~53–64 MiB Tab present at any document size is Chromium's spare renderer, not a document copy; measure save memory with retained content because padding is dropped on rewrite (clone `hello.pdf` with pypdf and attach `random.Random(0).randbytes(N MiB)`); redaction memory recipe = N pages of 612×792 each with an 1800×1200 random-RGB image plus token `BIGTOKEN-5150`, drive `createEngine` from `build/renderer/engine.js` through search/add/apply with every sanitize key under `/usr/bin/time -l`, and confirm the measured run reached the code under test (an early figure measured the too-large refusal); MuPDF caches pages, so timing harnesses need fresh processes plus a warm-up page (`scripts/measure.mjs`: 3 fresh processes per fixture, medians; `--once` prints one run).
- **Headless engine probe (reviewer reruns):** in Node, `import { createEngine } from 'build/renderer/engine.js'`, `E = createEngine(mupdf)` with the `mupdf` package, `s = E.createSession()`, then `E.dispatch({id, op:'open', name, pdf}, s).reply` and further ops; `pdf` must be an `ArrayBuffer` (a Node `Buffer` throws).
- **Save verifiers:** `scripts/verify-save.py` hashes the canonical object graph reachable from `/Root` and `/Info` (renumbering-neutral, decoded streams, `/Length /Filter /DecodeParms` and `/ID` ignored), so a Producer/ModDate diff is policy, not loss; its `--render` is first-page Quick Look no-op equality and never an edit pass criterion; `--encryption <pdf>` checks `/V /R /Length /P` and needs the `cryptography` package; `verify-roundtrip.py` has no `--render`. Process-death check (no test covers it): a child `node` imports `saveCopy` from `build/safe-write.js` with an `inject` hook (`writeAll` or `dirSync`) that pauses, then gets SIGKILL; expect the source unchanged, a pre-existing target whole (old bytes after a mid-write kill, new after rename) and exactly 1 orphan `.tmp` after a mid-write kill, 0 after rename.
- **Content and redaction verifiers:** `scripts/verify-edit-region.py BEFORE AFTER --rect x0,y0,x1,y1 [--margin 2]` (qlmanage 800 px + `sips`) requires byte-identical RGB outside rect+margin and ≥ 1 % changed pixels inside, renders page 0 only (any other `--page` exits), treats repeated `--rect` as a union, and takes PDF y-up rects while drive/UI rects are y-down; `verify-roundtrip.py --font-names '<JSON {page:[BaseFont]}>'` asserts Type1 + WinAnsiEncoding + no `/FontFile*` (guards `addSimpleFont(…, 'Latin')` against a future mupdf changing 'Latin') and `--no-tj-on <text>` exits 0 when the run is `Tj`, 1 when `TJ`; `verify-redact.py <out> --token P0B-SECRET-7731 [--all-toggles] [--expect-alt] [--expect-surfaces …]` always fails on page-content/XObject hits, trailer `/Prev`, `%%EOF` count ≠ 1 or a leftover Redact, and fails other-surface hits only under `--all-toggles` or outside `--expect-surfaces` (expect exit 1 on `fixtures/redact.pdf` with content 7 / other 38, exit 0 on the acceptance output); recoverability oracle `.venv-qa/bin/python scripts/p0b/recover.py <pdf> <token>` scans raw bytes, decompressed streams/strings, XMP, attachments and annot/field/outline/OCG/struct dicts and is the proof for redaction and orphan claims, but it is ASCII/latin1-only (for CJK scan for the old CID hex) and plaintext absence in encrypted bytes proves nothing; the P0-b edit probe saved with `garbage=compact`, so its orphan/recoverability results do not transfer to the product's `garbage=yes` saves.
- **Independent-reader limits:** `qlmanage -t -s 800 -o <dir> <pdf>` renders page 1 only, so later pages need a mupdf pixmap; pypdf is weak at CJK/RTL extraction and concatenates adjacent `Tj` runs, so pair mupdf structured-text extraction (bboxes prove a tail shift) with Quick Look pixels; pypdf "Odd-length string" warnings on mupdf-written ToUnicode CMaps are harmless; test page-coordinate maths on an offset-MediaBox page (`fixtures/edit-tj.pdf` page index 3, MediaBox `[20 30 632 822]`), because a `[0 0 612 792]` fixture cannot catch a 700-pt space error.
- **Smoke, network, wasm audit:** `npm run smoke` is a source `electron . --smoke` run, not packaged proof; the packaged run is `out/PDF4All-P0-darwin-arm64/PDF4All-P0.app/Contents/MacOS/PDF4All-P0 --user-data-dir=<tmp> --smoke [--fixture=large.pdf] --report=<path>`; a smoke passes when the `P0_SMOKE` line has `ok`, `sandbox`, `noUnexpectedRequests` and `networkProbeDenied` true and `protocolRequests` lists every served module (renderer, engine, engine-core, limits, content-edit, worker, vendor mupdf, fixtures), which proves the asset map and CSP admit a new module; no-network proof = sample `lsof -i -P -n` every second during a packaged `--smoke` (0 lines for PDF4All), then rerun with Wi-Fi off expecting `ok:true`, and `--net-log=<path>` captures Chromium's net log; when auditing the wasm for compiled-in libraries count each library's own symbol prefix (`cmark_*`, `jbig2_*`, `hb_*`, `FT_*`, `jpeg_*`, `opj_*`, `gumbo_*`, …), never one guessed function name, and re-audit on every engine or build-flag change (gate G8).
- **Signing oracles:** `scripts/verify-sign.py <pdf> [--ca fixtures/p0b/.ca/ca.pem] [--expect-signatures n] [--expect-certified P]` (pyHanko 0.37.0, no fetching) prints one INTACT/INVALID + coverage + trust + docmdp line per signature and exits 1 on any failure or mismatch; check signature appearance with a mupdf pixmap plus `qlmanage`, never Preview's signature panel; after a second incremental signature pyHanko reports Sig1 `ENTIRE_REVISION` (correct) and Sig2 `ENTIRE_FILE`, partial coverage must end at `%%EOF` plus ≤ 2 EOL bytes, and pyHanko's `CONTIGUOUS_BLOCK_FROM_START` is what the app rejects as `byte-range`; pyHanko is not the oracle for `signed-ec` (app trusted, since an absent keyUsage is unrestricted per RFC 5280) or `signed-sha1` (app valid with `weak-digest`); mupdf `validateChangeHistory()` is never an oracle (returns only 0/1, misses a flipped byte inside the ByteRange, rates allowed fills and illegal annots alike, stays 0 after a second incremental signature); the legacy-RC2 PKCS#12 test runs as `ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/Electron.app/Contents/MacOS/Electron --test tests/p5-sign-crypto.test.mjs` (repo Node 22.23.1 lacks rc2-40-cbc) and also cross-checks with `openssl cms -verify` when `openssl` is on PATH.
- **Real-UI and drive oracles:** drive masks real-UI paths (armed clicks rerouted, Tab/Enter call `finishDirect`, hidden handles get `pointerdown`, refusals never shown), so UI units also need real-CDP checks: spawn the real binary with `--remote-debugging-port=<free> --remote-allow-origins=* --user-data-dir=<dir> . --drive=<jsonl> --gui`, attach via `/json/list`, send `Input.dispatchMouseEvent`/`Input.dispatchKeyEvent`/`Input.insertText`, hover or focus before reading handle rects, `Page.captureScreenshot`, and view every shot; only save (`garbage=yes`) → reopen → `listLinks` proves a link-rect rewrite (including on a `/Rotate 90` page), since a pre-save live read passes even for a wrong raw-space write; password-leak oracles: `tests/p2-encrypt.test.mjs` scans every reply for the password strings, main refuses a smoke whose `P2_EDIT` contains a CLI password, and drive redacts `password`/`encrypt`/`encrypt-keep` contents and fails any STATE containing them.

## P2 behaviour decisions (authoritative human decisions, moved verbatim from progress.md §1)

| Decision | Outcome |
|---|---|
| CSP (2026-09-16) | `img-src 'self' data:` approved (print rasterisation needs it) and `blob:` rejected; thumbnails are per-row `<canvas>` via `putImageData`, never blob/PNG URLs; print is raster through our own engine (JPEG data-URL `<img>` sheets in `#print-pages`, then `webContents.print`); PDFium `<embed>` (a second engine that runs document JS) and print-DOM canvases (4 B/px; accelerated canvases print blank) were rejected |
| File modes (P2 U6/U7) | New files (`writeNew`, Save a copy to a new path) get `0o666 & ~umask`; an overwrite keeps the source file's mode; every new file or copy (exports included) goes through the single `writeNew` path via an exclusive 0600 temp; only the recovery journal stays 0600 (`src/safe-write.ts`); older contract text saying 0600 is stale; text export needs the `/P` copy bit and page-image export the print bit |
| Save / close (P2 U1) | Plain Save (⌘S) refuses `source-changed` if size/mtime/dev/ino changed since open, keeps the source file mode and makes no backup; Save As writes a copy and the open document keeps its path; the close prompt is Discard/Cancel with no Save button (deferred simplification) |
| Shortcuts | Every shortcut has exactly one owner, the main-process menu accelerator; the renderer keydown handler takes only chords with no menu item (⇧⌘T, ⌘O, zoom, ⌘F) and has no ⌘Z/⇧⌘Z/⌘S/⌘P branch; the discard prompt belongs to main and appears before the file picker |
| Page delete (P2 U5) | No confirmation (Undo restores it); inside the one `delete page` op it measures doomed links and dangling outline ids, deletes those links in descending index, clears the outline uri (titles and subtrees kept), deletes the page, then prunes fields left with no widget |
| Links (P2 U5) | Only http/https/mailto are followed (others show as blocked and keep their raw uri); main re-checks the allowlist and asks natively before `shell.openExternal`; smoke/drive only log `P2_LINK {uri, allowed}`; `link-add` refuses other schemes before mupdf can write a `/GoToR` |
| Insert / extract pages (P2 U6) | Insert appends grafted top-level fields to `/AcroForm /Fields` (colliding `/T` → `name (2)`), does not merge source bookmarks and refuses encrypted sources even with an empty password; Extract is allowed on read-only documents and never touches the open document |
| Stamps (P2 U8) | Watermark/header/footer are wrapped as `/PDF4All <</Kind …>> BDC … EMC` (font `/PDF4AllF` Helvetica, one reference per page) so they can be found later, but today only Undo removes them |
| Security (P2 U10) | New encryption is always AES-256 (RC4/AES-128 are only preserved via `encrypt=keep`); changing security needs owner auth or an unencrypted document; `security-set` is not journaled and cannot be undone (Save a copy leaves it pending); a blank owner password is written as the user password; RC4 sources show "weak encryption" in the banner |
| Passwords | Travel renderer→worker only (never IPC, logs or `P*_` lines); ≤ 1024 chars (`MAX_PASSWORD_CHARS`) with no attempt limit, lockout, show-password or remembering; a wrong one returns `authenticated:false`; SASLprep is not promised, so the dialog says "ASCII recommended" |
