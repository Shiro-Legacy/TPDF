### P1 — safe reader (closed 2026-09-16, 53 tests)
Open (120 MiB, token URL, streamed), Save As (50 MiB, safe-write transaction + orphan journal), zoom/fit, search, thumbnails, drag-drop, print (raster → `webContents.print`, no-printer fallback `printToPDF`, 40 MiB data-URL cap, measured in `.quad/shared/p1/unit5-print-large-all.json`, which `src/renderer/renderer.ts` cites, so keep that file), password entry worker-only, signed/certified/encrypted docs read-only. Defect fixed later (P3 U6): unlock reopens from the kept bytes because MuPDF caches pre-auth parses with undecrypted strings. Timeouts: worker requests have a 20 s renderer watchdog that terminates the worker; save/validate has its own 120 s timeout that only rejects the save. Worker failure tokens are exact: `read-only`, `encrypted`, `too-large`, `invalid`, `no-document` (main adds `write-failed`). Page cache: 96 MiB of RGBA plus a cap of 8 entries, oldest evicted, newest always kept (a 4096-edge page is up to 64 MiB).
**Ceilings:** open 120 MiB is a best case measured on padded one-page PDFs (Tab 552 MiB at 120 MiB, 604 at 180 = over budget, 766 at 250); image-heavy files cost more per page, bounded only by the 4096 px edge and the page cache; before the token URL the overhead was ~3.5× and the cap 60 MiB; ceiling files are generated by `fixtures/minipdf.py` into `/tmp/pdf4all-p1-ceiling/` and never committed. Node has no `F_FULLFSYNC`, so macOS fsync reaches only the drive cache and power-loss durability is not promised; a failed directory fsync still reports success with `durability-uncertain`. Print data URLs are capped at 40 MiB (`PRINT_MAX_BYTES`, `src/renderer/renderer.ts`) because all 500 pages of `large.pdf` made 52.6 MB of data URLs and peaked the Tab at 586 MiB (> 572 MiB = 600 MB); cost is ~6.5 MiB of Tab per data-URL MiB (~380 text pages), so raising the cap needs a new measurement; sheets are 150 DPI JPEG q0.85 and pages longer than ~27 in cannot reach 150 DPI. Print is raster only: no preview, no per-page paper size, no vector output, one job at a time, and the OS dialog holds every sheet while open; named `@page` landscape pages work.

### P5 — signing (U1 accepted 2026-09-23, 379 + 1 skip; U2 accepted 2026-09-23, 391 + 1 skip)

## §5 Process — full-mode pipeline, bus and workflow text

**Unit pipeline (every unit):** orchestrator drafts `.quad/shared/<phase>/contract-<unit>.md` (§0 ground rules below, §1–§6 spec with exact ops/STATE/drive steps, §7 ownership covering **every** file the unit can touch incl. `scripts/drive.mjs` and `src/main.ts`, §8 acceptance = suite + drives ×3 + hashes + shots viewed + one real CDP gesture rerun by the orchestrator + `npm run package`) → objections workflow (Opus 5.5, three refute-first lenses: engine+fixtures, renderer/UX with real mouse, tests/drive/evidence; blocking items adversarially verified) → accepted items (numbered, each backed by a probe) folded into §9, whose amendments override the body → **human approves the contract** → backup tgz + hash snapshot → build workflow (fixture agent alone first, then engine / renderer / tests in parallel with strict file ownership, then an integrator: suite, drives ×3, hashes, shots) → review workflow (three refute-first lenses → owning-role fixers, each fix with a test that fails on pre-fix code and each new guard test shown to bite — delete one key or branch locally, e.g. an `OP_PERMISSION` entry in built `engine-core.js`, see it fail, rebuild → independent rerun) → orchestrator acceptance under one lock hold (`accept-<unit>.sh`) → `acceptance/acceptance-<unit>.md`, this file, memory. Windows for a reset: after the build workflow returns and after the review's rerun file exists; never mid-workflow. Write every contract/objection/review/evidence file to disk immediately. Templates live in `.quad/shared/p6/scripts/` (`p6u4-build.js`, `p6u4-review.js`, `accept-u4.sh`).

**Test rules:** new Help text goes into existing cells, or all three row-count pins (§8) change together, and every `CONTENT_REASON_TEXT` value must appear verbatim (entity-free) in `#help-dialog`; never insert lines into an existing drive script (`tests/p3-drive.test.mjs` pins step indices and counts) — add a new JSONL with its own test file and copied helpers; each Electron drive test is one `test()` per script with `{ skip: CI_NO_ELECTRON, timeout: 180_000 }` and `drive(…, 150_000)`, and setting `CI_NO_ELECTRON` skips every Electron-spawning test; real-app checks touching the trust store pass `--user-data-dir=<scratch>` and must leave `~/Library/Application Support/pdf4all-p0/trusted-certs.pem` absent or empty (only `--smoke`/`--drive` honour `opts.path` in `trust-add`/`pick-certificate`).

**Quad bus (paused):** launchers `.quad/run/<seat>.sh`, roster `.quad/roster`, `qmsg` at `~/quad/bin`. Rules when it returns (human decision 2026-09-17): direct messages to the orchestrator + affected seat, never `all` or `--quiet` (suppresses the wake); claim before shared work, `done:` after; paths not code; no nested subagents in a pane. Bus reset = `qmsg reset`.

**Rules learned on the bus (still binding):** the build-slot holder does not re-claim between its own builds; a seat that builds during another's slot invalidates its results (the holder reruns `npm run build && npm test`, the intruder lists the `src/` files it changed); while the orchestrator's acceptance run holds the slot every seat holds `src/` and `tests/` edits; drives run whatever is in `build/`, so a run against a pre-fix build is not evidence (a failing TS build under `noEmitOnError` leaves the old `engine.js` in place) — run a fresh `npm run build` after the last source edit, then drive. Ownership is exclusive because concurrent writes overwrite each other: a seat needing a change in another seat's file sends the owner `path:line` plus a one-line intent and the owner edits; if a non-owner already saved, the owner re-reads before its next save. Reviewer fixes claim the file to its owner first and each comes with a test or drive step that failed before the fix. Cadence: objections ≤ 30 min (builders meanwhile start on parts objections cannot change); accepted objections become §8/§9 amendments with a named owner; review brief 60–75 min; reply format `review: <unit> — ACCEPT|REJECT, n fixes, path`. Fixture change = regenerate from its `make-*` generator, update provenance + the sha256 pin in `tests/fixtures.test.mjs`, check with `node --test tests/fixtures.test.mjs` (no build); every string a test targets must be unique on its page (identical runs = `ambiguous-text-association` and the test silently never runs). qmsg subjects are cut at ~150 chars (details go in `-b`); implementers send only the final `done`.

**Lean mode (use when the human asks for lower token use):** ultracode off; one workflow for the build and one for the review of a unit, nothing else; objections = one lens per role with one refuter per blocking item only; no critic passes on contracts (the orchestrator folds §9 itself); workflow agents write results to disk and return paths + counts, never full text; every agent reads only the contract sections and maps it needs, not this whole file; open a session with a narrow prompt ("read progress.md §0, §5, §11 and the P6 U4 record, then show me §9 for approval"); one unit per session. Full mode (the pipeline above) stays the default when the human does not ask.

**Subagent mode (now):** Workflow tool, every agent `model: 'opus'` (Claude Opus 5.5); pipeline/parallel with schemas; journals under `~/.claude/projects/…/subagents/workflows/<run>/journal.jsonl`; workflow agents run Electron drives, so keep `--drive` paths crash-proof (a reviewer's run once popped an "Uncaught Exception" dialog on the human's desktop). The review script names an owner for every file, and every GUI shot is viewed with `Read` before acceptance.
