# Design note — driving PDF4All without the GUI (human proposal, 2026-09-16 23:55)

Problem seen this session: the only ways to verify the app end-to-end are (a) hardcoded `--smoke` sequences in `main.ts`/`renderer.ts` (one per unit, each a new code path), and (b) AppleScript keystrokes + CDP reads, which are brittle (menu needs System Events, native sheets cannot be typed into reliably, a human touching the window breaks the run).

Smallest useful system (reuses what exists; no new dependency):
1. **`--drive=<script.jsonl>`** in `main.ts`: replaces the per-unit smoke branches with one generic replay. Each line is `{"cmd": "<edit-request op>", ...args}` — the *same* `edit-request` channel the menus already use (`content-edit`, `note`, `pages`, `security`, …) plus `open`, `save-to`, `undo`, `redo`, `password`, `wait` — or `{"expect": {...}}` matched against the state dump. After each command the renderer posts one generic **`STATE {...}`** line (the union of today's `P2_EDIT`/`P3_EDIT` summaries: page count, dirty, journal, annots per type, fields, targets, refusals, last announcement). The report is the sequence of states; exit 0 iff every `expect` matched. Existing smokes become scripts under `tests/drive/*.jsonl`; `--smoke` stays for P0/P1 security probes only.
2. **`window.pdf4all.state()`** (preload, read-only, no document text) for CDP readers, so a GUI check reads one JSON instead of scraping ids.
3. **Native dialogs bypassed by design**: `save-to`, `open`, `pick-images` take paths in drive mode (main already has `--save-to`, `--open`, `--insert-from`); the dialogs themselves stay for humans.
4. **`scripts/drive.mjs <script.jsonl> [--gui]`**: runs it headless (offscreen window) or visible; prints the report; the reviewer's acceptance runs become `node scripts/drive.mjs tests/drive/p3-u2.jsonl`.

Not in scope: pixel checks (stay in `verify-*.py`), a general automation API for third parties, anything that runs PDF JavaScript. Ownership if approved: main/preload/scripts = the seat finishing grok's role; renderer `STATE` + command table = ds2; one unit, ~300 lines, before or after U1b at the human's choice.

## P6 U4 drive additions
`arm {tool:'link'}` presses "Draw link" (the hit layer goes dead, so `direct.links` reads 0); `arm {tool:'off'}` disarms and closes a draw dialog, clearing its draft.
A `drag` on empty space (no `.hit-target`/`.hit-handle` under the point, or a tool armed) goes to the page itself: armed link draws a rect into `nav.linkDraft {page, rect}` and opens the link dialog; in Redact mode an unarmed drag of at least 3 CSS px marks an area, a smaller drag or a click marks nothing.
`link {kind:'page'|'uri', page|uri}` saves the drawn draft when one exists, else anchors on the current find hit as before; `link {action:'set', index, rect?, page?|uri?}` retargets or moves the Links row `index` (page 1-based, sent by the row's `annotId`).
`outlines {on: true|false}` mirrors the Edit-mode "Outline objects" checkbox (default on) and repaints.
`click`/`handle`/`drag`/`key`/`type` reach `.link-target`s with no new keys: in Read a click follows the link; in Annotate a click focuses, the grip/body moves, handles resize, plain arrows nudge 1 pt (Shift 10), Delete deletes, Enter opens the inline target editor and `type` replaces its selected value.
Plain arrows also nudge a focused object, redaction mark, or (Forms mode) checkbox/radio widget; on a radio plain ←/→ still move the selection.
STATE `links` is the shown page's `[{id, annotId, rect, kind, page?, uri?}]` in `getLinks()` order (`nav.links` keeps its old shape); `direct.links` counts painted link targets and `direct.outlines` reports the toggle.
`direct.active` for a focused or edited link is `{kind:'link', annotId, id, page, box, rect, target, editing, draft?}`; `nav.linkDraft` is the open draw draft or null.
`nav.last` gains `{action:'link-follow', kind, page?|uri?}`, `{action:'link-set', index, detail?}` (detail is the engine refusal token) and `{action:'link-draw', page, rect}`.
`fields.tabs` is the page's `/Tabs` name or null, `fields.tabsOrder` the order used (`R`, `C`, `S`, `A`, `W` or `fallback`) and `fields.order` the fillable names in Tab order; Tab and Shift+Tab follow it.
Scripts: tests/drive/direct-edit4.jsonl (links + tabs) and direct-edit5.jsonl (outlines, nudge, redact drag); gesture geometry is checked in tests/p6-drive4.test.mjs via `pick()`, never in an expect.

## P5 U3 drive additions
`{"cmd":"arm","contents":{"tool":"sigfield"}}` arms "Draw signature field" (Forms mode, a designable document); the next `drag` adds one empty signature field named by the free-name rule (the first `Signature<n>` no field uses). A drag under 3 px draws nothing; under 40x20 pt sets `error` "Draw a bigger signature field" and sends no request.
The designer command takes the kind too: `fields {action:'add', kind:'signature', name?, rect}` (name optional, the reply's name lands in `fields.last`); `props {rect|label|readOnly|required}` and `delete` work on an empty signature field, a rename is refused, and `fill` reports `fields.last {action:'fill', detail:'signature'}`.
`sign {cert, password, field, reason?, certify?}` with a top-level `to` signs an existing empty field of the shown page in place (its `rect`/`page` keys are ignored); `sign.last` gains `field`, refusals are `no-such-field`, `already-signed`, `invalid`, `certified`. A refused sign leaves the dialog open: send `key Escape` before the next `click`.
`sign.dialog` is `{field, page}` while the sign dialog is open in field mode (a `click` on an empty `.sig-target` opens it), else null.
`signatures` lists the shown page's signature fields in `fields` order as `{field, rect, status}`; status is `empty`, `signed` (no Verify yet this session), or the last Verify row's `valid`/`invalid`/`unsupported`. Trust is not a status; the badge caption alone shows "✓ Valid, untrusted". Use `{"cmd":"verify","contents":{}}` (the bare form only opens the dialog).
Every `sign` step's `contents` read `[redacted]` in the report and a STATE line holding the password fails the run; no fixture or output name may contain the password. Do not expect `mode` after a `sign` step (sign switches to annotate).
Script: tests/drive/sign-field.jsonl; the drawn rect and pyHanko checks live in tests/p5-drive-field.test.mjs.
A `click` on a signed `.sig-target` opens the Verify dialog (it runs Verify and marks that field's row); only an empty field opens the sign dialog.

## P6 U5 drive additions
`click {page,x,y,shift:true}` toggles an image/Form in the object selection (Edit text mode); `direct.selection` lists `{targetId, kind, name}` in click order and `direct.active` stays the anchor (last clicked). With 2+ members, `drag`, `key Alt+Arrow*` and `key Delete` act on all of them as one `edit-objects` op; `content.edited` is then `{kind:'objects', action, name:'Im1,Im2', count}` (single edits never carry `count`). `key Enter` does nothing on a group.
`drag {…, alt:true}` duplicates the selection at the drop point; the copies become the selection, the originals stay.
`{"cmd":"menu","contents":{"page":0,"x":430,"y":72,"item":"duplicate"}}` right-clicks the object under the point (`item` optional: replace, duplicate, delete); `direct.menu` is `{name, kind, count, items:{replace,duplicate,delete}}` or null. `key Shift+F10` on a focused object opens it too.
A group move is clamped to the page, so no out-of-bounds refusal is reachable from the page.
Traps: `menu` needs `contents` (packDrive folds only click/type/key/drag/handle); keys go to an open menu first (Escape closes it; ArrowUp/ArrowDown/Home/End move between enabled items, Enter or Space runs the focused one; focus starts on the first enabled item); a disabled `item` sets `error` "menu: <item> is not available" and leaves the menu open; after `undo` the selection re-resolves to the originals, so send `key Escape` before a fresh Shift-click.
Script: tests/drive/direct-edit6.jsonl; boxes are checked in tests/p6-drive6.test.mjs with a filter-by-name `all()`, never `find` (a duplicate shares its name).

## P6 U6 drive additions
`menu {page,x,y,item}` gains five items: rotate-cw, rotate-ccw, flip-h, flip-v (single or group, one op) and crop (single only; it toggles crop mode and writes nothing). `direct.menu.items` gains `rotateCw, rotateCcw, flipH, flipV, crop`; rotate is off when the rotated box would not fit the page.
In crop mode `direct.crop` is `{name, full}` (view space; `full` is the uncropped box, or the visible box when nothing is cropped yet) and `handle {page,x,y,handle}` on that object crops (a side or corner) or moves the crop window (`grip`); each commit is one op with `content.edited.action 'crop'`, and crop mode stays on after it.
With 2+ members `handle {page,x,y,handle}` grabs the group box: give the point of the union's handle (e.g. its east edge at mid-height); the members resize as a block (`content.edited {kind:'objects', action:'resize'}`); `key Alt+Meta+ArrowRight/ArrowLeft` widens or narrows the union by 1 pt.
`drag {…, meta:true}` holds ⌘ on press, every move and release, so the drag does not snap; without it a drag of an image or form snaps edges and centres to other images, forms and the page within 4 pt.
`content.objects[]` gains `orient {swap, sx, sy}` and, when cropped, `full` (view space); `content.edited.action` may be 'transform', 'crop' or 'resize'.
Traps: a crop handle that cannot move is a silent no-op (no revision, no error); `key Escape` (or Enter) leaves crop mode before it clears the selection; a `handle` grip on a group is a silent no-op (move a group with `drag`); guides never appear in a drive step's STATE (`direct.gesture.guides` is gone at `end`, read it over CDP during a drag); a form that surrounds other objects is clicked on its 6 px border band, and a click inside it reaches what lies beneath (empty space opens add text).
Script: tests/drive/direct-edit7.jsonl on fixtures/p6/objects6.pdf; boxes and orients are checked in tests/p6-drive7.test.mjs (pick by view: after a group rotate the members tie on x0).

## P6 U7 drive additions
`menu {page,x,y,item}` gains cut, copy and paste (11 items; `direct.menu.items` gains `cut, copy, paste`). Copy/Cut work on any selection in Edit text, Fill forms, Annotate and Redact: images, forms, text runs, fields, links, redaction marks. `menu {page,x,y}` on empty space opens the page menu `{name:'', kind:'page', count:0, items}` with only Paste on; its Paste puts the pasted items' top-left at the point. `key Meta+c|Meta+x|Meta+v` dispatch the DOM clipboard event (the Edit-menu roles' path).

## Bates drive additions
Keys: `header-footer` / `watermark` contents gain `align` ("left"|"center"|"right"; header/footer only, anything else refuses "Align must be left, center or right"), `batesStart`, `batesPad` (numbers or numeric strings, written verbatim into the dialog fields; absent → the window's counter `batesNext` and last pad). `{bates}` in the text expands per stamped page, in stamped-page order, to `String(start + i).padStart(pad, "0")` (pad 1–15, default 6, start + n − 1 ≤ 10^15 − 1); the engine refuses `stamp: bates-start-required:` / `invalid-bates:` / `invalid-align:` (reason `invalid`). STATE `decorate.bates {next, pad, last: {from, to, pages} | null}` appears whenever `decorate` does; `decorate.last.bates {from, to}` only on a stamp that produced numbers.
Traps: the counter survives `open`/`close` (STATE has no `decorate` key right after an open, so the next stamp's `from` is the proof); undo does NOT move it back — pass `batesStart` to renumber; a bad start/pad is the dialog's refusal "Bates start must be a whole number and digits 1–15" (exact `error`), an empty start is a refusal, never 0.
Script: tests/drive/bates.jsonl (nav 3 pages → save-to, hello → save-to, undo, refused start "x", header continues at 104), run by tests/p6-bates.test.mjs, which also reads the saved files. Pad carry-over: tests/drive/bates-pad.jsonl (nav, footer start 1 with `batesPad` "4" as a string → pad 4; a header with no start/pad continues 4–6 at pad 4; `align` "centre" refuses "Align must be left, center or right", revision unchanged; save-to), run by the second test in tests/p6-bates.test.mjs.

## Stamp look additions
Keys: `header-footer` / `watermark` contents also take `size` (a whole number of points 4–200, number or numeric string, written into the field; else the dialog's "Size must be a whole number from 4 to 200"), `color` (a "#rrggbb" string, either case; anything else refuses "Colour must look like #336699"), `opacity` (a JSON number 0.01–1, written into the Opacity select as a whole percent; 0, 1.5 or the string "0.3" refuse "Opacity must be a number from 0.01 to 1") and `behind` (a boolean, watermark only; anything else refuses "Behind must be true or false"). Every refusal is before any write: `decorate.last.ok` false, revision unchanged. In the window the same fields refuse "Colour must look like #336699" and "Opacity must be a whole percentage from 1 to 100". Absent, each is the dialog's starting look: a watermark 48 pt grey (#808080) at 30%, behind the page's content; a header or footer 10 pt black, solid, on top.
Engine: `stamp` (and `batch-file`'s `action`) take `size`, `color`, `opacity` (0.01–1; an ExtGState `/PDF4AllG<percent>` with `/ca` and `/CA`, shared by every page) and `behind` (one `q … Q` stream put first in /Contents, so the page draws over it; no `q` head or tail around the page's own streams); refusals `stamp: invalid-size:` / `invalid-color:` / `invalid-opacity:` / `invalid-behind:` (reason `invalid`). Absent, the engine writes the engine.ts bytes (on top, opaque), so only the app's defaults changed. Batch: a watermark goes behind at 30% as the dialog's does; `align` takes "center" there too.
Trap: a page that paints itself first (a scan, an opaque background box) covers a watermark behind it; pass `"behind": false` (still see-through at 30%) for such files. The dialog starts "Behind" unchecked, with a note (`#stamp-behind-note`), when a picture covers 90% or more of the page shown (from `edit-targets`); a filled background shape is not detected.

## Batch drive additions
- `{"cmd":"batch","folder":"<abs dir>","contents":{"kind":"footer","text":"B-{bates}","align":"right","batesPad":4,"pages":"1-2","batesStart":1,"cancelAfter":2}}` runs one stamp action over every `*.pdf` in the folder and resolves after the whole queue (contract-batch.md §9.9). `kind` and `text` are required; `pages` is a range string per file (blank = all); `batesStart` defaults to the window's Bates counter, `batesPad` to the stamp dialog's digits; `cancelAfter: n` stops the queue after n files. A `batch` line without `contents` is refused ("batch: contents required"). No document needs to be open, and the open one is never touched.
- `folder` is a LINE-LEVEL pre-answer (like `to`/`from`/`images`): startDrive sets main's `batchDirArg` from it; `--batch-dir=<abs dir>` on the Electron argv does the same for a whole run. Under `--smoke`/`--drive` with neither, `pick-folder` answers `cancelled` and never shows a sheet. Menu: File ▸ Batch… (⌥⌘B) opens `#batch-dialog`; `#batch-pick` lists the folder.
- Listing order (the queue and Bates order): names sorted with `localeCompare(b, "en", { numeric: true, sensitivity: "base" })`, ≤ 200 files, non-recursive. Outputs go to `<folder>/pdf4all-out/<name>` (never overwritten: an existing output fails the row `exists` before any engine work; a symlinked `pdf4all-out` fails `unwritable`), plus `report.txt` (tab-separated `name status pages detail bates`, one line per processed file).
- STATE `batch` (present once the dialog or a drive step touched it): `{ folder, out, action, total, done, ok, failed, running, cancelled, report: "ok"|<reason>|null, bates: {start, next, pad}, files: [{ name, status: queued|running|ok|failed, pages, detail, bates?: {from, to} }] }`. The Bates counter advances only after a file's output is written; `decorate.bates.next` follows it. Final text in `announcement` and `#batch-summary`: "Batch done: 3 ok, 1 failed, report in pdf4all-out" (or "Batch cancelled: …", or "; report not written: report.txt exists"). Row details: `encrypted`, `read-only`, `not-pdf`, `too-large`, `bad-pages`, `stamp-error: <token>`, `exists`, `unwritable`.

## Compare drive notes
- Open: `{"cmd":"compare","from":"fixtures/nav.pdf"}` with NO `contents` = the menu path (File ▸ Compare with… ⌥⌘K → `pickInsertSource("compare")`); `from` is the sticky LINE-LEVEL pre-answer of `insert-source` (like `insert`), so a later compare/insert line without `from` reuses it. Needs an open, unlocked main doc ("Open a document first, then choose Compare with…"). Other steps carry `contents`: `{close:true}` (works with no main doc), `{pageB:n}` (0-based, clamped to 0..pageCount−1, holds until A's page changes), `{page:n}` (= `goto` A; B follows to `min(n, pageCount−1)`), `{showDiff:bool}` (the `#compare-show-diff` checkbox).
- STATE `compare {open, name, pageCount, pageA, pageB, text: {same, removed, added, removedLines, addedLines, refused?} | null, pixels: {differing, total, ratio (4 dp), scale} | null, showDiff, last: {action: open|close, ok, detail?} | null}`; `announcement` = `#compare-summary` ("Page 1 vs 1: 0 lines same, 1 removed, 1 added; 0.3 % of pixels differ") after a compare step (an edit keeps its own announcement).
- Traps: compare never journals, dirties or moves `revision`; `open`/`close` of the main doc keep the slot (unless the two files together exceed 120 MiB: the slot closes, `last {action:"close", ok:true, detail:"too-large"}`); a refused compare-open (`encrypted`, `too-large`, `invalid`) keeps the previous slot and sets `last.ok false`; a main doc without the copy permission gives `text.refused "read-only"` and pixels only; `pixels` are at S = min(1, floor(4096/maxEdge·100)/100) — 72 dpi for letter pages (total 484704); `#reader` is hidden while compare is open.
Script: tests/drive/compare.jsonl (hello + labels, compare nav, pageB 2/9, showDiff, refused encrypted.pdf, undo, open nav, page 1, pageB 2, close), run by tests/p6-compare.test.mjs. GUI proof: .quad/shared/p6/checks/shot-compare.mjs (real ⌥⌘K, `--insert-from=<abs nav.pdf>`).

## Coded simple fonts

## Agent session
- `--drive=-` reads drive lines from stdin instead of a file (blank and `#` lines skipped, `${OUT}` per line) and writes one `STEP <json>` line to stdout per line read: the step record (`{cmd, …, state, expect?, ok?}`, secrets `[redacted]`). A line that is not a JSON object answers `STEP {"error":"bad line: …"}` and the session goes on (a file script still fails fast). No idle timeout; the 60 s step timeout stays (its STEP carries `error`, then the app exits).
- `{"cmd":"close"}` (or stdin EOF, or the end of a file script) finishes as before: `--report=` gets the whole report, exit 0 iff every expect matched. `close` is never a step, so a file script may end with it harmlessly.
- `{"cmd":"new","contents":{"size":"letter"|"a4"|[w,h]}}` (contents optional, letter default; each side 72–14400 pt) writes a blank one-page PDF as `Untitled.pdf` in a fresh temp folder and opens it (`doc.name "Untitled.pdf"`, revision 0); a bad size is the `unreadable` open-error ("Could not read Untitled.pdf."). File → New… (⌘N) does the same. `text-add` and `fields add` work on it.
- `scripts/session.mjs` `createSession({out?, gui?, report?})` → `{step(line), close()}` (packDrive applied per line, one step in flight); `node scripts/drive.mjs --session` pipes stdin through it. `scripts/pdf4all-mcp.mjs` is the MCP server (tools `pdf4all_open`, `pdf4all_new`, `pdf4all_do`, `pdf4all_state`, `pdf4all_save`, `pdf4all_help`); agent reference `docs/agent.md`.
Script: tests/drive/agent-session.jsonl (new A4, text-add, field add + fill, save-to, reopen, find, close), run in both modes by tests/agent-session.test.mjs.
- Drive guard (contract-drive-guard.md): an unknown `cmd` sets `error` `Unknown command "<cmd>"` and changes nothing, and a `content` object with none of `text`/`find`/`action`/`password`, a `content` line with no `contents`, or any string contents (bad JSON or plain text) is refused (`error` "content: give text, find or action") instead of running the `--edit=content` self-test, which stays on the null-contents and `{password}` smoke path (a drive `content` line with no contents sends `{}` and is refused; a `{`-prefixed string that fails to parse is refused with `content: <parse error>`, amendment §4); `error` stays until the next step that clears it (a bare `state` step does not; `find` and a well-formed `content` object do). Script: tests/drive/drive-guard.jsonl.

## Bugfix 1
- `{"cmd":"save-in-place","path":"${OUT}/x.pdf"}`: `path` sets the Save target for this step only (a step without it clears any earlier `save-to` target). On a document made by `new` (Untitled), Save is Save As: with `path` it writes there, rebinds the window to the new file (`doc.name "x.pdf"`, `dirty false`; the next `save-in-place` is a plain in-place save of it), without `path` it is `save {ok:false, reason:"cancelled"}` and stays dirty. On a titled document `path` is ignored. GUI ⌘S on Untitled shows the save dialog (default `Untitled.pdf`). Nothing is ever written into the `pdf4all-new-*` temp folder by Save.
- A performed `undo`/`redo` clears `error` (a failing one shows its own; a no-op one, nothing to undo or an open on-page editor closing, keeps it). Script: tests/drive/bugfix1.jsonl, run by tests/bugfix1.test.mjs.

## print-edit

## shapes
- Engine: `annot-add` of a Square, Circle, Line or Ink takes an optional stroke `color` [r, g, b] (each 0–1) and `width` (points, above 0 and at most 24); without them the old strokes stay (red 1 pt; Ink blue 1.5 pt), so existing scripts are unchanged. Any other type, or an Ink `signature:true`, with either is refused ("annot-add: color and width apply to Square, Circle, Line, Ink only").
- A Square's or Circle's box (what `annots` lists and what `annot-move`/`annot-set` keep) is /Rect less /RD, or, with no /RD, /Rect less half its border, with or without an appearance (an /RD too large for /Rect leaves the whole /Rect).
- `annot-set {page, annotId, color?, width?}` restyles one of those four (contents may then be left out): /C, /BS /W (a /Border dash moves to /BS /D; a Square or Circle keeps its box, /Rect and /RD follow the width) and a new appearance, one step "change rectangle colour" / "… line width" / "… style" (rectangle, ellipse, line, drawing).
- `annot-move {page, annotId, point, size?}` moves and resizes them too: the box goes to `point` (top left) and `size`, clamped inside the page; a Line's /L and an Ink's /InkList are scaled with the box (a level or upright line keeps no extent across). A move shifts /Rect and keeps the appearance, except that a shape without one (/AP) gets one drawn; a resize draws it again. `annot-move {page, annotId, points: [[x0, y0], [x1, y1]]}` puts a Line's two ends anywhere on the page (apart): they may cross, the line may turn level. Steps "move rectangle", "resize line", … Other kinds are refused ("annot-move: only FreeText, Square, Circle, Line, Ink annotations and signatures can be moved"; "annot-move: points apply to lines only").
- `annots` items of those four carry `color` (RGB 0–1, when /C is set) and `width`; a Line's carry `line` [x0, y0, x1, y1] (page points, /L's first point first), an Ink's `strokes` (page points), a Square or Circle with /IC `filled: true`.
- The drive's `square`/`circle`/`line`/`ink` ops still add one at once (the search hit, else the page centre). In the window, Insert ▸ Square/Circle/Line/Ink arms the Draw tool with that shape instead (nothing without a document): drag on the page to draw it. The Draw tool's bar has a colour (eight swatches and Custom…, whose picker sends only the colour it rests on) and a width, remembered in `ui-prefs.json` (`draw-color`, `draw-width`). With Select a shape is picked by its stroke (within half its width, at least 4 px) or, filled or already picked, anywhere inside, so text inside a drawn box can still be selected; it shows handles (a line, one on each end, each moving that end alone), moves and resizes by dragging, and the bar's colour and width change it.

## insert-blank
- `{"cmd":"insert-blank","contents":{"after":1,"count":1,"size":"same","rotate":0}}` inserts blank pages after page `after` (0-based; -1 puts them first), one journal step "insert blank page" (one Undo). Every key is optional: `after` defaults to the last page selected in the Pages grid while the Pages tool is on, else the current page; `count` is 1–100 (default 1); `size` is `"same"` (the default), `"letter"`, `"a4"` or `[w, h]` with each side 72–14400 pt; `rotate` is 0, 90, 180 or 270. Page → Insert Blank Page (⌥⇧⌘N on a Mac, no shortcut on Windows and Linux) and the Pages grid's "Blank page" button do the same with no contents.
- "same" copies the page before the new ones (the page after them when they go first; Letter in a document with no pages): its /MediaBox, /CropBox (as the page frame reads them, inherited), /UserUnit and its /Rotate (snapped to a quarter turn). Each new page has its own empty content stream and an empty /Resources and sets /MediaBox, /CropBox (the copied one, else equal to the MediaBox) and /Rotate itself, so nothing from its /Pages node (a node's /CropBox included) applies to it. A given `size` replaces the boxes only (no /UserUnit) and keeps the neighbour's turn: "letter" after a page turned 90 is a landscape page; give `rotate` too to change that.
- Afterwards `page` is the first new page, `pages.count` grows by `count` and the grid selects the new pages. Page label ranges after the insertion move down (a page inserted inside a range continues it); outlines, links and named destinations name pages by object and keep theirs. A destination written as a page number (`[2 /Fit]`, not valid in a local GoTo) is not rewritten, as with `insert`.
- Refusals (engine words, `reason` `invalid` unless noted): `insert-blank: after must be an integer in -1..<last>`, `insert-blank: count must be an integer in 1..100`, `insert-blank: size must be "same", "letter", "a4" or [width, height] with each side 72..14400 pt`, `insert-blank: rotate must be 0, 90, 180 or 270`; a signed or locked document is `read-only`, an encrypted one without the edit permission is refused like every page op.

## Pages grid: drag to reorder
- In the window the grid is dragged with the pointer (press on a page, move at least 6 px, let go): the drop point names a gap (left half of a card: before it; right half: after it; the empty cell at the end: last), and the selected pages go into that gap in their order, upwards or downwards; a drop inside or beside the dragged run takes no step, and so do a drop outside the grid and Esc during the drag. Scrolling with the wheel mid-drag recomputes the gap under the pointer. HTML drag and drop is not used: the window's native file drop (which opens a PDF dropped on it) takes every drag over the web view, so `dragover`/`drop` never reach the page.
- The core action is `UiAction::Pages {action:"move", pages, to}` with `to` the gap (0..=page count): `tandem-pdf --walk` drives it with `{"act": {"kind": "pages", "action": "move", "pages": [2], "to": 1}}` (page 3 becomes page 2). The UI's `drop_target` (crates/tandem-ui/src/pages.rs) turns a drop into that `to`.
