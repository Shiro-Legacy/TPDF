# Acceptance tests for specs 04-08 (reviewer side)

Status: written 2026-10-18 on branch `mit-tests-b`, before hand-off. The
tests follow the specs in `docs/clean-room/specs/` and the owner's decisions
in `docs/clean-room/OWNER-DECISIONS.md` (all accepted). They hold no
MuPDF-derived expression: no MuPDF streams, artwork, labels, constants or
descriptor values, and no MuPDF names in test names or comments.

A test that the current code fails because a decision changes behaviour is
marked `#[ignore = "clean-room: <spec>§<section> ..."]` (node: `skip` with
the same reason). Gates stay green. The implementer of each workstream
removes the `ignore` of its own tests; all of them must pass before the
workstream merges. Run them with
`tpdf-wt/tools/slot cargo test --release --test <file> -- --include-ignored`.

Columns: **class** is keep (unchanged), scrub (names or comments
reworded), modify (assertion changed by a decision), replace (a
MuPDF-equality assertion rewritten as a spec check), new, moved.

### Notes for the implementer and reviewer

- Quad tolerance (spec 8): `view.rs` compares quads along the baseline
  within 0.05 pt and across it within 0.35 em (`quad_near`).
- `layout_and_clipping` and `page_text_of_fixtures` accept either reading
  where a gap lies inside the 0.10-0.25 em band of 3.4. Spec 8.1 pins
  `2 Tc` at 12 pt (0.17 em) to `S p a c e d`; that conflicts with the band,
  so the test accepts both.
- `n11_pixel_sizes_at_the_rounding_edge`: the rows of 7.3 pin ε to
  [0.0009, 0.0011) pixel, narrower than the [1e-4, 2e-3] that 5.2 states.
  The render-size equality of the corpus gate needs the narrow window.
- `n13_an_embedded_program_describes_its_weight_and_pitch` expects
  `TextFont::name` to keep a subset prefix (`ABCDEF+Plain`), as 2.6 reads.
- Not written as tests: the corpus targets of 8.3 (reviewer-side, run with
  `engine/oracle/corpus-run.mjs`), the `text-all` cost and peak-RSS bounds of
  6.3, and N6's "add whole-line checks" to `app_scan_text.rs`.
- The 22 app node suites of 8.1 were not changed: they assert app
  behaviour, not MuPDF output.
