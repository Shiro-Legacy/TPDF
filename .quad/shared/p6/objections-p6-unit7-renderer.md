**R1 (blocking) §2.2, §0** — Selection handling is object-only in six places, so a selection with a non-object member never shows and is lost on the next repaint. (a) `restoreDirectFocus` re-resolves members only against `.object-target` of the same kind (renderer.ts:2867-2873). It nulls the anchor outside Edit text (:2858) and then empties the selection whenever there is no object anchor (:2887). A field selection in Fill forms, a link selection in Annotate or a mark selection in Redact is therefore cleared by the first repaint, and ruling K1 (undo keeps `directSelection` and re-resolves it) cannot work for runs, fields, links or marks. (b) `markSelection` uses `objectNode` (:2677), so the other kinds get no `.selected`/`.multi`. (c) `selectionTargets` returns null when any member is not an object node (:2718-2724), and `paintGroupBox` (:2683), `startGroupGesture` (:3090), `groupDelete` (:3114) and `objectMenuItems` (:2743) then do nothing. (d) STATE `direct.selection` is gated on `uiMode === "edit" && directFocusedObject` (:7426). — Amendment: "`directFocusedObject` stays object-only (null when the anchor is not an object); the anchor is `directSelection.at(-1)`. A new `selectionMembers()` returns every member with `{member, rect (view, y-down), node}`, and resolves each kind its own way: objects as today; text runs by nearest same-`text` candidate (ids change on every write, as `applyTextTransform` does at :2479-2491); fields by `[data-field-id]`; links and marks by `[data-annot-id]`. `restoreDirectFocus`, `markSelection`, `paintGroupBox` (union of all members, handles only when every member is an object) and STATE use it. STATE `direct.selection` = `doc && directSelection.length ? members : []` in every mode. `selectionTargets` stays the objects-only view used by the U5/U6 object paths."

**R2 (blocking) §2.2, §2.4, §4.1** — `direct.selection[].kind` holds `"image"`/`"form"` today, not `"object"`. `ObjectFocus.kind = item.kind` (focusObject :3026), and existing scripts pin it (direct-edit7.jsonl:14 `{"name":"Im1","kind":"image"}`, direct-edit6.jsonl, 1 line). §2.2's `kind: "object"` would redden the U5/U6 drives, and §4.1's expected `['text','object']` contradicts §0's rule of no shape change. — Amendment: "Member `kind` is `'image' | 'form' | 'text' | 'field' | 'link' | 'mark'` (objects keep their U5 kind). §4.1 expects kinds `['text','image']`."

**R3 (blocking) §2.2, §4.1** — "A plain click selects one" is false for two of the new kinds. A plain click on a candidate `.text-target` opens the inline editor (:2620). A plain click on a field fills it (:2561 → `activateField`): it opens an editor, and on a checkbox or radio it writes a new value (:3361). `activateField` also calls `clearDirectFocus` (:3358). So §4.1's "click run, Shift-click Im1 → 2 members" gives `[Im1]`: `toggleObject` with no object anchor falls to `focusObject` (:3247). "Click field A, Shift-click B" gives B alone, after A's editor was opened. — Amendment: "A plain click keeps its U3/U4 action (text and fields open their editor; objects, links and marks select one). A Shift-click on any of the five target kinds when the selection is empty selects that target alone and opens no editor. A Shift-click while a text-run or field editor is open commits and closes that editor as a blur does, then seeds the selection with that run or field before it adds the clicked target. A Shift-click on a checkbox or radio never toggles it. §4.1 Shift-clicks the first member too."

**R4 (blocking) §2.2, §2.3, §4.1** — Paragraphs cannot use the `edit-text` path. Each paragraph is one `.text-target.paragraph` button (`paintedParagraphs` :2608), and it moves through `edit-paragraph` (`startTextGesture` → `applyParagraphEdit`, :2466). §1.3 has no paragraph item, so `edit-text {move}` on "the paragraph's first run" (§4.1; direct3's paragraph, direct-edit3.jsonl:4) moves one line and breaks the paragraph apart. — Amendment: "Text members are single-run candidates with `moveable` only (`.text-target:not(.paragraph):not(.unsupported)`). A Shift-click on a paragraph or an unsupported run adds nothing and announces 'Paragraphs cannot join a selection'. §4.1 uses 'Move me' (100.78, 386.57) on direct3.pdf." (Alternative for the engine lens: a `{op:'edit-paragraph', paragraphId, move}` batch item.)

**R9 (should) D2, §2.1** — The paste placement geometry is underspecified. ## checkedFine
- D5 dispatch: the menu-role path `webContents.copy()/cut()/paste()` fires `copy`/`cut`/`paste` on the focused **non-editable** object button (probe B). `paste` fires with an empty OS clipboard (probe A/B; formats `[]`, text sha e3b0c442…). `beforecopy` precedes `copy`; there is no `beforecut`/`beforepaste`.
- `preventDefault()` on `copy` with no `setData` leaves the OS clipboard text intact (probe P). A copy that is not prevented and has no selection leaves it intact too (P0). So D5's `preventDefault` is safe; the probe put the clipboard back after step P.
- A copy with the Inspector's X input focused targets that input (probe D), so the "input focused → let it through" branch is reachable.
- `expect` is a subset match with exact array lengths (main.ts:1658-1663). New `items` keys do not break direct-edit6.jsonl:44,49,57,68 or direct-edit7.jsonl:15,47,72. p6-drive7.test.mjs:178,182 read single keys, and no test deep-equals `menu.items` or pins `menu.kind`.
- tests/p3-drive.test.mjs:93-97 deep-equals only single edits from object-edit.jsonl. The `selection` kind and a single Cut's `{kind, action:'delete', name}` keep that shape.
- `#object-menu` (index.html:218) has 8 buttons. The click handler uses `closest('[role^="menuitem"]')` (renderer.ts:2819), and keyboard navigation walks the enabled buttons (:2824), so three more `menuitem`s work unchanged. `objectItemsFor` is at :2744.
- The drive `click {shift:true}` carries `shiftKey` on pointerdown, pointerup and click (renderer.ts:1287, 1298, 1299). A mode change clears the selection (`setMode` :4848 → `cancelPendingTools` :4823).
- `helpRows()` counts the tbody rows (:1587-1589). p2-shell.test.mjs:130 and p3-drive.test.mjs:162 pin 11, and §2.5 adds no row. `permitted('copy')` exists (:1730; `DocumentPermissions.copy` engine.ts:198).

## buildRisks
- Renderer seat: R1 is most of the work. Do not add a fourth parallel selection store: generalise `ObjectFocus` → `SelectionMember` and route everything through `selectionMembers()`. The U5/U6 object paths must keep `selectionTargets()` byte-for-byte, or direct-edit6/7 go red.
- Text-member ids change on every write (the engine's `p0.c0.<offset>` ids). Re-resolve by text and nearest rect, as `applyTextTransform` does. A field-props or link-set in the same batch must not trip the text resolution into picking a neighbouring run.
- Every refresh a batch needs: `refreshContentTargets(true)` (runs and objects), `refreshFields()`, links (`linksPage`) and notes. Run them after one reply, then call `restoreDirectFocus` once. `applyEdit` alone does not refresh fields.
- For the page menu, capture the `at` point at `contextmenu` time. A viewport scroll closes the menu (:2838), so the drive `menu` must not scroll between opening it and picking the item.
- Keep `swallowNextClick`/`addBlocked` behaviour for group drags that start on a text or field body. Otherwise the trailing click opens an editor (the U5 R3 class of bug).
