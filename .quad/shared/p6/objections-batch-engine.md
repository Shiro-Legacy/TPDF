# Batch objections — engine lens (Opus 5.5, 2026-09-24)
Scope: contract-batch.md D1, D2, §1 (+ §0, §5 where the engine is named). Read-only on src/tests/fixtures. Probes (pure node, build/ of 22:46, no lock, no Electron) in `.quad/scratch/batch/objections/engine/`: `probe.mjs` → `probe.out` (mupdf open/needsPassword/hasPermission/countPages of every candidate fixture; PNG and 100-byte junk through `openDocument(bytes,"application/pdf")`; a stampPage-shaped write on a transient doc with and without `enableJournal`; the open doc's journal before/after), `probe2.mjs` → `probe2.out` (detect() on signed/certified fixtures, limits), `probe3.mjs` → `probe3.out` (open/destroy counting through a `createEngine({...mupdf, Document: Proxy})` shim, run on insert-pages). `shasum -a 256 -c .quad/shared/p6/checks/fixtures.sha256`: 9 OK.

**E-1 (blocking) D2 "`openDocument(bytes)`"** — the engine's `openDocument` (engine.ts:993-1011) calls `enableJournal()` (:1005); any write on such a doc outside an operation throws. probe.out: the stampPage-shaped write with the journal on → `Can't add a journal fragment absent an operation`; without it → saved 2320 B, reopened `/Contents` array. `stampPage` (:3106-3187) writes with no `beginOperation`, so as written every file fails `stamp-error`. insert-pages uses `mupdf.Document.openDocument(bytes, "application/pdf")` directly (:5131) then `sourcePdf.disableJS()` (:5138), no journal.
amendment: "9.x `batch-file` opens with `mupdf.Document.openDocument(bytes, "application/pdf")` exactly as insert-pages does (engine.ts:5129-5138), then `asPDF()` and `disableJS()`; it never calls the engine's `openDocument` helper and never `enableJournal()`s the transient doc (probe.out: journal on ⇒ the stamp write throws)."

**E-2 (blocking) D2, §1.3(b) `no-edit-permission`** — unreachable as ordered. Every encrypted fixture needs the user password (probe.out: encrypted, -noedit, -noprint, -aes256, p3/encrypted-edit-noannot all `needsPassword true`; make-encrypted.py:56 `user_password="pdf4all-user"`), so the `needsPassword`/`encrypted` refusal fires first and `encrypted-noedit.pdf` returns `encrypted`, never `no-edit-permission`; and an unencrypted doc always passes (`allowed()` engine-core.ts:261 `if (!info.encrypted) return true`). Test (b) fails as written, or the token is dead code. mupdf does report `/P` while locked: -noedit `edit=false,annotate=false`.
amendment: "9.x Refusal order on the transient doc: not a PDF → `not-pdf`; `detect(source)` (engine.ts:1042); `!info.permissions.edit` → `no-edit-permission` (readable while locked, probe.out: encrypted-noedit edit=false); `info.needsPassword || info.encrypted` → `encrypted`; `info.signatures > 0 || info.certified` → `read-only` (E-3); `countPages() < 1` → `not-pdf`. Test (b): `encrypted-noedit.pdf` → `no-edit-permission`, `encrypted.pdf` and `encrypted-aes256.pdf` → `encrypted`."

**E-3 (blocking) D2 signed/certified** — D2 lists no signed/certified refusal. The app refuses every write of a signed or certified doc, copies included: `serializeDocument` → `read-only` (engine.ts:1281-1284), `requireMutable` (:1594). A full rewrite (`incremental=no,garbage=yes`) of a stamped signed file breaks its signature; batch would be the only path that writes one. probe2.out: `p5/signed-ec.pdf` signatures 1, `p5/certified-p1.pdf` certified true (both unencrypted, so nothing else stops them).
amendment: "9.x `batch-file` refuses a transient doc with `detect().signatures > 0 || certified` as `read-only` (the serializeDocument rule, engine.ts:1282-1284) before any write; test (b) adds `fixtures/p5/signed-ec.pdf` → `read-only` and `fixtures/p5/certified-p1.pdf` → `read-only`; the D2 reason list gains `read-only`."

**E-4 (blocking) D2 not-pdf** — "what does mupdf throw for PNG": nothing. `openDocument(pngBytes,"application/pdf")` sniffs the content and opens an IMAGE document (probe.out: img-rgb.png `asPDF false`, count 1); 100 junk bytes throw `no objects found` after a repair attempt. A builder mapping only the throw to `not-pdf` would stamp nothing and crash on `asPDF()!`, or leak the image doc. insert-pages covers both (:5130-5133 catch, :5137 `asPDF()` null) and closes in `finally` (:5165-5166; probe3.out PNG: opened 4, destroyed 3 = the session doc only still alive).
amendment: "9.x `not-pdf` = `byteLength < 5`, or `openDocument` throws, or `asPDF()` is null (a PNG opens as an image document, probe.out), or `countPages() < 1`; the `finally { closeDocument(source) }` wraps everything after a successful open, including the `asPDF()` null path."

**E-5 (should) §1.2 save options** — "the same options the open document's save uses" is `saveOptions(session)` (engine.ts:1255-1263), which appends the OPEN doc's pending `security-set` (`encrypt=aes-256,user-password=…`, :1257-1259). A builder copying it would encrypt every batch output with the human's pending password. The doc-free writers use the constant: extract-pages `outPdf.saveToBuffer(SAVE_OPTIONS)` (:5185), pdf-from-images (:3020); `SAVE_OPTIONS = "incremental=no,garbage=yes"` (:163). They also refuse `view.byteLength > MAX_SAVE_BYTES` before copying (:5188-5190), and main refuses the write above 50 MiB anyway (limits MAX_SAVE_BYTES 52428800, probe2.out).
amendment: "9.x `batch-file` saves with `pdf.saveToBuffer(SAVE_OPTIONS)` (the extract-pages block, engine.ts:5185-5196: size check against `MAX_SAVE_BYTES` → `too-large`, `copyBytes`, `buffer.destroy()` in finally), never `saveOptions(session)`; the reply returns `transfer: [bytes]`."

**E-6 (should) §1.2/§1.3(c) reason plumbing** — `failReason` takes `SaveReason` (engine-core.ts:159; union engine.ts:189-193), which has no `not-pdf`, `no-edit-permission`, `bad-pages`, `stamp-error`; under `noEmitOnError` a builder must guess between widening the union and a new helper. Stamp refusals after Bates are `failReason("invalid", "stamp: <token>: <detail>")` (contract-bates.md §9.2), kind/text ones plain `throw new Error("stamp: …")` (engine.ts:3047, :3195), and `checkPages` throws `reason:"invalid"` (:2843, :2847); "detail" in (c) is undefined.
amendment: "9.x `batchFile` never throws for a per-file refusal: it returns `{ reply: { id, ok:false, reason, detail, error } }` directly, `reason` ∈ {`too-large`,`not-pdf`,`no-edit-permission`,`encrypted`,`read-only`,`bad-pages`,`stamp-error`}; `stamp-error.detail` is the token matched by `/^stamp: ([a-z-]+):/` on the caught message (`bates-start-required`, `invalid-bates`, `invalid-align`), else `text` for the checkStampText/kind messages; `error` is the message. `SaveReason` is not widened. A `checkPages` failure on the transient count → `bad-pages`."

**E-7 (should) §1.2 Bates loop duplicated** — D1 needs the per-page `{bates}` value and `{from,to}`, which Bates puts inside `stampPages`'s loop (contract-bates.md §1.2); `stampPage(pdf, pageIndex, kind, template)` (:3106) takes the pdf, not the session, so it runs on a transient doc unchanged (no session/generationCounter/editScanCache read; `{label}` via `page.getLabel()` :3073 works on a transient doc, probe.out nav labels 1|2|3). Only the loop and the validation are session-bound.
amendment: "9.x Factor `stampLoop(pdf, pages, kind, text, { batesStart, batesPad, align }) → { from, to } | undefined` out of `stampPages` (called inside its `mutate`) and call it from `batchFile`, so the Bates expansion has one copy; `pages` is deduped and sorted as stampPages does (:3203-3204); `checkStampAction` covers kind, text, align, batesStart/batesPad and `bates-start-required`, and runs BEFORE the transient open."

**E-8 (should) §1.2/D2 no document open** — insert-pages begins `requireMutable(session, "insert-pages")` (:5116), which refuses `no-document` with no doc (:1591; probe.out: stamp with no doc → `reason:"no-document"`). A builder mirroring "the insert-pages path" breaks D5 ("no document needs to be open"). `dispatch` itself has no doc precondition (:4138-4140), and its catch spreads `journalState(session)`, which is null-safe (:1389-1396). `OP_PERMISSION` is only read inside `requireMutable` (:1595), so a `"batch-file": "any"` row is never consulted; the doc-free precedents (`extract-pages`, `pdf-from-images`) are in p2-shell's `READ_ONLY` (tests/p2-shell.test.mjs:167-172), not the table.
amendment: "9.x `batch-file` never calls `requireMutable` or reads `session.doc`; it is listed in `READ_ONLY` in tests/p2-shell.test.mjs (as `pdf-from-images`) and gets no `OP_PERMISSION` row (§1 and D2's `OP_PERMISSION` sentence are withdrawn). Test (a) also runs one `batch-file` on a fresh session with no `open` → ok."

**E-9 (should) §1.3(a)/(d) invariants weaker than claimed** — there is no "journal length" op; the observables are `engine.journalState(session)` (exported, engine.ts:6010; `serializeDocument` :6007 returns `{ bytes, saveMs }` :1305) and `session.doc.asPDF().getJournal()` (`position`, `steps`, :1385). No handle count exists; mupdf is injected via `createEngine(mupdf)`, so a Proxy shim counts opens/destroys (probe3.mjs works on insert-pages).
amendment: "9.x (a) after the batch call, the test asserts `session.doc` is the same object as before, `engine.journalState(session)` deep-equals `{revision:0,dirty:false,canUndo:false,canRedo:false}`, `session.doc.asPDF().getJournal().position === 0`, and `engine.serializeDocument(session).bytes` equals the pre-call serialization byte-for-byte. (d) builds the engine as `createEngine({ ...mupdf, Document: <Proxy wrapping openDocument that counts opens and wraps destroy> })` (probe3.mjs) and asserts opens − destroys === 1 (the session doc) after ok, `encrypted`, `not-pdf` (PNG) and `stamp-error` calls."

**E-10 (nit) D2 reply `pages`** — "pages 3" could be the page count or the count stamped. amendment: "9.x reply `pages` = the number of pages stamped (= `pages.length` after dedupe), `pageCount` = the transient doc's page count."

**E-11 (nit) §1.1** — insert-pages nulls nothing but `open` drops the JS copy (`request.pdf = null`, :4146). amendment: "9.x `batchFile` sets `request.bytes = null` after reading it, as `open` does (engine.ts:4145-4146); `bytes.byteLength > MAX_PDF_BYTES` → `too-large` before `openDocument`."
