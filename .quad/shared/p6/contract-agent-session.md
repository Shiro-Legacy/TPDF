# Agent session — live drive over stdin, a zero-dependency MCP server, File → New, and an agent reference

Drafted 2026-09-25 by fable51 (lean mode, one Opus 5.5 implementer, human-ordered in chat: "true agentic support where people can tell their ai to create a pdf, modify a pdf, fill a pdf and the agent can do it easily … go, write the contract and build with opus 5.5"). Line numbers are from `src/main.ts` / `scripts/drive.mjs` as of 2026-09-25 10:00; re-grep before editing.

**Problem:** the app already answers ~130 `edit-request` ops over `--drive=<script.jsonl>` (`src/main.ts:1770 startDrive`), but (1) the whole script is read at launch and the app quits after the last line, so an agent that must look before it acts relaunches the app for every decision; (2) no AI host can reach the app without our internal design doc and a hand-written JSONL; (3) there is no blank document — the only "new" is `new-from-images` — so an agent cannot create a PDF from nothing. Everything else (text-add, fields add/props/fill, pages, redact, sign, save-to) exists and is proven by 28 drive scripts.

**Decisions (fable51, lite mode; each built as written):**

- **D1 (session in main)** — `--drive=-` reads drive lines from `process.stdin` (`node:readline`, one JSON object per line, blank and `#` lines skipped) instead of a file. Refactor `startDrive` so the per-line body (the loop at :1800-1838: secrets, pre-answers, send, await STATE, expect, push) is unchanged and only the line source differs (`AsyncIterable<DriveLine>`: array for a file, readline for stdin). In stdin mode, after every `steps.push(step)`, main writes exactly one line `STEP <json of step>\n` to `process.stdout` (secrets already read `[redacted]` there). A new cmd `close` (no contents; also stdin EOF) ends the session: `finish({out, steps, memory}, !failed)` as today, so `--report=` still gets the whole report and the exit code still means "every expect matched". No idle timeout between lines (an agent may think for minutes); the 60 s **step** timeout stays. A JSON parse error on a stdin line is reported as `STEP {"error":"bad line: …"}` and the session continues (a file script keeps today's fail-fast). `${OUT}` substitution applies per line as today.
- **D2 (session client)** — new `scripts/session.mjs` exporting `createSession({out?, gui?, report?})` → `{ step(line: object | string): Promise<step>, close(): Promise<report> }`: spawns Electron exactly as `scripts/drive.mjs:44` does (same flags, `--drive=-`, fresh `mkdtemp` userData, `stdio ['pipe','pipe','inherit']`), applies `packDrive` to each line (move `packDrive` into `session.mjs` and import it from `drive.mjs`; behaviour byte-identical), writes it to the child's stdin, resolves the next `STEP ` line from the child's stdout (FIFO: one in flight at a time; a second `step()` before the first resolves queues). Non-`STEP` stdout lines are ignored. `close()` writes `{"cmd":"close"}`, waits for exit, returns the parsed `--report` file. `scripts/drive.mjs` gains `--session` (no script argument): it pipes its own stdin lines through `createSession().step()` and prints each result as one JSON line; on stdin EOF it prints the report and exits with the report's code. A script path still works exactly as before.
- **D3 (MCP server)** — new `scripts/pdf4all-mcp.mjs`: MCP over stdio, newline-delimited JSON-RPC 2.0, **no dependency** (hand-rolled; ~150 lines). Methods: `initialize` (reply `protocolVersion` = the client's if it is a string, else `"2025-06-18"`; `capabilities: {tools: {}}`; `serverInfo {name:"pdf4all", version}` from package.json), `notifications/initialized` (ignored), `ping` (`{}`), `tools/list`, `tools/call`; unknown method → error `-32601`; unparsable line → error `-32700` with `id: null`; the server never exits on a bad line, only on stdin EOF (then it closes the session). Tools (names, input JSON Schemas, one-paragraph descriptions that say what STATE slice to read back):
  - `pdf4all_open {path}` → step `{cmd:"open", path}`.
  - `pdf4all_new {size?: "letter"|"a4"|[w,h]}` → step `{cmd:"new", contents:{size}}` (D4).
  - `pdf4all_do {cmd, contents?, path?, to?, from?, range?, ms?}` → the step as given (generic; the description points at `pdf4all_help`).
  - `pdf4all_state {}` → `{cmd:"state"}`.
  - `pdf4all_save {path}` → `{cmd:"save-to", path}`.
  - `pdf4all_help {topic?: "create"|"modify"|"fill"|"ops"}` → the matching section of `docs/agent.md` (D6) as text, whole file when no topic.
  Every tool result is `{content:[{type:"text", text: JSON.stringify(step, null, 1)}], isError: boolean}` where `isError` is true when the step carries `error` or `state.error` is a non-empty string. The session starts lazily on the first tool call that needs it (`createSession({out})`, `out` = `--out=<dir>` argv or a `mkdtemp`); `pdf4all_save` with a relative path resolves against `out`. A `pdf4all_do` whose `cmd` is `close` is refused with `isError` (the session belongs to the server). Register line for humans (README): `claude mcp add pdf4all -- node /ABS/PATH/pdf4all/scripts/pdf4all-mcp.mjs` and the equivalent Claude Desktop `mcpServers` JSON snippet.
- **D4 (blank document, both halves)** — main-side `newBlank(contents, size)`: writes a hand-built minimal PDF (one `/Page`, `/MediaBox [0 0 w h]`, empty `/Resources`, correct xref offsets, `%PDF-1.7`) as `Untitled.pdf` inside a fresh `mkdtemp(join(app.getPath('temp'), 'pdf4all-new-'))` and then calls the existing `deliverOpen(contents, path)` — so STATE `name` is `Untitled.pdf`, `pages` 1, every existing op works on it, `save-to` copies it out, and nothing new is journaled. Sizes: `"letter"` = 612×792 (default), `"a4"` = 595.276×841.89, or `[w,h]` numbers each in 72…14400 (else `open-error`-style refusal: the drive step's STATE shows the existing open-error path — pick the existing reason token that fits, `unreadable` if none; NO new reason token). Drive cmd `{"cmd":"new","contents":{"size":…}}` (contents optional) and a File → **New…** menu item, accelerator `CmdOrCtrl+N` (unused today; `Alt+CmdOrCtrl+N` stays New from Images), placed above "New from Images…". In the GUI, a dirty document gets today's discard box via `deliverOpen`. The implementer verifies with the drive script that `text-add` and `fields add` work on the blank page (empty `/Resources`) — if text-add refuses, fix the engine's resource creation path minimally and say so in the build note.
- **D5 (drive script, runs in both modes)** — new `tests/drive/agent-session.jsonl` (never touch existing scripts): `new {size:"a4"}` → expect `name "Untitled.pdf"`, `pages 1` (and the page-size slice STATE already exposes — grep `pageSize`/`box` in STATE; if none exists, expect only name/pages); `mode edit` or whatever mode text-add needs; `text-add {page:0, point:[72,700], text:"Invoice 42", font:"Helvetica", size:14, color:[0,0,0]}` → `dirty true`; `fields {action:"add", kind:"text", name:"customer", rect:[72,600,300,624]}` → `fields.last.action "add"`; `fields {action:"fill", name:"customer", value:"Ada"}` → `fields.values.customer "Ada"`; `save-to ${OUT}/created.pdf`; `open ${OUT}/created.pdf` → `pages 1`, `fields.values.customer "Ada"`; `content` listing (`edit-targets` or the STATE slice) shows a target whose text is `Invoice 42`; `close`. In batch mode `close` must be a harmless last line (finish as today).
- **D6 (agent reference)** — new `docs/agent.md` (≤ 200 lines, plain, honest): how to start (MCP registration, or `node scripts/drive.mjs --session`), the six tools, then three recipes **Create / Modify / Fill** giving the exact step lines and the STATE keys to read back (`revision`, `dirty`, `error`, `content.edited/refused`, `fields.values/last`, `pages`), the refusal tokens an agent will meet (from Help/`design-agent-drive.md`), a section "Prefer semantic ops" (edit-text by target text, fields by name; `click/drag/handle` need page points and are for GUI parity), and the ceilings (single-run text edits, repertoire-gated CID/coded fonts, no OCR). `README.md` "## Driving the app" gains ≤ 5 lines (session, MCP, docs/agent.md). `.quad/shared/p3/design-agent-drive.md` gains "## Agent session" (≤ 12 lines: `--drive=-`, `STEP` lines, `close`, `new`, sizes, `scripts/session.mjs`, MCP tools). `src/renderer/index.html` Help table: one new row "New document" stating blank Letter/A4 or custom size, Untitled.pdf, save with Save a copy.
- **D7 (tests, red before fix)** — new `tests/agent-session.test.mjs` (copy `drive()`/helpers from `tests/p3-coded-drive.test.mjs`; never import them; every Electron test `skip: CI_NO_ELECTRON`): (a) **interleaving**: `createSession()`; `step({cmd:"open", path:"fixtures/form.pdf"})`; read `state.fields` from the result and pick the first text field's **name from that STATE**, then `step({cmd:"fields", contents:{action:"fill", name, value:"Ada"}})` → `fields.values[name] === "Ada"`; assert each result arrived before the next line was written (record timestamps); `close()` → report has exactly the steps sent, `ok true`. (b) **bad line**: a stdin line `{nope` → `STEP {error: /bad line/}`, session still answers `{cmd:"state"}`. (c) **batch unchanged**: `node scripts/drive.mjs tests/drive/agent-session.jsonl` → 0 red; reopen `${OUT}/created.pdf` with mupdf: 1 page, A4 MediaBox (±0.01), a widget named `customer` with value `Ada`, page text contains `Invoice 42`. (d) **MCP**: spawn `scripts/pdf4all-mcp.mjs` with stdio pipes; `initialize` → `serverInfo.name "pdf4all"`, echoed protocolVersion; `tools/list` → the six names; `tools/call pdf4all_new {size:"letter"}` → `isError false`, text parses, `state.name "Untitled.pdf"`; `tools/call pdf4all_do {cmd:"text-add", …}` → `isError false`; `tools/call pdf4all_save {path:"mcp.pdf"}` → file exists under `--out`; `tools/call pdf4all_do {cmd:"close"}` → `isError true`; `tools/call nosuch` → JSON-RPC error `-32602`; a garbage line → `-32700` with `id null` and the next `ping` still answers; close stdin → process exits 0 and no `--drive=` Electron remains (`pgrep -f -- '--drive=-'` empty). (e) **blank bytes**: export `blankPdf(w,h)` from a small pure module (`src/blank-pdf.ts`, no Electron imports, used by main) and test with mupdf: 1 page, MediaBox as asked, `xref` offsets valid (mupdf `PDFDocument` opens it without repair — check `doc.wasRepaired?.()` if the binding has it, else just open + countPages). Run the new file before any fix and save the red log to `.quad/shared/p6/acceptance/agent-session-red-before.log` (≥ 1 `not ok`).
- **D8 (GUI proof)** — `.quad/shared/p6/checks/shot-agent.mjs` (copy `shot-coded.mjs` machinery): launch the app with no document flags, real osascript ⌘N (addressed by unix id, frontmost checked in the same call) → CDP `window.pdf4allState()` shows `name "Untitled.pdf"`, `pages 1`; then CDP-type nothing else; shot `review-out/agent-new.png`; `PASS all`. Exit 2 + `OSA-UNAVAILABLE` / exit 1 + `blocked:` as the template. fable51 runs it only when the human is away.

## 0. Ground rules
progress.md §5 §0. `mutate` untouched; refusals never dirty; **no new dependency** (the MCP server is hand-rolled; `node:readline`, `node:net`, `node:child_process` only); no new renderer `.js`; no new reason token; no STATE key shape change (new STATE keys are allowed only if D5 needs a page-size slice and none exists — say so); existing fixtures byte-identical (`agent-session-hash-before.txt` = 56 lines; **nothing new under `fixtures/`** — the blank PDF is generated at runtime); never `save-in-place` a fixture; the Downloads sample is never copied anywhere; never `--no-sandbox`; never kill an Electron process whose command line lacks `--drive=` or a tmp `--user-data-dir`; secrets never in logs; build/test/Electron only under the lock in ONE Bash call: `( until mkdir ~/Documents/pdf4all/.quad/run.lock 2>/dev/null; do sleep 5; done; trap 'rmdir ~/Documents/pdf4all/.quad/run.lock' EXIT; cd ~/Documents/pdf4all && npm run build && node --test tests/agent-session.test.mjs )`; typecheck `npx tsc --noEmit -p tsconfig.json` needs no lock; macOS: no `timeout`, zsh `$pipestatus`; no artificial timers or time budgets anywhere in code or notes (waits are conditions: a `STEP` line, a lock dir, process exit). Additive edits only in shared files (`main.ts`, `renderer.ts`, `index.html`, `README.md`, design doc); never rewrite a whole existing file.
