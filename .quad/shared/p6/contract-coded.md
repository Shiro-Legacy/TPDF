# Coded simple fonts — symbolic TrueType/Type1 runs with no `/Encoding` edited through the P3 U3 repertoire gate

Drafted 2026-09-25 by fable51 (lean mode, one Opus 5.5 implementer, human-ordered in chat: "make it editable, extend the repertoire gate"). Line numbers are from `src/renderer/content-edit.ts` as of 2026-09-25 08:00; re-grep before editing.

**Problem (proven on `~/Downloads/file-example_PDF_1MB.pdf`, a LibreOffice-style export, NOT a fixture):** its five fonts are simple TrueType (`BAAAAA+LiberationSans-Bold` …) with `Flags 4`, `FirstChar 0`, NO `/Encoding`, a `/ToUnicode` with a 1-byte codespace (`<00> <FF>`, `<01> <0052>` bfchars) and a `/Widths` array; the text operands are sequential glyph codes (`[<010203040506>-1<07>…]TJ`). The scanner's reason chain (:2353-2354) treats a simple font with no `/Encoding` as WinAnsi, `editDecodeWinAnsi` fails on bytes < 0x20, and every run is `unsupported-encoding`: page 1 of that file scans 45 targets, 0 candidates (drive STATE `content.targets 45, candidates 0`). MuPDF's structured text reads the words fine through ToUnicode (stext font name = the full BaseFont incl. subset prefix, e.g. `BAAAAA+LiberationSans-Bold`).

**Decisions (fable51, lite mode; each built as written):**

- **D1 (classification)** — `EditCid` (:76) gains `bytesPerCode: 1 | 2` (2 for today's Identity-H). A simple font (`Type1`/`TrueType`/`MMType1`) is **coded** when ALL hold: `/Encoding` absent; `FontDescriptor /Flags` is a number with bit 3 (value 4, Symbolic) set and bit 6 (value 32, Nonsymbolic) clear; the descriptor embeds a program (`FontFile`/`FontFile2`/`FontFile3`); `/ToUnicode` is a stream this parser follows with **1-byte** codespace ranges and 1-byte bfchar/bfrange sources (destinations stay 4-hex BMP; `editParseToUnicode` (:1588) takes `bytesPerCode` and requires `EDIT_HEX2`-style 2-hex-digit sources when it is 1, keeping today's 4-hex strictness for 2); `/FirstChar` is an integer and `/Widths` an array of numbers (code = FirstChar + index → widths map, 1000-unit); `dw` = descriptor `/MissingWidth` when a number, else 0. Then `editResolveFont` sets `font.cid = { toUnicode, widths, dw, bytesPerCode: 1 }` (new helper `editResolveCoded(font, descriptor, state)` beside `editResolveCid` (:1697)). Any font failing one condition keeps today's path and today's reason tokens exactly (no new reason token, no `CONTENT_REASON_TEXT` change). Lazier alternative named and rejected: dropping the Flags gate would move nonsymbolic no-`/Encoding` fonts off the proven WinAnsi path.
- **D2 (scan)** — reason chain (:2340-2354): after the `Type0` branch add `else if (font.cid) { if (!cidDecoded) reason = "unsupported-encoding"; else if (editIsRtlOrShaping(cidDecoded.text)) reason = "rtl-or-shaping"; }` BEFORE the `!font.simple || font.encodingUnknown` branch. `editCodesOf` (:395) and `editDecodeCid` (:404) take `bytesPerCode` (1-byte: one code per byte, never odd-length null). The repertoire recording (:2309-2316), `record.cidKey`/`fontSize` (:2429-2431), `state.cidPending` (:2441) and `editAttachRepertoires` (:482) apply unchanged (they key on `font.cid` and `objectNumber > 0`); `record.cidWrite` (:83) gains `bytesPerCode`. `record.text` is the decoded text (already `cidDecoded.text`); bounds come from `editMatchRuns` with `font.summary.name` — verify against the fixture that the stext font name matches (the name has the subset prefix stripped on our side at :1758; if `editMatchRuns` compares names, prove the match on the fixture and on the Downloads sample before calling D2 done; if it does not match, fix the comparison in `editMatchRuns` for coded runs only and say so in the evidence).
- **D3 (write)** — `editHexOperand(codes, bytesPerCode)` (:503) writes 2 hex digits per code when `bytesPerCode` is 1 (`<0102>`), 4 otherwise. `editMeasureCid` (:527) is unchanged in logic (widths/1000 × size, `dw` fallback, `tjAdjustment`, Tc, Tz) but reads codes with the run's `bytesPerCode`. `editPlanText` (:956): the `cid` flag stays `record.cidWrite !== undefined`; a coded run's `tag` is `editActualTextBytes(next)` as for CID. TJ→Tj rewrite, tail rule, overflow/`tail-would-move`, undo, `garbage=yes` save exactly as U3. Paragraph rule (:2834 `record.cidWrite === undefined`) stays: coded runs are single-run edits (ceiling, record it). `text-add`, `edit-replace-*` need no change beyond going through `editPlanText`.
- **D4 (fixture)** — `fixtures/p0b/edit-coded.pdf` from a new deterministic `fixtures/p0b/make-edit-coded.mjs` (mupdf + `fixtures/fetch-font.mjs`; font = the already pinned `NotoSansHebrew[wdth,wght].ttf` — it has Latin glyphs (`L`=200, `o`=379 …); DroidSansFallback has none). One page 612×792: `F1` Helvetica control run `(PDF4All) Tj` at 72,740 (WinAnsi path, must stay a candidate as today); `F2` = one symbolic simple TrueType dictionary shaped like the LibreOffice sample: `/Subtype /TrueType`, `/BaseFont /AAAAAA+NotoSansHebrew`, NO `/Encoding`, descriptor `/Flags 4`, `/FirstChar 1`, `/Widths` from `Font.advanceGlyph(gid)*1000` rounded to integers, `/ToUnicode` with `<00> <FF>` codespace and 1-byte bfchars, `/FontFile2` = a font program that draws code→glyph: subset with `doc.subsetFonts()` first (MuPDF keeps glyph ids), then replace the program's `cmap` table by one with a single `(3,0)` format-4 subtable mapping `0xF000+code → gid` (and, if cheap, a `(1,0)` format-4 mapping `code → gid`); FreeType ignores table checksums but keep the directory consistent (tag/offset/length).
