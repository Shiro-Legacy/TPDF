# Drive guard — refuse unknown drive commands and an empty `content` object

Drafted 2026-09-25 by fable51 (lean mode, one Opus 5.5 implementer, human-ordered in chat: "fix the two leftovers, same process with opus 5.5"). Line numbers are from `src/renderer/renderer.ts` as of 2026-09-25 10:00; re-grep before editing.

**Problem (progress.md §10 "Agent session leftovers" (2) and (3), from `review-agent-session.md` findings 5 and 6):**
- (a) An unknown drive `cmd` reaches `runEditRequest(op, contents)` (:1613), matches no branch, falls off the end of the if/else chain (:1683) and `driven()` (:~1095) logs a STATE that shows nothing wrong: `error ""`, revision unchanged. An agent that typos `feilds` gets a green-looking result.
- (b) `{"cmd":"content","contents":{}}` (or `{"page":0}`, or any object with none of `text`/`find`/`action`/`password`) reaches `smokeContent` (:5100) and runs the `--edit=content` smoke's fixed self-test sequence (ALPHA→BETA→BRAVO×120 on the page's first candidate run) — a destructive edit nobody asked for. The self-test is still needed by `tests/p3-smoke2.test.mjs` (`--edit=content`, main.ts:209 sends `contents` undefined → renderer `null`, or `{"password":…}` for a locked fixture), so only the **object-without-keys** case is wrong.

**Decisions (fable51, lite mode; each built as written):**

- **D1 (unknown op)** — `runEditRequest` gets a final `else showError(\`Unknown command "${op}"\`);` after the `PAGE_OPS` branch (:1683). Nothing else changes: no revision, no dirty, no announcement, no journal step. main.ts is untouched (its own cmds `open/save-to/save-in-place/print-to/wait/new/close/state` never reach the renderer; every other cmd already goes to the renderer, so this one guard covers every path: drive file, stdin session, MCP). Verify by grep that every op main's menus send is on the chain (`grep -o "op: '[a-z-]*'" src/main.ts | sort -u` vs the chain) so no menu item starts showing the error.
- **D2 (empty content object)** — in `smokeContent`, right after `wanted = parsed` succeeds (:5111): if the parsed object has none of `text`, `find`, `action`, `password` as own keys of the right type (`text` string, `find` string, `action` string, `password` string), `showError("content: give text, find or action")`, set `contentRefusals = []`, `contentEdited = null`, `contentReplaced = null` (already reset above), `logContentSmoke()` if that is what the other early returns do, and `return` — before `refreshContentTargets`. `contents === null` (the smoke/menu path) and `{password}`-only objects keep today's behaviour. Non-JSON strings keep today's behaviour too (out of scope).
- **D3 (error lifetime)** — check how `error` clears between steps (41 `clearError()` callers; e.g. :1046 in the request path). The next step that succeeds must show `error ""` again, exactly as after any existing refusal; if a plain `state` step does NOT clear it, that is existing behaviour — do not change it, just pin it in the drive script's expects and say so in the build note.
- **D4 (drive script)** — new `tests/drive/drive-guard.jsonl` (never touch existing scripts): `open fixtures/p0b/edit-transformed.pdf` → `doc.name`; `{"cmd":"nosuch"}` → expect `error "Unknown command \"nosuch\""`, `revision 0`, `dirty false`; `{"cmd":"feilds","contents":{"action":"fill","name":"x","value":"y"}}` → same shape of error; `{"cmd":"content","contents":{}}` → expect `error "content: give text, find or action"`, `revision 0`, `dirty false`, `content.edited null`; `{"cmd":"content","contents":{"page":0}}` → same; `{"cmd":"find","contents":{"query":"ALPHA"}}` → `search.count 1` (the first run is intact); `{"cmd":"content","contents":{"target":"ALPHA","text":"BETA"}}` → `content.edited {from:"ALPHA", to:"BETA"}`, `revision 1`, `dirty true`, `error ""` (or per D3); `{"cmd":"content","contents":{"password":"nope"}}` is NOT in the script (it would run the self-test on an unlocked doc — that is the preserved smoke path; document it instead).
- **D5 (tests, red before fix)** — new `tests/drive-guard.test.mjs` (copy `drive()`/`red()` helpers from `tests/p3-coded-drive.test.mjs`; never import them; `skip: CI_NO_ELECTRON`): (a) the drive script runs 0 red, with the step count pinned and the two error strings asserted from the report (not only via expects); (b) MCP: spawn `scripts/pdf4all-mcp.mjs` with pipes (copy the helper from `tests/agent-session.test.mjs` test (d)), `initialize`, `tools/call pdf4all_do {cmd:"nosuch"}` → `isError true` and the text contains `Unknown command`, `tools/call pdf4all_do {cmd:"content", contents:{}}` → `isError true`, then close stdin → exit 0, cleanup in `finally`/`t.after` even on failure; (c) `--edit=content` smoke path still works: do NOT duplicate `tests/p3-smoke2.test.mjs`, just run that existing file once under the lock and quote the result in the build note. Run the new file before any source change and save the output to `.quad/shared/p6/acceptance/drive-guard-red-before.log` (≥ 1 `not ok`).
- **D6 (docs)** — `docs/agent.md`: replace the sentence at :41 ("An unknown `cmd` does nothing and reports no error: check that `revision` moved.") with "An unknown `cmd` sets `error` `Unknown command "…"` and changes nothing." and the sentence at :87-88 ("Always send `text` (or `find`): a `content` step with neither runs the built-in self-test edit on the page's first run.") with "A `content` object with none of `text`, `find` or `action` is refused (`error` "content: give text, find or action")." Add both refusals to "### Refusals you will meet" (one line). `.quad/shared/p3/design-agent-drive.md`: one sentence under "## Agent session". No Help change (these are drive-only refusals; the GUI cannot send an unknown op).
- **D7 (GUI proof)** — no new shot: the unit touches the renderer's dispatcher, so the regression proof is the existing `checks/shot-agent.mjs` (real ⌘N through the same dispatcher → Untitled.pdf, `review-out/agent-new.png`); fable51 runs it when the human is away.
