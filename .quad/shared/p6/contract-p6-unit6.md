## 1. Engine (`src/renderer/engine.ts`, `content-edit.ts`)
### 1.1 Placement rule: eight orientations and one optional clip
`EditPlacement` (content-edit.ts:90-101) gains `orient: EditOrient` and `clip: { rect: number[]; start: number; end: number } | null`, where `export type EditOrient = { swap: boolean; sx: 1 | -1; sy: 1 | -1 }` (new, exported beside `EditPlacement`). `simplePlacement` (2279-2295) accepts a `cm` matrix of either form: **plain** `[a, 0, 0, d, e, f]` with `a ≠ 0, d ≠ 0` → `orient = { swap:false, sx: sign(a), sy: sign(d) }`, or **swapped** `[0, b, c, 0, e, f]` with `b ≠ 0, c ≠ 0` → `orient = { swap:true, sx: sign(c), sy: sign(b) }` (x' = c·y + e, y' = b·x + f). Anything else stays `null` (still `unsupported-transform`). New pure exported `editOrientOf(matrix: number[]): EditOrient | null` is that classification; `editPlacementMatrix(box, rect, orient = { swap:false, sx:1, sy:1 })` (542) writes `a 0 0 d e f` for plain and `0 b c 0 e f` for swapped, magnitudes from the box/rect side ratios (swapped: `|c| = boxW / rectH`, `|b| = boxH / rectW`), `e`/`f` so that the mapped rect's bounding box is exactly `box` (`e = box[0] − min over the mapped x of rect's corners`, same for `f`); both callers (engine.ts move/resize and `editDuplicateEdit`, 555) pass `placement.orient`. `placement.box` (the rect the U4 code moves/resizes/duplicates) is the **axis-aligned bounding box of rect's four corners under the matrix**, normalised (`min/max`), for every orientation; `placement.view` follows. **Clip:** in `applyOperator` (2428-2460) the sequence `x y w h re` → `W` → `n` **directly after a `q` and before any `cm` of that block** (four numeric operands, no operator between the three) keeps `current.clean` and records `current.clipRe = { rect: [x, y, x+w, y+h] normalised, start: <start of the first operand>, end: <end of the n token> }`; any other `re`/`W`/`n` placement (after the `cm`, a second clip, a path with more segments) makes the block unclean as today. `simplePlacement` copies it to `placement.clip`, and the placement's **visible** rect is `box ∩ clip.rect` (empty or under 1 pt on a side → not a placement, `unsupported-transform`). The public `EditTarget.placement` (engine.ts:526) becomes `{ box: number[]; orient: EditOrient; full?: number[] }`: `box` is the **visible** rect (so every existing pin on uncropped fixtures is unchanged), `full` is the uncropped box, present only when a clip is present. `objectOps` gains `"transform"` and `"crop"` **last** wherever `"move"` is listed (2354, 2355, 2386; 2356's `["replace"]` stays); `EditObjectAction` (engine.ts:422) gains `"transform" | "crop"`. A clipped or rotated placement that now matches is a candidate with the full list; `formRect` (2297) is unchanged (a Form's `/Matrix` is inside `rect`, the `cm` sits above it).
### 1.2 `edit-object` actions
`EditObjectRequest` (engine.ts:423-434) gains `transform?: "rotate-cw" | "rotate-ccw" | "flip-h" | "flip-v"`. **Every placement write is one affine applied to the `cm` and, when present, to the clip rect**, so the visible rect, the full box and the clip stay consistent: `move`/`resize {box}` — `box` is the new **visible** rect (validated by `editObjectBox` against `editPageClipBox`, 657, exactly as today; the full box may leave the page when a clip hides that part); the axis-aligned affine A that maps the old visible rect onto `box` is applied to `full` (`full' = A(full)`, written via `editPlacementMatrix(full', rect, orient)`) and to `clip.rect` (rewritten in place as `x y w h re` with `editNumber`, the `W n` bytes untouched); without a clip `full' = box` as today. **`transform {transform, box?}`** — T is the 90° rotation or the flip about the visible rect's centre in page space (rotate-cw = the −90° matrix `[0 −1 1 0]`, rotate-ccw = `[0 1 −1 0]`, flip-h = `[−1 0 0 1]`, flip-v = `[1 0 0 −1]`, each conjugated by the centre translation); the new `cm` is the numeric product `M · T` (row-vector convention, `editAffine` order), the new orient is `editOrientOf` of it (so rotate-cw on the identity gives `{swap:true, sx:1, sy:−1}`, rotate-ccw `{swap:true, sx:−1, sy:1}`, flip-h `{swap:false, sx:−1, sy:1}`, flip-v `{swap:false, sx:1, sy:−1}`, rotate-cw twice `{swap:false, sx:−1, sy:−1}`), the new full box and clip rect are the bounding boxes of their corners under T; when `box` is given, the result is then refitted so the visible rect equals `box` (validated by `editObjectBox`; the same A-affine as move/resize, so a rotated rect of the same size is a pure translation); without `box` the rotated visible rect must pass `editObjectBox` itself or the request refuses `out-of-bounds` (nothing written). A missing/unknown `transform` refuses `"invalid-transform"` (new `EditObjectDetail` token). **`crop {box}`** — `box` is the new visible rect: `editObjectBox` first, then it must lie inside `full` (each edge within 0.01 pt) or `out-of-bounds`; writes or replaces the clip as `x y w h re W n` (new: inserted right after the `q` token, before the `cm`, with a `\n`; existing: the `x y w h` operands rewritten in place); `box` equal to `full` within 0.01 on every edge **removes** the clip bytes (`[clip.start, clip.end)` → `""`) and is a no-op when there was none. `crop` and `transform` are checked against `objectOps` as every action is (4711-4719); the same-`cm`-and-same-clip no-op check applies to `move`/`resize`/`crop` (a `transform` is never a no-op). Reply, journal, privatise (cow) and refusal order are today's (4689-4851); one `mutate("edit object")`.

### 2.4 Alignment guides (`snapRect`, exported pure)
`export function snapRect(rect: number[], others: number[][], page: { width: number; height: number }, tolerance = 4, edges: ('x0'|'x1'|'cx'|'y0'|'y1'|'cy')[] = all six): { rect: number[]; guides: { axis: 'x'|'y'; at: number }[] }` (renderer.ts, beside `gestureRect` 2216; view space, y down): candidates per axis are every other rect's two edges and centre plus the page's two edges and centre; for each of the moving rect's listed edges the smallest |delta| ≤ tolerance wins (ties: the first candidate in `others` order, page last), at most one delta and one guide per axis; the returned rect is the input translated by the winning deltas, never resized. `startRectGesture` calls it on every move for object gestures (single body drag, group drag, ⌥-drag duplicate, group-box handles, crop handles) **after** the delta and **before** `gestureRect`'s clamp: grip = all six edges; a side/corner handle = only the edges that handle moves (centres excluded); `others` = the view rects of every painted `.object-target` not in the selection (text runs, fields, links and marks are not guide sources — ceiling); `event.metaKey` on the move → no snap, guides cleared.
