## checkedFine
- §1.2 maths (`maths.mjs`, built `editAffine`, content-edit.ts:621-623). `editAffine(left, right)` is row-vector `left × right` (apply `left` first). So the new cm is `editAffine(M, Tc)`, with `Tc = editAffine(editAffine(translate(−c), [...T,0,0]), translate(c))`. `editMultiply` (614) is the linear-part product. The seat uses `editAffine`. All five orients and every §1.4 box and cm are exact: Im1 cw `0 -100 50 0 97 675` box [97,575,147,675]; ccw `0 100 -50 0 147 575`; flip-h `-100 0 0 50 172 600`; flip-v `100 0 0 -50 72 650`; cw×2 {false,-1,-1}; Im2 cw `-100 0 0 -50 475 725` [375,675,475,725]; Im2 flip-h {true,-1,-1}; Im3 flip-h `100 0 0 50 200 600`; Im3 cw {true,1,1} [225,575,275,675]; Im4 cw full [82,350,132,450] clip [82,390,122,450]; Fm1 cw `0 -1 1 0 122 350` [122,50,322,350]. Move/resize affines: Im4 move gives cm `100 0 0 50 172 400`, re `172 400 60 40`; Im4 resize gives full [72,400,272,500]. The swapped convention (x' = c·y+e, y' = b·x+f, sx = sign c, sy = sign b) matches the rest. The linear parts stay exact zeros under products with 0/±1. `-0` is harmless (`!== 0` is false, and `editNumber` prints `0`).
- §1.1 writer: `e = box[0] − min(mapped x)` gives Im2 `0 -100 50 0 400 750` and Im3 `-100 0 0 50 300 600` for rect [0,0,1,1]. For a plain matrix with a > 0 it equals today's `box[0] − a·rect[0]` (542-548), so the default parameter keeps byte-identical output for every existing caller. tests/, scripts/ and checks/ never import `editPlacementMatrix`, `editDuplicateEdit`, `simplePlacement` or `EditPlacement`. Their only users are engine.ts:4732, 4781, 4791, 4833, 4879, 4916, 4949-4950, and the re-exports at 5388-5389.
- Clip lexing (check 4). Every operator reaches `applyOperator` with its own operand list (2595-2598), and `re` arrives as four `{t:'num', n, start, end}`, exactly like `cm`. `W` and `n` arrive with empty lists. Today they only hit the `clean = false` line (2431). No path or clip state exists, the scanner's `ctm`/`bounds` ignore clips, and a placement's box comes only from its `cm` (2289). `geometryBlocked` (1685) is page-level and orthogonal. Before the `cm`, the only CTM is the page's own, because outer `cms` must be empty (2282). So the `re` rect is in page space.

A clip rewrite `[opsStart, opsEnd)` plus a cm rewrite `[cmStart, cmEnd)` in one block are disjoint and ordered, so they are accepted. (An equal-start insert would only pass if listed after the replacement; the E3 insert at `qToken.end` never shares a start with the cm.)

- Do every `editObjectBox`, containment, `full'` ceiling (E9) and `invalid-transform` check before `mutate`, so a refusal never dirties. `transform` never takes the same-cm no-op path.
