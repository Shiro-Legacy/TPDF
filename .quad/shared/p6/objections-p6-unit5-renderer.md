## checkedFine (tried to break, could not)
- **Shift reaches the listener (question 1).** `driveDirectClick` dispatches pointerdown → pointerup → click on the same element (1263-1275). The object's pointerdown runs `startRectGesture`, which stops propagation (2291) and focuses without clearing. `clickToAdd` returns before `dropDirectFocus` for hit-layer targets (2847), and no focus listener exists on object targets. Adding `shiftKey` to the click init at 1275 is enough.
- **Threshold and Escape (question 2).** The 3 px threshold (2302) and the window-level Escape cancel (2318) apply to any rect, the union included. `gestureRect` 'grip' clamps the union to the page (2171-2174). The 4.2 clamp arithmetic checks out: union [72,52,460,192], dy −80 → delta −52 → Im2 [400,0,460,40], Im1 [72,90,172,140].
- **⌥ on pointerdown (question 3).** Nothing conflicts: the text ⌥-click single-run path lives in the text-target click listener (2465), not on objects; buttons are not HTML5-draggable; `startRectGesture` calls `preventDefault`. `driveDirectClick` already passes `altKey` (1263). `driveDirectGesture` passes only `shiftKey` today (1310-1313), so the contract's `altKey` addition there is needed and enough.
- **No Electron default context menu.** src/ has no `contextmenu` or `context-menu` listener and main.ts builds only the application menu (963), so `preventDefault` is harmless. Chromium's key name is `ContextMenu`.
- **The `hidden` div and p2-shell.** The inventory scan covers only `<button|textarea|input|select>` (p2-shell:103-114). The three menuitems carry id + text, the `div[role=menu]` is not scanned, and `hidden` works because the contract CSS sets no `display`.
- **`key Shift+F10`.** It parses at 1332-1333 and reaches a focused `.object-target` through `onTarget` (1348-1352). Its keydown needs a branch before `else if (event.key !== " ") return;` (2605).
- **The 'menu' op name.** It reaches `runEditRequest` unfiltered (preload.cts:77-87; renderer 952-960) and is not in `OP_MODE` (572).
- **Clearing (question 6).** Page change (1882), mode change (`cancelPendingTools` 4158) and open all go through `clearDirectFocus`, so wiring the selection there covers them. So do undo/redo (5933/5953), `openInlineText`, `openAddText` and `activateField`; 4.1 re-clicks after every `undo`, so it is consistent (state it in §2.1's list).
- **`content.edited` keys.** p3-drive.test.mjs:93 deep-equals `edited` for text edits only, and the single-object path is unchanged, so adding `count` for `kind:'objects'` is safe.
- **Help edits (question 7).** Every quoted phrase exists verbatim at index.html:550, 551 and 561; the row count stays 11 (p2-shell:127); `CONTENT_REASON_TEXT` is untouched.
- **Handles.** `.hit-target.selected.multi .hit-handle` (0,4,0) beats `.hit-target:hover/.active/.selected .hit-handle` (0,3,0), so handles and the grip stay hidden on a group.
- **4.1 revision arithmetic** (0, 1, 2 … 15, 16) is consistent with one op per gesture plus undo.

## buildRisks
- `EditObjectDetail` (engine.ts:437-439) has no `"invalid"`. The engine seat must widen it for `edit-objects`, or `failEditObject("invalid", …)` will not compile, and the renderer reads `refused.detail` verbatim (3617).
- `startRectGesture` is shared by fields, marks and objects. The optional `place` (R2) must default to today's `placeBox(button, …)` byte-for-byte, or the P6 U2–U4 drives regress (direct-edit3/4/5 in acceptance).
- Tests `pick()` object boxes by name. After a duplicate, two `Im2` entries exist in `content.objects[]`, so harness picks must match by `view` box, not name alone.
- The review S2 test pins the `const onTarget = …` line to contain `#hit-layer .sig-target` (p2-shell:190-193). Any edit to that line must keep the substring.
