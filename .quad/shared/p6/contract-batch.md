# Batch — one action over a folder of PDFs, with a queue, a progress view and a per-file report

Drafted 2026-09-24 by fable51 (lean mode, Opus 5.5 subagents, no fixture phase). Builds on the Bates unit (`{bates}` counter in the renderer). Line numbers from `maps-bates-batch.md`; re-grep. **Decisions (fable51's, lite mode; lazier alternative named; each built as written):**

- **D1 (the action)** — the one action is a stamp: header, footer or watermark text with the four placeholders including `{bates}` (so Bates numbering spans the whole folder in file order). The action travels as the existing stamp fields `{kind, text, pages?, align?, batesPad?}`; `batesStart` comes from the renderer counter per file. Lazier alternative (also taken): no other action in this unit; the queue passes an opaque `action` object so a later unit adds flatten/labels without touching the queue.
- **D2 (documents never touch the open one)** — a new engine op `batch-file { name, bytes, action }` opens a TRANSIENT document (the `insert-pages` precedent, engine.ts:5103: `openDocument(bytes)`, `disableJS`, refuse `needsPassword`/encrypted and no-edit permission), runs `stampPage` over the requested pages, saves to a buffer and closes it in `finally`. No journal, no `mutate`, no revision, no dirty; the human's open document and its undo stack are untouched. Reply `{ ok:true, pages, bytes (transferred), bates?: {from,to} }` or `{ ok:false, reason }` with reasons `encrypted`, `no-edit-permission`, `not-pdf`, `too-large`, `bad-pages`, `stamp-error`. `OP_PERMISSION["batch-file"] = "any"` (the op checks the transient doc's own permission).
- **D3 (folder access)** — main gains two IPC channels: `pick-folder` (`showOpenDialog({properties:["openDirectory"]})`, or the `--batch-dir=<abs>` smoke/drive override; `readdir`, `.pdf` case-insensitive, `inspectRegularFile`, ≤ `BATCH_MAX_FILES = 200` else refuse `too-many-files`, per-file `pdfWithinCeiling` reported as `too-large` rather than refusing the folder; returns `{ ok, folder, files: [{ name, bytes: size }] }` and REMEMBERS the listing) and `batch-io { name, action: "read" | "write", bytes? }` (read returns the bytes of a listed name only; write puts bytes at `<folder>/pdf4all-out/<name>` creating the dir once and refusing `exists` if the file is already there — never overwrite, never write outside `pdf4all-out`). Lazier alternative rejected: reusing `save-new` would open a dialog per file.
- **D4 (progress view)** — `#batch-dialog` on the `#verify-dialog` model: heading, folder line, `#batch-summary` (`role="status"`, live), `<table>` `#batch-list` rows name · status (queued/running/ok/failed) · pages · detail, buttons `#batch-start`, `#batch-cancel` (stops after the running file), `#batch-close`. The report is `<folder>/pdf4all-out/report.txt` (one line per file: name, ok|failed, pages, detail, Bates range) written through `batch-io write` at the end. Lazier alternative rejected (report only in the dialog): the human asked for a per-file report they can keep.
- **D5 (entry points)** — File menu "Batch…" with `Alt+CmdOrCtrl+B` (not a macOS reserved chord; check `macos-reserved-chords`), sends `edit-request {op:"batch"}`; renderer routes `contents === null` → open dialog and pick folder, else drive: `batch { folder?: (uses --batch-dir), kind, text, pages?, align?, batesPad? }` runs the whole queue headless and resolves when done. `OP_MODE["batch"]` = none (works in any mode; no document needs to be open).
