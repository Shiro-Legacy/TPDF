## 2. Renderer (`src/renderer/renderer.ts`, `index.html`, `styles.css`)
### 2.1 Selection model (Edit text mode, object targets only)
New module state `directSelection: string[]` (targetIds in click order; `[]` when none) beside `directFocusedObject` (renderer.ts:2221), which stays the **anchor** (last clicked member; `direct.active {kind:'object'}` keeps reporting it). Plain click on an object target (2601 `focusObject`) → `directSelection = [id]`. **Shift-click** toggles: adds a non-member (anchor = it), removes a member (anchor = the last remaining; an empty result = `dropDirectFocus()`); Shift-click on a text run, field, link or mark is today's click. Painting: every member gets `.selected` (a new `markSelection()` replaces the single-button `markSelected` call for objects; `markSelected` itself is unchanged for fields/links/marks); members of a selection of ≥ 2 also get class `multi`, and CSS `.hit-target.selected.multi .hit-handle { display: none }` (grip included) so only a single selection shows handles. Selection survives a repaint/rescan (re-resolved through `resolveObject`, 2513, kind + name + nearest; a member that no longer resolves is dropped) and is cleared by `clearDirectFocus` (2229: page change, mode change, open), Escape, a click on empty space (the add-text click still opens its editor after clearing), and after a compound delete.
### 2.2 Group gestures (one `edit-objects` per gesture)
With ≥ 2 members: a **body drag** on any member starts `startRectGesture` (2288) on the **union rect** of the members (page clamp comes for free from `gestureRect`'s `page` option, so the whole block stays on the page — the engine's `out-of-bounds` is therefore not drive-reachable); during the drag every member button is translated by the same delta (`follow` hook, or the renderer seat's equivalent); on release `commitObjectGroup(delta)` sends `edit-objects` with a `move` item per member (`box` = member box + delta in PDF space via `pdfBox`, snapped to the clip within 0.01 as 2626). **Arrows** on a focused member (⌥ 1 pt, ⌥⇧ 10 pt, plain as U4 §9.12, ⌥⌘←/→ ignored for groups) → the same group move with the delta clamped by the union. **Delete/Backspace** → `edit-objects` delete items for every member (the reply's `applyEdit` repaints; selection cleared). **Enter / double-click** (replace) stay single-selection only (2600, 2609): with ≥ 2 members they do nothing. After a compound reply: `contentEdited = { kind:'objects', action, name: <member names joined by ","> , count: n }` (new key `count`; `kind:'objects'` is a new value of an existing string key), announcement `Moved 2 objects` / `Deleted 2 objects` / `Duplicated 2 objects`; the refusal path is `applyObjectEdit`'s (3608-3626) with `contentRefusals.push({ text: <names>, detail })`. With 1 member every gesture is today's `edit-object` path, byte-for-byte.
### 2.3 ⌥-drag duplicate
`paintObjectTarget`'s body `pointerdown` (2599): `event.altKey` → the gesture is a **duplicate**: same `startRectGesture` (handle `grip`, 3 px threshold; under it = today's click), a ghost is the dragged button itself (the original's outline stays where it was via a temporary clone with class `ghost`, `pointer-events:none`, removed on end/cancel), and the commit sends `edit-object {action:'duplicate', box}` (single) or `edit-objects` duplicate items (each member box + delta, clamped by the union as §2.2). After the reply the **copies** are the selection (resolved as the kind + name objects nearest each requested box); the originals stay. ⌥ on a handle (resize) is ignored (today's resize). `direct.gesture` during an ⌥-drag reports `kind:'duplicate'` (`DirectGesture.kind` gains the value).
### 2.4 Context menu
