## Observations (numbers are page points)
1. **Exist and work.** `Link.setBounds(rect: Rect): void`, `Link.setURI(uri: string): void` (both return `undefined`). Link has **no** `getObject`/`getRect`. Bad input throws `expected rectangle` / `expected string`. Without an outer op each call journals itself: steps `["Set link rectangle","Set link uri"]` (2 steps).
2. **Journaled inside `beginOperation('x')…endOperation()`**: 1 step `["x"]`. `pdf.undo()` → fresh `getLinks()` shows old bounds `[72,162,300,192]` + `https://example.com/`, raw `/Rect [72 600 300 630]`; `redo()` re-applies. Engine `{op:'redo'}` reports `step:"x"`. A page held open across undo is re-synced (held and fresh both old).
3. **Save round-trip** (engine `save` = `incremental=no,garbage=yes`) → reopen: `getBounds()/getURI()` and engine `links` show the new values on p0 and on the rotated p1.
4. **SPACE TRAP — `setBounds` takes RAW `/Rect` space (unrotated, y-up), `getBounds` returns page space (y-down, rotated).** p0: `setBounds([100,150,250,190])` writes `/Rect [100 150 250 190]`, fresh read `[100,602,250,642]`. p1 (/Rotate 90, `page.getBounds()` `[0,0,792,612]`, `getTransform()` `[0,1,1,0,0,0]`): link `getBounds` `[600,72,630,300]` = Widget `getRect` `[600,72,630,300]` = the space Redact `setRect/getRect` use; `setBounds([100,200,180,260])` reads back `[200,100,260,180]` while Widget/Redact `setRect` of the same rect wrote `/Rect [200 100 260 180]` and read back `[100,200,180,260]`. `page.createLink(R)` is correct (page space in, `/Rect [200 100 260 180]`). Fix proven: `setBounds(Rect.transform(R, Matrix.invert(page.getTransform())))` reads back R exactly on p0 and p1, before and after save. Also: the same Link object's `getBounds()` right after `setBounds` echoes the raw input (not page space) — always re-read from a fresh page.
5. **Identity.** Links are **not** in `page.getAnnotations()` (p0 with 2 links → `[]`; engine `annots` → `[]`; p1 → `[]`, the Widget is only in `getWidgets()`), so `annotId()`/`findAnnotation()` cannot find them. Id = object number of the `/Annots` entry (`page.getObject().get('Annots').get(k).asIndirect()`, `/Subtype /Link`). createLink×3 (15,16,17 appended after 13) + deleteLink(middle) → `getLinks()` `[#page=1, a, c]` = `/Annots` `[13,15,17]` (order equal). A Link dict with no `/A`/`/Dest` inserted at index 1 (obj 18) is in `/Annots` but **skipped by `getLinks()`** (3 links vs 4 entries → index drift). Object numbers survived `garbage=yes` save (13,18,15,17). An inline (direct) Link dict: `getLinks()` lists it, `asIndirect()` = **0**.
6. **Retarget.** `doc.formatLinkURI(fitDest(2))` = `"#page=3&view=Fit"`; `setURI` of it on URI link 11 → `/A <</S/GoTo/D[5 0 R/Fit]>>`, `resolveLink` = 2; GoTo link 10 → `setURI('https://…')` → `/A <</S/URI/URI(…)>>`, `resolveLink` = −1; both survive save. **`/Dest` shadows `/A`:** on link 13 `setURI('https://…')` adds `/A` but keeps `/Dest [3 0 R/Fit]`, so `getLinks()` still says `#page=1`, `to 0` (also after save). Fix proven: `entry.delete('Dest')` + `setURI` in one op → new URI wins, 1 step, undo restores `/Dest`. `setURI` does no scheme policy: `javascript:alert(1)` → `/S/URI`; `file:///etc/hosts` → `/S/GoToR` + new filespec obj, `getURI` `file:///etc/hosts#page=1`, **`resolveLink` = 0** (listLinks would call it `kind:'page'`); `#nameddest=foo` → `/D(foo)`, resolve −1; `#page=99` throws `cannot find page 99 in page tree`; `""` throws `unsupported link URI type` (abandon leaves the old /A).
7. **Fallback (raw dict) also works**: in one op `entry.put('Rect',[100,602,250,642])` (raw y-up) + `put('A', <</S/URI/URI(…)>>)` → fresh read `[100,150,250,190]`/new URI; undo → old; redo → new; save/reopen → new.
8. **Hazards.** `setBounds` with the unchanged rect still journals a step (`["Set link rectangle"]`) → engine needs its own no-op check (as redact-set). While any handle on the page stays open, `loadPage` returns the cached page: after `setBounds` it reports the raw rect `[100,602,250,642]`, after a raw `put('Rect')` the old rect, until the handle is destroyed (engine loads/destroys per op today: keep it that way; read back after `destroy`).

## Recommendation
- `listLinks` gains `annotId`: walk `/Annots` entries with `/Subtype /Link` in order and zip onto `getLinks()`, skipping entries MuPDF skips (no `/Rect`, or none of `/Dest`, `/A`, `/AA`); confirm each pair by `Rect.transform(raw /Rect, page.getTransform())` ≈ `getBounds()` ±0.01, else advance. Inline dicts report `annotId: 0`, and `link-set` refuses them (`no-such-annot`): a stated ceiling.
- `link-set {page, annotId, rect?, target?}`: validation first (`checkLinkRect` page space, `LINK_SCHEMES` + `MAX_URI_CHARS` exactly as link-add, target page via `checkPage`), find the entry by `annotId` (`no-such-annot`; subtype not Link → `not-link`), no-op when the rect is within ±0.01 of `getBounds()` and the URI equals `getURI()` (returns `noop:true`, no journal). Then ONE `mutate`, one page handle: `link.setBounds(Rect.transform(rect, Matrix.invert(page.getTransform())))` when the rect changed; `entry.delete('Dest')` + `link.setURI(uri or formatLinkURI(fitDest(p)))` when the target changed. Destroy the page, then reply.
- Tests: p0 + /Rotate 90 page (page-space rect in = `links` rect out), `/Dest` link → URI, URI → page, save `garbage=yes` → reopen → `links`, undo/redo restore rect + target, same-rect no-op keeps `revision`, `javascript:`/`file:` refused before any write, a bare Link dict does not shift `annotId`s.
