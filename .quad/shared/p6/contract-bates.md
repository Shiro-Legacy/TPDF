# Bates numbering — a `{bates}` counter on the stamp op that spans files

Drafted 2026-09-24 by fable51 (lean mode, Opus 5.5 subagents, no fixture phase). One unit on the existing `stamp` op (kind header/footer/watermark): a new placeholder, a zero-padded counter that the renderer carries from one document to the next, right alignment for header/footer, dialog fields, drive path, STATE slice, Help. Line numbers from `maps-bates-batch.md` (2026-09-24); re-grep before editing. **Decisions (fable51's, lite mode; lazier alternative named; each built as written):**

- **D1 (token + fields)** — `{bates}` is a fourth placeholder in the stamp text. `StampRequest` gains `batesStart?: number` (integer 0 … 10^15−1) and `batesPad?: number` (integer 1 … 15, default 6). When the text contains `{bates}` the engine expands it per stamped page, in stamped-page order, to `String(batesStart + i).padStart(batesPad, "0")`; `batesStart` is REQUIRED when the token is present (refusal token `bates-start-required`), so the renderer, not the engine, owns the "continue from last" default. Bad start/pad → `invalid-bates`. Lazier alternative (default start 1) rejected: an implicit start hides where a drive's numbering came from.
- **D2 (counter spans files)** — the renderer keeps `batesNext` (module-level, survives `open` and `close`; starts at 1) and after an ok stamp whose text had `{bates}` sets it to `to + 1`. STATE gains `decorate.bates: { next: number, pad: number, last: { from, to, pages: number[] } | null }`. `ponytail:` undo does not roll the counter back — the dialog's start field defaults to `next` and the human overrides it; Help says so. Lazier alternative (counter per document) rejected: spanning files is the point.
- **D3 (alignment)** — header/footer gain `align?: "left" | "right"` (default left = today). Right places the run at `vx = visualWidth − 36 − textWidth`, `textWidth = chars × size × 0.556` (Helvetica digit width; the watermark already uses a 0.5-em estimate). `ponytail:` no font measurement — a right-aligned ACME-000100 lands within ≈5 pt of the margin; the test tolerance is 10 pt. Watermark ignores `align`.
- **D4 (reply)** — the stamp reply gains `bates: { from, to }` when the token was used. No new op, no `OP_PERMISSION` change (`"stamp": "edit"` covers it). `--edit` smoke allowlist untouched; the AI path is the drive (open → header-footer → save-to over N files already works).
