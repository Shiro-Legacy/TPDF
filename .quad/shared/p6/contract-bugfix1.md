**Problem (progress.md §10 "Real bugs"; full wording `docs/history.md` :151, :155, :157):**
- (B1) `text-add` after an undone `text-add` points the new run's `/PDF4AllF<n>` at a freed font object: the run scans `unsupported-encoding`, gets no target, draws in a fallback font. Repro `.quad/scratch/p6u8/impl/probe4.mjs`. Code: `src/renderer/engine.ts` :5657-5667 (`pdf.addSimpleFont(baseFont, "Latin")`); the stamp path :3193-3196 calls `pdf.addSimpleFont(font)` the same way.
- (B2) A run the app wrote (`text-add`) cannot grow when edited: "Twin" → "Twin 2" refuses `overflow` with free space to its right. Code: `src/renderer/content-edit.ts` `editAttachGrowthLimits` :1840-1871 — `pageRight` is the right-most text edge on the page, so a lone run's limit is its own right edge (:1868); consumed at :1004.
- (B3) GUI ⌘S on `Untitled.pdf` (File → New) silently writes into the `pdf4all-new-*` temp folder. Code: `src/main.ts` `newBlank` :425-439, `save-file` handler :614-678 (in-place branch :641-654); renderer `saveInPlace` `src/renderer/renderer.ts` :9735.
- (B4) MCP `pdf4all_save {path:"sub/x.pdf"}` into a missing folder → `save {ok:false, reason:"write-failed"}`. Code: `scripts/pdf4all-mcp.mjs` :78-82.
- (B5) Undo/redo never clears the error bar. Code: `src/renderer/renderer.ts` `undoEdit` :7183, `redoEdit` :7204.
- (B6, suspected) `src/renderer/content-edit.ts` `scanEditTargets` :1883-1887 reads `/Rotate` and `/UserUnit` with `at(pageDict, …)`, which misses an inherited `/Rotate`; `engine.ts` :5632 uses `getInheritable("Rotate")`. If true, a page rotated through its `/Pages` parent is scanned as editable.

## Decisions (fable51, lite mode; each built as written)

- **D1 (B1, root cause first)** — Before editing, prove the cause with a headless probe under `.quad/scratch/bugfix1/` (expected: mupdf's font-resource cache returns the object freed by the journal undo; print the returned object's number and whether it resolves to a dictionary). Fix once, in ONE helper in `engine.ts` that both callers (:3196 and :5664) use: call `addSimpleFont` as today; if the returned object does not resolve to a dictionary with `/Type /Font`, build a fresh font dictionary with `pdf.addObject(...)` whose keys and values equal what `addSimpleFont` returns in the good case for that Base-14 font (dump the good dictionary in the probe; quote it in the build note). The good path must stay byte-identical: every existing sha pin (`tests/p6-bates.test.mjs`, `tests/p2-decorate.test.mjs`, drive pins) stays green unchanged. If the probe shows a different cause, stop, write the finding into the build note and fix that cause instead, inside the same two call sites. Never patch the scan or the renderer announcement to hide it.
- **D2 (B2)** — In `editAttachGrowthLimits`, a text record whose `tfName` matches `/^PDF4AllF\d*$/` (the names only this app writes) takes `growthLimit = obstacleLimit ?? <right edge of the page box in the same space as record.bounds>`; `state.page.getBounds()` is available in the scan state. Every other run keeps today's text-margin rule exactly. `obstacleLimit`, `tailFollows` and the `outside-page` check are unchanged; a grow that would cross the page edge or an obstacle still refuses `overflow` with the same detail shape. If `tests/drive/direct-edit9.jsonl` or any test pins the old `overflow` refusal for an app-written run, flip that pin's values in place (never insert or delete lines; step counts unchanged) and list each flip in the build note.
- **D3 (B3, Save on an untitled document = Save As)** — `main.ts` keeps a module `Set<string>` of the paths `newBlank` created. In the `save-file` handler, when `inPlace` is true and the current path is in that set: take the Save-a-copy route for the destination (GUI: the existing save dialog with `defaultPath` `Untitled.pdf`; smoke/drive: `saveToArg`, see D3b), write with the existing `saveCopy`/safe-write transaction, and on success **rebind** the window's `openPaths` entry to the written file (same `url`, `name` = the new basename) and drop the old path from the set, so the next ⌘S is a plain in-place save of the new file. The reply is the normal ok result with the new `name`. The renderer's `saveInPlace` success path then marks the journal position clean as today and additionally adopts `result.name` as `doc.name` when it differs (title, STATE `doc.name`, status "Saved <name>"). Undo history survives. A cancelled dialog is today's `cancelled` (status "Save cancelled", still dirty, nothing written). Nothing new is ever written into the temp folder by Save. No new reason token, no new IPC channel, no preload change.
- **D3b (drive half of D3)** — drive `{"cmd":"save-in-place","path":"${OUT}/x.pdf"}`: `startDrive` (:1871) sets `saveToArg = pathOf(args.path)` when `path` is given, else clears it to `undefined` for this step. On a titled document `path` is ignored (plain in-place save, today's behaviour). On an untitled document with no `path` the result is `save {ok:false, reason:"cancelled"}`, document still dirty. Check that a stale `saveToArg` from an earlier `save-to` step cannot leak into a later `save-in-place` (that is why the step clears it).
- **D4 (B4)** — `scripts/pdf4all-mcp.mjs` `pdf4all_save`: for a **relative** `path` whose resolved location stays inside `out`, `mkdir(dirname(target), { recursive: true })` before the step. A relative path that escapes `out` (`../x.pdf`) is refused by the tool (`isError true`, text "pdf4all_save: path must stay inside the output folder") without starting a step. Absolute paths are unchanged (a missing folder stays `write-failed`) and get one sentence in `docs/agent.md`. `src/main.ts` save-to and `safe-write.ts` are untouched by D4.
- **D5 (B5)** — `undoEdit` and `redoEdit` call `clearError()` right after their `canUndo`/`canRedo` check, before the request; a failing undo still shows its own error from the `catch`. A no-op undo (nothing to undo, or an open on-page editor closing) clears nothing. Before editing, grep every `tests/drive/*.jsonl` and test file for an `undo`/`redo` step whose expect pins a non-empty `error`; flip each such pin's value in place and list it in the build note (`tests/drive/compare.jsonl` step 8 is the known candidate).
- **D6 (B6, probe first)** — Build the evidence in memory, no new fixture: in the test, open `fixtures/p6/direct3.pdf` with mupdf, move `/Rotate 90` onto the `/Pages` parent (page dictionary has no own `/Rotate`), save to a buffer, feed it to the engine. If `edit-targets` reports any item as editable (`support "candidate"` with `moveable true` or an object placement that accepts `edit-object`), the bug is real: change :1884-1885 to read `/Rotate` through `getInheritable` exactly as `engine.ts` :5632 does (`/UserUnit` is not inheritable; leave it). If the probe shows the scan already refuses, change no source, keep the test as a pin, and say so in the build note.

## 0. Ground rules
progress.md §5 "Contract ground rules" and "Code rules". `mutate`, `saveOptions`/`serializeDocument`/`SAVE_OPTIONS`, `safe-write.ts`, `policy.ts` CSP and `walkEditContent` internals are untouched; refusals never dirty; no new dependency; no new renderer `.js` file; no new reason token; no existing STATE key changes shape; no new engine op (so no `OP_PERMISSION` change); fixtures byte-identical (55 lines) and nothing new under `fixtures/`; never `save-in-place` a `fixtures/` path; never `--no-sandbox`; never kill an Electron process whose command line lacks `--drive=` or a tmp `--user-data-dir` (the human's app may be open); no GUI or keystroke runs (the human may be at the machine); never insert or delete lines in an existing drive script. Build/test/Electron only under the lock in ONE Bash call, run in the background: `( until mkdir ~/Documents/pdf4all/.quad/run.lock 2>/dev/null; do sleep 5; done; trap 'rmdir ~/Documents/pdf4all/.quad/run.lock' EXIT; cd ~/Documents/pdf4all && npm run build && node --test tests/bugfix1.test.mjs )`; never edit while holding it; `npx tsc --noEmit -p tsconfig.json` and `-p tsconfig.preload.json` need no lock and must be clean (`noUnusedLocals` is on). No git: edit files in place, never rewrite a whole existing file, never `Write` a file you did not just read. macOS: no `timeout`, zsh. No timers as budgets; waits are conditions on a file or the lock.
