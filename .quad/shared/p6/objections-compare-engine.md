# Compare objections — engine lens (Opus 5.5, 2026-09-24)
Scope: contract-compare.md D1, D2, §1, §5 memory. Read-only on src/tests/fixtures; no build, no Electron. Probes in `.quad/scratch/compare/objections/engine/`: `lines.mjs`/`perm.mjs` (→ `lines.out`, `perm.out`: lines per page, raw stext bbox vs `Line`, every fixture's `/Encrypt` and permissions), `nocopy.mjs` (→ `nocopy.out`: in-memory no-copy PDF through `createEngine`, `render` with no doc), `mem.mjs` (→ `mem.out`: `/usr/bin/time -l`, large.pdf once vs twice). Map drift: open is engine.ts:4138 (map :4129), close :4263 (:4253), edge throws :1095/:1102 (:1093), parseLines :6059 (:6047), text-all :5229 (:5217), search :1169 (:1175). `shasum -a 256 -c checks/fixtures.sha256`: 9 OK.

**E-1 (blocking) §D1 OP_PERMISSION** — `OP_PERMISSION` is the WRITE gate. Its only reader is `requireMutable` (engine.ts:1590-1601), which refuses `no-document` with no main doc, `read-only` for a signed/certified main doc (:1593), and `"any"` = annotate|edit|form on an encrypted doc (engine-core.ts:262). A builder who follows "`"any"`" and calls `requireMutable` cannot compare `fixtures/p0b/signed-intact.pdf` with `signed-tampered.pdf`. Read ops are listed in `READ_ONLY` in tests/p2-shell.test.mjs:168-173 instead ("never both", :179-180). Dispatch has no doc gate before the switch (engine.ts:4136-4138, worker.ts:32), so each op decides for itself.
amendment: "9.x `compare-open`, `compare-close`, `compare-render` and `compare-text` get NO `OP_PERMISSION` row and never call `requireMutable`. They join `READ_ONLY` in tests/p2-shell.test.mjs:168. `compare-open`/`compare-close`/`compare-render` need no main document. `compare-text` needs both documents: `no-document` without a main doc, `read-only` when `session.locked`."

**E-2 (blocking) §D1, §1.3(c)** — The copy gate is on the wrong document, and its test cannot be built. `compare-open` refuses every encrypted file, so the compare doc always has all permissions (engine-core.ts:261: `!info.encrypted` → true). No fixture lacks copy: perm.out shows copy=true for all 5 encrypted fixtures, and encrypted-noprint is print=false only. The text that needs gating is the MAIN doc's. text-all gates it with `doc.hasPermission("copy")` → `failReason("read-only", …)` (engine.ts:5234). edit-targets (:5266), edit-replace-preview (:5432) and clip-copy (:3341) do the same; render (:4188) and search (:4199) do not gate. `no-copy-permission` is not a `SaveReason` (engine.ts:189), and `failReason` is typed to that union (engine-core.ts:159).
amendment: "9.x `compare-text` refuses `read-only` (detail message '…does not permit copying', as text-all engine.ts:5234) when the MAIN doc's `hasPermission("copy")` is false; STATE `text.refused = "read-only"`. §1.3(c) builds the no-copy main doc in memory: `hello.pdf` `saveToBuffer("encrypt=rc4-128,owner-password=own,user-password=,permissions=-20")`. It opens with no password and `permissions.copy false` (nocopy.out); `compare-text` refuses and `compare-render` works. `encrypted.pdf` (needsPassword true, perm.out) as compare → `encrypted`. No fixture change."

**E-3 (blocking) §5, D1** — The memory gate cannot fail. `fixtures/large.pdf` is 478 062 B (`ls`), and a second copy opened and rendered adds 7 MiB max RSS (mem.out: 123.0 → 132.1 MB). The real risk is a 120 MiB main (`MAX_PDF_BYTES`, limits.ts:8) plus a 120 MiB compare. A 120 MiB open alone already reached Tab 552 MiB against the 572 MiB (= 600 MB decimal) budget (progress.md:134, :221). The only memory readout, `metrics()` → `peakWorkingSetSize` (main.ts:275-277, read by tests/p1-save.test.mjs:467-471), comes from `--smoke --report` edit modes, which have no compare path. The drive harness reports no memory.
amendment: "9.x `compare-open` refuses `too-large` before opening when `bytes.byteLength + session.sourceBytes > MAX_PDF_BYTES`, where `session.sourceBytes` is the main doc (0 when none). `session.compare` carries `sourceBytes`. `open` of a main doc whose bytes plus `session.compare.sourceBytes` exceed `MAX_PDF_BYTES` destroys the compare slot first and replies `compareClosed: true`. §5's measurement is `/usr/bin/time -l node` on `createEngine`: open a 60 MiB padded main, then `compare-open` a 60 MiB padded compare (both from `fixtures/minipdf.py` into /tmp), `compare-render` p0 and `compare-text` p0/p0. Max RSS is recorded next to the 120 MiB single-open figure, plus one `compare-open` over the combined cap → `too-large`."

**E-4 (should) §D2 bbox** — `Line` cannot give the bbox: `Line.y` is the baseline (`item.y`) and the stext `bbox.y` top is dropped (engine.ts:6078-6086). For hello.pdf p0, raw bbox = {x:72,y:53,w:132,h:49} while `Line` = {x:72,y:92,w:132,h:49}, and y−h = 43 ≠ 53 (lines.out).
amendment: "9.x `compare-text` reads its lines from `JSON.parse(structured.asJSON())` blocks→lines itself and does not extend `Line` or `parseLines`. Each entry is `{ text, bbox: [bbox.x, bbox.y, bbox.w, bbox.h] }`: top-left, y down, page pt, the same space as `render`'s `Line.x`. §1.3(b) is exact: A=hello, B=nav p0 → `{same:0, removed:[{text:'PDF4All',bbox:[72,53,132,49]}], added:[{text:'one',bbox:[72,66,40,32]}], moved:0}`."

**E-5 (should) §1.3(a)** — Test (a) passes if `compare-render` renders `session.doc` by mistake, because main and compare are both nav.pdf.
amendment: "9.x §1.3(a) opens hello.pdf (1 page) as main and compare-opens nav.pdf (3 pages). `compare-render {page:2, scale:1}` is ok with `lines[0].text` of nav p2, and `compare-render {page:0}` has `lines[0].text === 'one'` while the main `render` p0 has 'PDF4All'. Then the p0-vs-p0 identical case runs with nav.pdf as both."

**E-6 (should) §1.1 teardown** — There is no `closeSession` (grep: none in src/). Worker teardown is `worker.terminate()` in `workerFailed` (renderer.ts:851), which frees the whole WASM heap and already clears the clipboard mirror (`clipboardInfo = null`, :852).
amendment: "9.x No engine teardown is added. `createSession` (engine.ts:6015-6018) initialises `compare: null`. `workerFailed` (renderer.ts:852) resets the renderer's compare state next to `clipboardInfo = null`."

**E-7 (should) §D1 replace** — "closes a previous compare doc first" contradicts the clipboard pattern the contract cites, which keeps the old slot on refusal and destroys it only after the new one is built (engine.ts:3334-3336, :3486-3488). A builder has to guess which one.
amendment: "9.x `compare-open` checks size (E-3), then opens and `detect`s the new doc as insert-pages does (`mupdf.Document.openDocument` + `disableJS`, engine.ts:5130-5143; not the journaling `openDocument` helper :993-1010). On a refusal the old slot is kept. On success the new doc is stored, then the previous one is destroyed. The size check counts only the main doc, so the brief overlap is ≤ MAX_PDF_BYTES."

**E-8 (should) §D1 tokens** — `no-compare-document` is not in `SaveReason` (engine.ts:189-193). With `noEmitOnError` a typed `failReason("no-compare-document", …)` fails to build. The edge refusals are untagged Errors (engine.ts:1095, :1102, scale :1081), so the reply has `error` and no `reason` (dispatch catch :5980-5986).
amendment: "9.x Add `\"no-compare-document\"` to `SaveReason` (engine.ts:189). `compare-open` replies `{ok, name, pageCount, pages: pageSizes(doc)}` (:1020) so the renderer clamps its one scale to `min(MAX_SCALE, 4096/max edge of A and B)` before it asks. A render refusal has no reason token; the renderer matches `ok:false` only."

**E-9 (should) §1.2 LCS cap** — No fixture page exceeds 13 lines (perm.out: form-xfa p0), so O(n·m) is free here. A real page with 5 000 spans gives a 25 M-cell table (100 MB as Uint32) inside the 600 MB worker.
amendment: "9.x `compare-text` refuses `too-many` when either side has more than 2 000 lines (a 4 M-cell Uint16/Uint32 table ≤ 16 MiB); `ponytail:` Hirschberg/Myers if that ceiling bites."

**E-10 (nit) §D2** — `preserve-spans` (engine.ts:1106) keeps spans of different fonts as separate stext lines, so a one-word font change shows as extra lines. The Help text should say "lines (text runs)".
amendment: "9.x The diff unit is the stext line under `preserve-spans`; a font change inside a line can split it."

## checkedFine
- `renderPage(doc, pageIndex, scale)` is doc-parameterised (engine.ts:1079), with MAX_PIXEL_EDGE 4096 at :74 and `toStructuredText("preserve-spans")` at :1106, so `compare-render` is a thin wrapper. `render` with no doc → `{ok:false,error:"render: no document open"}` (nocopy.out).
- `open` destroys only `previous` = the old `session.doc` (engine.ts:4185), and `close` (:4263-4281) touches no clipboard. A `compare` slot survives both if it is left out of those blocks, which is the same as the clipboard comment at :796.
- Clipboard shape `session.clipboard = {doc: scratch, items}` at :3486-3488, with a `new mupdf.PDFDocument()` scratch at :3362.
- nav.pdf has 3 pages, hello.pdf p0 has 1 line 'PDF4All', nav p0 has 1 line 'one', and large.pdf has 500 pages with at most 6 lines (lines.out). No `Line.text` has trailing or double spaces on these fixtures. encrypted.pdf opens with needsPassword=true (perm.out).
- The coverage test regex (tests/p2-shell.test.mjs:163) picks up the new `op:"compare-*"` strings from renderer.ts, so the unlisted-op case is caught. No test deep-equals Session keys.

## buildRisks
- A compare-text reply for pageA reads the LIVE main doc (edits included). Replies need `revision` and a compare generation counter so the renderer drops stale replies after an `open` or `compare-open`.
- The renderer must transfer the compare bytes (the insert-pages transfer at renderer.ts:7226 (map said :7212, drift)). A retained JS copy counts against the Tab budget.
- Never call `requireMutable`, `mutate` or `beginOperation` in compare ops. §1.3(e) should also assert `canUndo` unchanged.
