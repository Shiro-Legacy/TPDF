## Findings, by severity

**F1 — High — FIXED. A `sign-draw` over 4096 characters hangs the step and kills the drive/agent session.** `src/preload.cts:97` (pre-fix) dropped any `edit-request` whose `contents` exceeded `MAX_NOTE_CHARS`; no STATE line follows, so `startDrive` (`src/main.ts` ~1931) waits 60 s, records `step timeout` and calls `finish` — the whole drive (or live MCP session) ends. A realistic drawing (600 points ≈ 15 000 chars) is far over 4096, so the "ceiling" made `sign-draw` unusable for real signatures. Proof: review drive test, red before (`expected: 9, actual: 2` steps — the run died at the first big `sign-draw`). Fix: `src/preload.cts:27,99-101` — `sign-draw` only may carry up to 4 MiB (`MAX_SIGN_DRAW_CHARS`, the store's own read cap); an over-cap `sign-draw` is forwarded with `""` and refused at `src/renderer/renderer.ts:4232` ("sign-draw: contents are empty or larger than 4 MiB"). Every other op keeps 4096. To make a store-sized drawing feasible, `drawPad` no longer repaints a closed pad per point (`renderer.ts:4071`, was O(n²)), and `padBounds` uses a loop instead of `Math.min(...xs)` (`renderer.ts:4064`; spreading ≥ ~120 000 arguments throws `RangeError` in V8 — probed). Test: `(review) drive: …` steps 2–4 (131 072-point drawing saved, 600-point drawing saved, 4.2 MB contents refused with the error, saved drawing kept). Docs updated (`docs/agent.md` fill recipe, `design-agent-drive.md` §draw-signature).

**F2 — Medium — FIXED. The stroke points reach the drive report and every `STEP` line.** `src/main.ts` `startDrive` copies `args` (including `contents`) into the step record; contract §0 says the points never reach "a log, a report or STATE". The implementer's test only checked `state`. Proof: `probe-small-pre.json` — every `sign-draw` step carries the strokes object. Fix: `src/main.ts:1911` sets `step.contents = '[redacted]'` for `sign-draw` (the same token `encrypt`/`sign` use). Test: the review drive asserts `contents === '[redacted]'` on every `sign-draw` step (red before: the run never got that far; the probe shows the object).

**F3 — Medium — FIXED. `sign-draw {clear:true, strokes:…}` silently deletes the saved signature.** Contract D7: "both keys → error, nothing saved". `driveSignDraw` checked `clear === true` first and removed the drawing with `error ""`. Proof: `probe-small-pre.json` step 2: `error ""`, `saved false`. Fix: `renderer.ts:4234` refuses "sign-draw: give strokes or clear, not both" before anything. Test: review drive step 5.

**F4 — Low — FIXED. On a page under 200 × 60 pt the default placement squashes the signature.** `placeSignature` fitted 200 × 60 only; `left` clamps to 0 and `at()` clamps every point to the page edge, so the drawing is distorted. Proof: `probe-small-pre.json` step 4 — a 300 × 100 drawing on a 144 pt page became 144 × 60 (aspect 2.4, should be 3). Fix: `renderer.ts:4148` — the default scale is also bounded by the page width/height (the `width` path already was). Test: review drive step 6 (inside the page, aspect 3 ± 0.02, width 144).

**F5 — Low — FIXED. Store file hygiene (`src/sign/drawn.ts`).** (a) `writeFileSync(tmp, …, {mode: 0o600})` only applies the mode on create: a stale `${path}.${pid}.tmp` with 0644 made the saved file 0644 (test red: `expected 384, actual 420`). (b) A failed write/rename left the temp file behind (probe pre-fix: `["blocked.76812.tmp"]`). (c) `get()` on a FIFO at the path blocked the main process forever in `readFileSync` (probe pre-fix: `BLOCKED (ETIMEDOUT)`); a device file would read unbounded since `statSync().size` is 0. Fix: `drawn.ts:44` regular files only; `drawn.ts:55-63` remove a stale temp, create with `flag: 'wx'`, remove the temp and rethrow on failure. Tests: `(review) the store: …` ×3 (post-fix probe: `[]`, `null`). Threat model is same-user local, hence Low.

**L1 — Medium — LEFT (contract decision). A store-valid maximum drawing freezes the engine for minutes.** D3 allows 64 × 2048 = 131 072 points. mupdf's `setInkList` is quadratic: measured (`probe-size.mjs`, pre-fix build) 1.07 s at 4 096 points, 16.9 s at 16 384 (plain Ink identical — the engine's `MAX_INK_*` caps already allowed this). Extrapolated ~18 min per place/move/resize at 131 072, all in the worker. In addition `engine.ts:4984` spreads `Math.max(...xs)`, which throws `RangeError` at ≳120 000 points (that refusal is actually the faster outcome, so I left it). Suggested fix (needs a decision): a total-points cap in `checkDrawnSignature` and the pad (e.g. 4 096; a real signature is a few hundred to ~2 000 points).

**L2 — Low — LEFT.** `sign-place` (and `fill-text`, pre-existing) with no document open returns with `error ""` (`renderer.ts` `driveSignPlace`: `if (!value || !doc) return`). Same as the fill-anywhere precedent; not listed in D7's errors.

**L3 — Low — LEFT.** Side handles e/w use the free path of `gestureRect` with `min = 24·h/w`, so the ghost can show a width under 24 pt that the engine then clamps to 24: the commit differs from the ghost. Corner handles are right.

**L4 — Low — LEFT.** `annot-move` without `width` on a drawn-signature Ink wider/taller than the page (only a foreign Ink with that `/Subj`, or one placed before F4) keeps the size and clamps each point, which squashes it.

**L5 — Note — LEFT.** The pad handles `pointercancel` but not `lostpointercapture`; a lost capture leaves `padStroke` open until the next `pointerup`/`pointerdown` (the next `padBegin` discards it). No crash, no leak across openings (`openSigpad` and the dialog's `close` both clear).

Checked and found right: refusals in `annot-add`/`annot-move` happen before `mutate` (dirty/revision unchanged — tests (a)); path without `signature` unchanged except the label expression (same value); the no-op rule (`noop: true`, no journal); `annotRect` = the listed rect (the test's "same rect again → noop" passes); `undo`/`redo` restore ink list and border width (new test); `RectGesture.keepAspect` leaves every other caller's expression identical (`(undefined===true || L && !shift) && !within` ≡ old); armed placement: `layerLive()` is false while armed so `#hit-layer:not(.live) .hit-target {pointer-events:none}` lets the click reach the page, and `cancelPendingTools` (mode change/other tool) and document reset disarm; an armed `click` over a text box places the signature and leaves the box (new drive steps 7–9); every successful place/move/resize/delete calls `noteFilled()`, a noop does not; `smoke` includes `--drive`, so the store is memory-only in driven sessions; the IPC handlers are `isTrustedOpen`-guarded and validate with `checkDrawnSignature` (structured clone strips prototypes/getters; arrays are length-checked before iteration); no `console` logging of points; STATE carries counts only; `/T` and `/Contents` absent (tests a and c); Help text inside the existing Fill cell; new ids in `REQUIRED_IDS`; no existing drive script line touched; `fill` was not deep-equal-pinned anywhere; files touched are inside §1.
