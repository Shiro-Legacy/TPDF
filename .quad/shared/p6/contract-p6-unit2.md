## 1. Fields: drag and resize (renderer + existing `field-props {rect}`)
1.1 In **Fill forms** mode (and read/annotate, same targets), a hovered or focused `.hit-target` shows 8 resize handles (`.hit-handle.n/ne/e/se/s/sw/w/nw`, 8×8 px, `cursor` per side) and one **move grip** (`.hit-grip`, 14×14 px, just outside the top-left corner, `cursor: move`). Body click = fill (U1). Grip drag = move; handle drag = resize (opposite edge anchored). Signature and read-only fields: grip + handles still shown; document `read-only`/no-`edit` permission → no grip/handles, tooltip states why.
1.2 Drag = pointerdown on grip/handle + pointermove ≥ 3 px + pointerup. Live preview moves the target box only (no engine call). Pointerup sends **one** `field-props { page, widgetId, rect }` in page points (y down, same space as U6). Rect clamped to the page box; min size 8×8 pt. Esc during drag cancels (box snaps back, no op). Result: paint, hit layer rebuilt, focus stays on the same widget.
1.3 Keyboard: with a target focused, `⌥`+arrow nudges 1 pt, `⌥⇧`+arrow 10 pt (one op per keypress; radio ArrowLeft/Right without ⌥ still selects). `⌥⌘`+arrow resizes width/height by 1 pt. (Plain arrows are not taken: they scroll/select as in U1.)
1.4 Radio kids move individually (their own widget rect). Multi-select is out of scope.
1.5 STATE: `direct.gesture: null | {kind:"move"|"resize", handle, targetId|name, rect}` during a drag; `fields.values` unchanged; `fields.defs[..].rect` reflects the new rect after the op (existing `defs` state).

## 2. Text runs: drag and resize (engine `edit-text` gains `move` and `size`)
2.1 `edit-text` request gains optional `move: {dx, dy}` (page points, y **up**, PDF space) and `size` (new `Tf` size, 1–400 pt, 0.5 pt steps). `text` stays optional-with-default (unchanged text allowed when `move`/`size` is present). One op writes all three.
2.2 **Move rule (proven):** the run's show operator gets `tx ty Td` before it and `-tx -ty Td` after it, `tx ty` = `(dx, dy)` mapped through the inverse linear part of (Tm × CTM) at the operator (must be proven from the carried state: `Tm` known, CTM rectilinear and invertible; else refuse `not-candidate` with reason `matrix`). The trailing `Td` restores `Tlm` exactly, so later lines are unaffected. Refuse `tail-would-move` when `tailFollows` (the tail's advance would be lost). Refuse `outside-page` when the moved bounds leave the page clip box.
2.3 **Size rule:** `size Tf` (same font name) before the show, `old Tf` after. The P3b growth rule applies with the new width (`growthLimit`, tail shift); refuse `overflow {oldWidth,newWidth,limit}` as today. Leading is not touched (a taller run may touch the line above; that is the user's choice, Acrobat behaves the same).
2.4 `edit-targets` reply gains per text target: `fontSize` (Tf × text-matrix scale, page pt) and `moveable: boolean` (2.2 provable and no tail). Rescan after the write re-issues bounds.
2.5 Renderer (Edit text mode): a hovered/focused `.text-target` shows the same grip + handles as 1.1 (handles only e/w/se/sw/ne/nw for runs: horizontal drag = no-op for a single run — width is text-determined — so **corner drag = font size** (size' = size × newHeight/oldHeight, 0.5 pt steps, live preview scales the editor font), **e/w handles hidden for runs**). Grip drag = move (live preview moves the target box; pointerup sends `edit-text {move}`). Esc cancels. Not moveable → grip hidden, tooltip "This text cannot be moved (reason)".
2.6 **Font cap lifted:** the inline editor for a run uses `font-size = fontSize × zoom` px, min 10 px, **max 400 px** (100+ pt at any zoom). Field editors: `clamp(10, rect.h × zoom × 0.6, 400)`. `#content-add-size` already allows 4–144 pt; raise `max` to 400 in both `index.html` and the engine check (`request.size > 144` → 400).

## 3. Paragraph reflow (engine `edit-paragraph`; renderer paragraph editor)
3.1 **Paragraph rule (scan, post-pass):** ≥ 2 candidate text targets on one page that are (a) consecutive in stream order inside one stream element and one `BT…ET`, (b) the only show operator on their line (no `tailFollows`, no show before them since the previous positioning op), (c) same font resource name and `Tf` size (±0.1), same `Tc`/`Tw`/`Tz`, (d) left edges aligned (±1 pt), (e) baselines strictly descending with uniform leading `L` (±0.5 pt), (f) positioned only by `Td`/`TD`/`T*` between the first and last show (no `Tm`, `Tf`, `Tc`, `Tw`, `Tz`, `TL` change, no `q/Q`, no marked-content ops between them), (g) simple base-14/WinAnsi-proven font (the same set `edit-text` writes today), (h) ≤ 200 lines, ≤ `MAX_EDIT_TEXT_CHARS` joined. Everything outside the rule is not a paragraph; its runs stay single-run targets.
3.2 `edit-targets` reply gains `paragraphs: [{ paragraphId, targetIds, bounds, left, width, leading, fontSize, lines, kerned, tagged }]`. `width` = max right edge − left edge of the lines. `tagged` = any line has `mcid`/`actualText`.
3.3 `edit-paragraph { page, paragraphId, generation, revision, text, width?, move?, size?, leading? }`. `text` = the new flow; `\n` = hard break; other whitespace runs collapse to one space. `width` (default: the paragraph's) is the wrap width; `move`/`size` as §2 (size also scales `leading` proportionally unless `leading` is given).
3.4 **Wrap rule:** greedy by words, advance measured with the same formula as `edit-text` (font widths × size, `Tc`, `Tw`, `Tz`); a word wider than `width` → refuse `word-too-wide {word, width}`. Result lines N′.
3.5 **Span rewrite (proven):** the bytes from the first line's `opStart` to the last line's `opEnd` are replaced by `[tx ty Td] (l1) Tj 0 -L′ Td (l2) Tj … (lN′) Tj  ex ey Td` where the final `Td` restores `Tlm` to what the original span left it: `ex = -tx`, `ey = -(N-1)·L - ty + (N′-1)·L′` (text-space units, via the same inverse mapping as §2.2). `TJ` lines become `Tj` (kerning dropped; reply `kerned: true`). COW (U1b) applies to the whole span's stream element. `size` → `size Tf` before and `old Tf` after the span.
3.6 **Growth limit (vertical):** the new last baseline minus descent must stay ≥ the top of the nearest text target or placement below the paragraph that overlaps it horizontally, + 1 pt; else the page's text bottom margin (min bottom edge of every text target on the page); else the page clip box. Refuse `overflow { lines, maxLines }`. Horizontal: every wrapped line ≤ `width`, and `left + width` ≤ page clip → else `outside-page`.
3.7 **Tagged paragraphs:** lines with `mcid`/`actualText` may be rewritten (their own `/ActualText` rewritten as U2 does per line); N′ > N on a tagged paragraph → refuse `tagged-growth`. Blanked lines (N′ < N) are written as `() Tj` with their positioning kept? **No** — the span rewrite drops them entirely (the trailing `Td` accounts for the difference).
3.8 Renderer (Edit text mode): hovering a run that belongs to a paragraph highlights the whole paragraph (`.text-target.paragraph` + `.para-outline`). **Click** opens a paragraph editor (`textarea.inline-editor.paragraph`, over `bounds`, font = `fontSize × zoom`, `line-height = leading × zoom`, `width` = paragraph width × zoom, lines joined with `\n`? **No**: shown as one flow with soft wrapping (`white-space: pre-wrap`), lines joined by a single space; Enter = hard break, ⌘Enter/Tab/blur = commit, Esc = cancel). **⌥-click** opens the single-run editor (U1). Commit sends `edit-paragraph`. Grip = move; **e/w handles = width** (re-wrap live preview by the textarea width; pointerup commits with `width`); corner = font size (leading scales). Same Esc/unchanged/undo rules as U1 (`directUnchanged()` covers text, width, move, size).
3.9 Text tab: paragraphs listed as one row ("Paragraph, 4 lines, Helvetica 11") above their runs; edit opens the same editor.
3.10 Drive: `click` gains `alt: true` (⌥-click). New cmds `drag { page, x, y, dx, dy }` (pointer sequence from (x,y) by (dx,dy) page pt, via `elementFromPoint` like U1 click) and `handle { page, x, y, handle: "nw"|…|"grip", dx, dy }` (finds the handle of the target under (x,y)). Both as real pointer events; never a direct engine call. STATE `edit.paragraphs` count; `direct.active.kind: "paragraph"` with `paragraphId`, `lines`, `width`.

## 9. Amendments 2026-09-23 (fable51, from `objections-p6-unit2-opus55.md` — all 17 accepted; override §1–§6 where they differ; field names unchanged)
1. **`move {dx,dy}` is in the space `bounds` uses:** page pt, y down, rotated page view. Engine maps through the inverse linear part of pageTransform × CTM × Tm; any invertible matrix is proven (no `rectilinear`, no `rotated` refusal). Zero determinant / non-numeric operand / unknown Form `/Matrix` → `not-candidate` reason `matrix`. (ds2: send deltas in the same space as `bounds`.)
2. **`size` is in page pt, the unit of the reply's `fontSize`.** Engine writes `Tf = size / scale` (scale = length of the y column of the linear part of Tm × CTM × pageTransform; `fontSize` uses the same scale). 1–400 and 0.5 pt snapping are renderer concerns. (ds2.)
3. **`moveable` = candidate ∧ first show since the last positioning op ∧ ¬tailFollows ∧ matrix proven.** A tail run refuses `not-candidate` reason `tail`; it may still be resized.
4. Scanner gains the linear matrix state (last `Tm` in the BT × `cm` products × Form `/Matrix` chain × page transform). Translation not tracked.
5. The trailing `Td` is the textual negation of the exact `editNumber` strings written in the leading `Td`.
6. New width at a new size comes from `editAdvance` at that size (`Tc`/`Tw` unscaled), never old width × ratio; `outside-page` uses the resized bounds.
7. **§3.3 `width`, `leading`, `move` are page pt, y down** (the `bounds` space); engine converts to text space.
8. Span rewrite starts at the first line's `operandStart`.
9. `TD` sets TL: track TL from `TL`/`TD`; when the span's final TL differs from the TL on entry, append `TL_final TL` after the trailing `Td`.
10. §3.1(d)/(e) proven from operands: positioning ops between consecutive shows compose to exactly `(0, −L)` in text space. Stext supplies only `bounds`/`width`.
11. §3.1(f) is a whitelist: the span holds only `Tj`/`TJ` shows and `Td`/`TD`/`T*`. Anything else → not a paragraph.
12. Tags: mcid-only paragraphs are paragraphs and **may grow**; any `/ActualText` (span or matching StructElem) → not a paragraph (single-run editing only). `tagged-growth` dropped; `tagged` stays informational.
13. Growth limit: new box (left..left+width′ × vertical extent) must clear every obstacle (text target or placement) by 1 pt, else the clip box. New bottom = old last-line bottom + (N′−1)·L′ − (N−1)·L, scaled for size. No descent metrics. Refuse `overflow {lines, maxLines}` / `outside-page`.
14. Editable combos: mupdf `setChoiceValue`/`setTextValue` + `update()` proven; engine deletes `/I` explicitly; drive uses `field-props {edit:true}` on form2; no new combo fixture.
15. No-op writes (unchanged text, zero move, no size/width/leading change) return ok with no journal op.
16. `paragraphId = "para." + first line's targetId`; freshness = generation, revision and identical `targetIds` on rescan, else `stale-target`.
17. Paragraph lines stay in `targets`; each line target gains `paragraphId?` (additive). (ds2: use it instead of inverting `paragraphs[].targetIds`.)
