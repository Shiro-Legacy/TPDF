1. **Medium, FIXED by reviewer** — `src/renderer/content-edit.ts:1846` (D2). On a rotated page the app-written run's growth limit became the view's right edge (`getBounds()[2]` = 792 on a /Rotate 90 letter page), but the run's advance goes down the view (along y), so the x-axis check no longer bounds it. Repro (`.quad/scratch/bugfix1-review/probe-b2.mjs`): blank page → `text-add "Twin"` → `page-rotate 90` → `edit-text "Twin "+48×W` returned ok; the saved line bbox ran to y 621.8 on a 612 pt-tall view, and the last glyphs were clipped. Before the build this was refused (limit = the run's own right edge). That breaks D2's "a grow that would cross the page edge still refuses `overflow`". Fix: `pageBoxRight = state.geometryBlocked ? pageRight : page.getBounds()[2]`, so rotated or UserUnit pages keep the old text-margin rule. Test `(f) B2 review: …rotated after text-add cannot grow off the page` fails on the build's code (`.quad/scratch/bugfix1-review/f-red.log`) and passes after the fix.
2. **Low, not fixed (reasoned)** — `src/renderer/engine.ts:3123` (D1). The fallback is taken only when the cached reference doesn't resolve to `/Type /Font`. If mupdf ever reused the freed object number for a *different* font dictionary, the cache would hand back the wrong font and the check would accept it. In every sequence I probed (add→undo→redo→add; add→undo→add→undo→add; Helvetica→undo→Times→Helvetica; Helvetica→undo→Courier→Times→Helvetica; add→save→add; stamp→undo→Times→stamp), mupdf never reused the number, and every `/PDF4AllF*` resolved to the right `/BaseFont`. Proposed hardening if wanted: also require `/BaseFont` = `name`.

Agents cannot make symlinks through MCP. Proposed: `realpath` the deepest existing ancestor and compare it with `realpath(out)`.
