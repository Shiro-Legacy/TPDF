## checkedFine
- (1) The simple-placement rule holds for both the original and the copy. direct3: Im2 and Fm1 duplicated plus Im1 moved in one op; all five are candidates with `move+resize+delete(+replace)` and the right boxes, after the op and after a reopen via engine `save` (`SAVE_OPTIONS "incremental=no,garbage=yes"`, engine.ts:163). Cow: same result on edit-objects.pdf p1 after `editPrivatise` (sim.mjs `eo_p1_after`/`eo_p1_reopen`). The copy's trailing byte is the original's post-`Q` separator (`editNextQEnd`, content-edit.ts:572-573).
- (2) `editSplice` would accept an insert at `qEnd` plus a delete `[qStart,qEnd)` of the same placement: the insert sorts first, and `end == qEnd <= previousStart`. So the distinct-id check is the only guard, and it is enough, because one placement is one `targetId`. Equal-start collisions between different placements are impossible: `qEnd` is followed by whitespace or a delimiter and the next block starts at `q`.
- (3) Spans cannot nest or overlap. Object candidates need `depth 0` (content-edit.ts:2327, 2359) and `savedStates.length === 1`, and `Do` sets `clean = false` (2521-2522), so each block holds exactly one `Do`. A nested Form is `unsupported` (targets-streams `Fm1 c1/Fm2@99`).
- (4) The no-op rule mirrors engine.ts:4720-4724. With everything dropped, no `mutate` runs, so there is no dirty flag and no revision bump.
- (5) Refusal shape: `dispatch` flattens `detail` and `extra` into the reply (engine.ts:5036-5045), so `targetId` arrives top-level. `refusalDetail` reads `reply.detail` (renderer.ts:4752-4755).
- (6) `MAX_EDIT_TARGETS` is importable from `build/renderer/engine.js` (engine.ts:5291).
- (7) `DEFAULT_EDIT` passes the p2-shell coverage and doubled checks. `requireMutable` falls back to `"edit"` (engine.ts:1523).
- (8) One `mutate` is one journal op (engine.ts:1718-1739). sim.mjs: one `undo` restores all items, and a throw calls `abandonOperation`.
- (9) Two-element `/Contents` through the engine (sim2.mjs): paths `Im1:c0`, `Im2:c1`, `Fm1:c1`. A move across both elements lands in one op, survives reopen, and one undo restores it. Delete Im2 + duplicate Fm1 in `c1` both land.
- (10) p6-direct3:93 and p3-objects:130-136 are listed. p3-objects:177 `['replace']` stays. p6-drive3:97 uses `includes`. No drive `.jsonl` pins `ops` (the only miss is E1).
- `/Contents [a a]` (one stream twice): each element counts as shared (content-edit.ts:1703-1705), so privatising once per element gives each its own copy and the spans hold. A second `editPrivatise` skips the inherited-resources copy (content-edit.ts:990).

## buildRisks
- `duplicate` must take the `editObjectBox` branch of `move`/`resize` (engine.ts:4713) but must NOT run the same-`cm` no-op check.
- `editObjectBox` and `resolveEditTarget` throw without `targetId`. Wrap each per-item step and rethrow `failEditObject(detail, msg, { targetId, ...(reason ? { reason } : {}) })`. Map a resolve error to `stale-target`/`too-large` as engine.ts:4690-4698 does; a stale revision throws reason `invalid` and must still map to `stale-target`.
- Per element: privatise once, read the bytes once, then one `editSplice` with every edit, all spans from the one pre-write scan. Never one write per item; a second write would shift the recorded spans.
- The duplicate text is `"\n" + bytes[qStart,cmStart) + editPlacementMatrix(box, rect) + bytes[cmEnd,qEnd)`, read from the post-privatise bytes (byte-identical), with `start = end = qEnd`.
- Group by `record.path` and parse it as engine.ts:4727-4729. Items on non-`c<n>` paths are already refused by the candidate/ops checks.
- The shape check must reject `resize`, `replace`, unknown actions, missing or empty `targetId`, and a non-array `items`. The cap goes first (E8).
- `count` excludes items dropped as no-ops.
