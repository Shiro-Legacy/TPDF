## 1. Images and Forms on the page (Edit text mode)
1.1 **Engine — coordinates (additive).** `edit-targets` reply gains `transform: [a,b,c,d,e,f]` = `page.getTransform()` of the scanned page (PDF user space, y up → page view space, y down, the space text `bounds`, `edit-text move` and `text-add point` already use). `EditTarget.bounds` and `placement.box` stay in PDF user space (tests/p3-objects.test.mjs:147-148 pins that). Renderer converts with two pure exported helpers in `renderer.ts` next to `editorBox`: `viewBox(box, m)` (map the 4 corners, min/max → y-down rect) and `pdfBox(rect, m)` (exact inverse of the 2×2 linear part + translation; throws on zero determinant). Both unit-tested in `tests/p6-direct.test.mjs` with the child-process harness, including a non-zero MediaBox origin and the identity-with-flip case `[1,0,0,-1,0,792]`.
1.2 **Engine — no-op guard.** `edit-object` with `action: move|resize` whose new `cm` operand text equals the current one returns `{ok:true, noop:true, ...editState}` with no journal op (U2 §9.15 parity). Test: same-box move → `revision` unchanged, `dirty` unchanged (tests/p3-objects.test.mjs:377-381 pins the old behaviour — update that assertion; it is the engine owner's file for this unit, additive edits only elsewhere).
1.3 **Engine — obstacle space fix.** `content-edit.ts:1582` (`editAttachGrowthLimits`) and `content-edit.ts:2708` (paragraph obstacle test) compare y-down text bounds with y-up `placement.box`. Map `placement.box` through the page transform before comparing. Test in `tests/p6-direct3.test.mjs`: on `direct3.pdf` page 0 the paragraph's growth limit is bounded by the image *below* it (y-down), and `edit-paragraph` with N′ lines that would overlap the image refuses `overflow` while N′ that stops 1 pt above it succeeds; before the fix the mirrored box gives the opposite answer (state the numbers in the test).
1.4 **Renderer — targets.** In `paintHits` edit block, **before** the text loop (so text targets stay above in DOM order), paint one `<button class="hit-target object-target [image|form]" data-target-id>` per `contentScan.items` item with `kind !== 'text'`, `support === 'candidate'`, `bounds` non-null and `objectOps` including `move`, placed at `viewBox(item.placement.box, contentScan.transform)`. `aria-label` = `objectRowLabel(item)`, `title` = `objectRowState(item)`. **Page-cover rule:** an object whose view box covers ≥ 90 % of the page area gets no on-page target (panel only; it would swallow every click) — Help says so. Replace-only objects (`bounds` null) get no target (panel only).
1.5 **Renderer — gestures.** Generalise `addFieldHandles`/`startFieldGesture` with a commit callback (`(rect) => Promise<boolean>`; the field call site keeps `field-props` → `refreshFields`) and widen `DirectGesture.targetId` to `number | string`. Object targets get the grip + 8 handles when `canEdit()`. **Corner handles keep the aspect ratio for images** (Shift = free); edge handles stretch freely; Forms resize freely (Acrobat: images scale proportionally from a corner). Pointerup sends **one** `edit-object { action: 'move' | 'resize', box: pdfBox(rect, transform) }` (`move` when width and height are within 0.05 pt of the original, else `resize`; same rule as `submitObjectEdit`), then `refreshContentTargets(true)` and `paintHits`. Min size 1 pt, max `MAX_IMAGE_PAGE_POINTS`; rect clamped to the page view box. Esc during the drag cancels (box snaps back, no request). A refusal snaps the box back and shows in `#error` (U2 fix 1 rule).
1.6 **Renderer — keys and clicks.** Click (no drag) on an object target: focus it and select its Inspector row (`activateContentRow`); no request (1.2 guards the engine anyway). Focused object: `⌥`+arrow nudges 1 pt, `⌥⇧`+arrow 10 pt, `⌥⌘`+arrow resizes width/height 1 pt (one op each); **Delete/Backspace** → `edit-object { action: 'delete' }` when `objectOps` has `delete` (one op, undoable; announce "Image deleted"); **Enter or double-click** on an image with `replace` in `objectOps` → `pickOneImage()` → `edit-object { action: 'replace', image }` (drive: `images` dialog-answer on the `key` line). Plain arrows are not taken.
1.7 **STATE.** `direct.objects: n` (painted object targets on the shown page; `direct.targets` unchanged), `direct.active` for a focused object target `{ kind: 'object', targetId, page, rect (y-down), box, ops }`, `direct.gesture.targetId` may be a string, `content.edited` as today.

## 2. Add text where you click (Edit text mode)
2.1 A click on the page in Edit text mode with no `.hit-target` under the pointer, no armed tool (`layerLive()`), no open inline editor, a collapsed selection (`getSelection().isCollapsed`), and `canEdit()` opens an **add-text editor**: `textarea.inline-editor.text-inline-editor.add-text` whose top-left is the click point (page pt, y down). Font, size and colour come from the Inspector controls `#content-add-font`, `#content-add-size`, `#content-add-color` (the panel is the mirror; defaults Helvetica 12 black). Editor box: `[x, y, x + max(8·size, 48), y + 1.2·size]` px at `shownZoom`, auto-grows with the draft (reuse `growParagraphEditor`), font `size × shownZoom` px (cap 400). Clicks inside `#hit-layer` targets never reach this path (they bubble to `#page` today — guard with `hitLayer.contains(target)`).
2.2 Keys: Enter = newline, ⌘Enter / Tab / blur = commit, Esc = cancel. Empty or whitespace-only draft → close, no request.
2.3 Commit sends **one** `text-add { page, point: [x, y + 0.8·size], text, font, size, color }` (baseline ≈ top + 0.8·size for base-14). On `ok`: rescan, focus the new run's text target (`content.lastAdd.targetId`), announce "Text added". On a refusal (`unsupported-encoding` with `missing`, `unbalanced-content`, `too-large`): show it in `#error`, keep the editor open with the draft. A page with `/Rotate ≠ 0` or `UserUnit ≠ 1` shows `unsupported-transform` in `#error` at click time and opens no editor (STATE `pages.rotate` is known).
2.4 `directActive.kind` gains `'add'` with `point`; `dropDirect`/`finishDirect`/`directUnchanged` handle it (empty draft = unchanged). `submitContentAdd` (panel path) and the click path share one `addTextAt(page, point, text)`.
2.5 STATE: `direct.active: { kind: 'add', page, point, fontSize, box, draft }`.

## 3. Redaction marks on the page (Redact mode)

3.2 **Renderer.** `layerLive()` includes `redact` mode when no tool is armed (`redactDrag`/`#redact-area` off). Click = focus + select the Annotations row. **Delete/Backspace** → existing `deleteNote(annotId)` (`annot-delete` accepts Redact). `⌥`-arrow nudge / `⌥⇧` 10 pt / `⌥⌘` resize as §1.6. Drive: `annot { action: 'delete', index }` on a Redact row is allowed (today `driveAnnot` refuses `not-editable`).
3.3 STATE: `redact.rects: [{ id, rect, search: boolean }]` for the shown page (new key; existing `redact.*` unchanged), `direct.marks: n`, `direct.active: { kind: 'redact', annotId, page, rect, box }` when a mark is focused.
