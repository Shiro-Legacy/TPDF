**Problem (progress.md §10 "Queued units" 2):** a Firefox Print → Save-as-PDF file (producer "Quartz PDFContext") shows 0 edit targets. Every glyph is its own block:
`q 277.2148 81 5.785156 6 re W n /Cs1 cs 0 0 0 sc q 7.974999 0 0 7.974999 277.215 81.20605 cm BT 1 0 0 1 0 0 Tm /TT2 1 Tf (!) Tj ET Q Q`
Fonts are symbolic simple TrueType subsets (no `/Encoding`, `/Flags 4`, `/ToUnicode`, `/FirstChar 33`, codes in first-use order, **no space glyph** — a word gap is only a larger x step).

**Probe results (fable51, `.quad/scratch/print-edit/probe{1,2,3,4}.mjs`, on the human's 2-page file; counts only):**
- P1 The scan throws `too-large: more than 512 targets on this page` (`content-edit.ts` :2020) — 1245 / 1218 `Tj` a page. That is the whole reason for "0 targets".
- P2 With the two caps lifted in a scratch copy the existing walker already makes 1207 of 1245 per-glyph records `candidate` through the Coded path (`editResolveCoded` :1722); the other 38 are `ambiguous-text-association` (doubled narrow letters "ss", "ll", "tt": two identical glyphs inside `editMatchRuns`' origin tolerance :1434). Scan time 523 / 485 ms; tokens 48,299 / 47,399 (cap 50,000).
- P3 A prototype grouping (same font, size, colour and baseline, contiguous blocks; gap = next x − (x + advance), in em) gives 67 / 77 lines a page. Intra-word gaps: −0.008 … +0.014 em. Word gaps: 0.26 … 0.57 em (median 0.278). Nothing between 0.014 and 0.26. Every block matched the head/tail grammar of D1 (0 misses).
- P4 Stripping every per-glyph clip changes 0.03–0.3 % of the page's samples (antialiasing fringe the integer clip shaved off; max delta ≈ 100/255): the clips hide no glyph, they only trim edge pixels.

## Decisions (fable51; each built as written)

- **D1 (glyph block grammar)** — a *glyph block* is, in one top-level page content stream (record `path` matches `^c\d+$`, `depth` 0), exactly this token sequence (any PDF whitespace between tokens):
  `q` [`n n n n re W n`] [[`/Name cs`] `n{1,4}` (`sc`|`scn`|`g`|`rg`|`k`)] `q` `S 0 0 S X Y cm` `BT` `1 0 0 1 0 0 Tm` `/Font 1 Tf` `<one string operand holding exactly 1 byte>` `Tj` `ET` `Q` `Q`
  with `S > 0` (both scale numbers equal as numbers), and the walker's own record for that `Tj` must agree: a Coded font (`font.cid` with `bytesPerCode` 1), decoded text of exactly one non-space character, `renderMode` 0, `ocDepth` 0, no `mcid`, no ActualText, `characterSpacing`/`wordSpacing` 0, `horizontalScale` 1, `textLinear` equal to `[S,0,0,−S]` and `origin` equal to the page transform of `(X, Y)` (both within 0.01; so no outer `cm`, no rotated page, `geometryBlocked` false), and `support` either `candidate` or `unsupported` with reason exactly `ambiguous-text-association` (P2). Anything else is not a glyph block and keeps today's behaviour. The clip and the colour group are optional so that a line this unit rewrote (D5: no clip) is recognised again.
- **D2 (glyph lines: a scan post-pass)** — new `editCollapseGlyphLines(state)` in `content-edit.ts`, called in `scanEditTargets` (:1939) after `editAttachRepertoires` and before `editAttachGrowthLimits`. It walks `state.items` in order and chains consecutive glyph blocks into a *glyph line* when: only whitespace lies between the previous block's final `Q` and this block's first `q`; same `tfName`, same `S`, same colour group (whitespace-normalised bytes; both absent counts as same), `|Y − Y_prev| < 0.005`; and `gap = (X − (X_prev + adv_prev)) / S` (adv = the font's `/Widths` advance ÷ 1000 × S) satisfies `−0.2 < gap ≤ 1.0`. `gap > 0.12` means one word space before this glyph; otherwise none. A block that fails any test starts a new line. A line needs ≥ 1 `candidate` member (it lends `cidWrite`, `repertoire`, `font`, the vertical bounds); a chain with none is left uncollapsed. Lines of one glyph are lines too (a lone glyph must not keep its clipped per-glyph record).
  Each line becomes ONE ordinary text record + item that replaces its members (the item takes the first member's position in `state.items`; member items and records are removed):
  `kind "text"`, `support "candidate"`, `path`/`objectNumber`/`depth`/`cow` of the first member, `text` = the characters with one `" "` per word gap, `font`/`tfName`/`tfSize`/`fontSize`/`cidKey`/`cidWrite`/`textLinear`/`leading` from a candidate member, `origin` = first member's, `bounds` = union (a member without bounds contributes `[x, top, x + adv, bottom]` with top/bottom from the union of the bounded members), `firstOnLine true`, `tailFollows false`, `prevShowId null`, `between null`, `kerned` undefined, `payloadBytes` undefined, `operandStart` = first block's `q` start, `operandEnd` = `opStart` = `opEnd` = last block's final `Q` end (the whole chain is the operand; the op span is empty), `targetId = editTargetId(page, path, operandStart, "GL|" + codes and gap flags)`, and a new worker-only field `glyphLine: { glyphs: [{ code, x, adv }], y, scale, colour: string, space: number }` where `space` (em) = the median of this line's word gaps, or 0.28 when it has none. The item gains `glyphs: <member count>` (the only new reply field) and its `repertoire` string additionally contains `" "`.
  The stream bytes the post-pass needs come from a new `state.streams: Map<string, Uint8Array>` that `walkEditContent` fills for depth-0 paths (one additive line; the walker's logic is otherwise untouched — it is on the don't-touch list for moves, not for this).
- **D3 (caps)** — `emit` (:2020) enforces a new raw ceiling `MAX_EDIT_RAW_TARGETS = 4096` (same `too-large` message with that number); `MAX_EDIT_TARGETS = 512` is enforced on `state.items.length` right after the collapse with today's exact message. `MAX_EDIT_TOKENS` goes 50,000 → 200,000 (4096 blocks × ~39 tokens; the human's pages sit at 48 k). `MAX_EDIT_SCAN_BYTES`, `MAX_EDIT_REPLY_TEXT_CHARS` and every other cap are unchanged. A page over a cap is refused whole, as today. Grep every test/doc that names 512 or 50,000 for the *raw* meaning and fix the wording only where it is now wrong (list each in the build note).
- **D4 (planning an edit)** — `editPlanText` (:958) starts with `if (record.glyphLine) return editPlanGlyphLine(…)`. Same signature inputs (`next`, `geometry {move, size}`), same `EditTextPlan` out, so `edit-text`, `edit-replace-preview/apply` and `edit-batch` (move) work on glyph lines with no engine change beyond D6. Rules:
  1. `next`: every whitespace run becomes one space, both ends trimmed (`record.text` is already in that form). Over `MAX_EDIT_TEXT_CHARS` → `too-large` (before normalising, as today).
  2. Every non-space character must be in `cidWrite.chars`; else `unsupported-encoding` with `missing` (≤ 20), the same detail/extra `editPlanText` gives a Coded run (:993).
  3. Layout: glyph i sits at `x_i`; text unchanged (pure move/size) → `x_i' = x0' + (x_i − x0) × S'/S` (original spacing kept exactly); text changed → `x_0' = x0'`, each next glyph at previous + its advance × S', plus `space × S'` per word space.
  4. `size` (page pt, 1..400, same validation message as `editPlanGeometry` :915) → `S' = size`; `move {dx, dy}` (page view, y down) → `x0' = x0 + dx`, `Y' = Y − dy`; invalid shapes refuse `invalid` with the existing messages.
  5. Width, growth and page rules are the existing ones, reused not copied (:995-1027; restructure so both paths run the same lines): `oldWidth` = bounds width, `newWidth` = last glyph's right edge − x0'; growth over 0.5 pt must stay within `growthLimit`/`obstacleLimit`/page right exactly as an ordinary run (`overflow`), a moved/resized box must stay on the page (`outside-page`).
  6. Output: `operand` = the blocks re-emitted one per glyph, **without a clip**, separated by one `\n`: `q <colour> q S' 0 0 S' x_i' Y' cm BT 1 0 0 1 0 0 Tm /Font 1 Tf <hh> Tj ET Q Q` (numbers through `editNumber`, the code as 2 hex digits, the colour group verbatim, omitted when the line had none). Empty `next` → empty operand (the line is deleted; `text: ""` is today's delete). `prefix`/`suffix` stay `""`, `tag` = `editActualTextBytes(next)` (unused: glyph blocks carry no ActualText), `shift 0`, and a new plan field `rewrite: true` when the bytes differ from the source span (so a pure move is not mistaken for a no-op).
  7. Rescanning the written stream must yield one glyph line with `text === normalised next` (or none when deleted) — that is the proof the write is what was planned.
- **D5 (clips)** — a rewritten line drops its per-glyph clips (P4: they only trim antialiasing fringes). Untouched lines keep their bytes. Stated as a ceiling in Help and `docs/agent.md`: "a line that was clipped per glyph is redrawn unclipped".
- **D6 (engine)** — `edit-text` (:5647) treats `plan.rewrite === true` as a change: the no-op test becomes `next === record.text && !plan.prefix && !plan.suffix && !plan.rewrite`; for a glyph line `next` is compared after D4.1 normalisation. Journal label unchanged ("move text" with geometry, else "edit text"). `edit-batch` (:4075) and `buildReplacePreview` (:1585) need no change if D4 is honoured — prove it with tests, change only what a failing test forces. `clip-copy` (:3593) refuses a glyph line: `refuse("a print-to-PDF line")` → existing detail `not-candidate` (so Copy/Cut/Duplicate of such a line are refused; ceiling). `editParagraphLine` (:2870) already excludes it (`cidWrite`). No new op, no new `OP_PERMISSION` entry, no new reason/detail token.
- **D7 (renderer, drive, STATE — parity)** — glyph lines are ordinary text targets: click-to-edit, drag, arrows, the size control, Find/Replace and the `content` drive command must work with no new plumbing; fix only what a test shows broken (e.g. anything that assumes `payloadBytes`/`kerned`, or the inline editor sending un-normalised text). STATE: new key `content.glyphLines` = number of items with `glyphs` on the shown page (no existing key changes shape). The repertoire sentence (`renderer.ts` :4790) is unchanged (it will now show the space). No new control ids.

- **D12 (amendment 2026-09-30, after D11: near-equal scale, explicit space blocks)** — the D11 build left 68 / 53 single-glyph items on the human's pages for two reasons, both now accepted into D1. (1) Scale: the two `cm` scale numbers count as equal when |a − d| ≤ 1e-3 · |a| (Quartz writes 11.9625 / 11.96249); the glyph's and the line's scale is `a`, and the same tolerance applies where a chain compares one block's scale with the next. A re-emitted block writes that one scale for both numbers. (2) Space blocks: a glyph block on a D11 font (not a Coded font) whose operand is the one byte 0x20, with a `/Widths` number for 0x20, joins the chain as a word gap: it contributes exactly one space to the line's text (no second space from the gap rule on either side of it), is not a glyph in `glyphs`, never starts or ends a line (leading/trailing ones stay out of the chain as today), and is consumed by the collapse so it is no target of its own. On rewrite, spaces stay gaps as in D4 (no 0x20 block is re-emitted; the advance of a space is the line's `space` value, which for a line with 0x20 blocks is the font's `/Widths` value for 0x20 scaled). An unedited line is untouched bytes as before. Fixture: the `/TT3` line's two spaces become explicit 0x20 blocks and its `cm` d is written as a − 0.00001 on every other glyph; regenerate, re-pin. Tests: the D11 test's expectations hold unchanged on that line (one glyph line, text "Office use only", edit ok, undo restores bytes); no separate item for the space blocks. Acceptance on the human's file is as in D11 (zero single-character glyph-block items on both pages; ambiguous records excepted).

- **D13 (amendment 2026-09-30, after review `review-print-edit.md`)** — (1) D12's "exactly one space" per 0x20 block becomes: a run of adjacent space blocks contributes one space (so the line text is always whitespace-normalised and an identical-text edit or a pure move never re-lays the line out). (2) A page whose ordinary (non-glyph) runs alone exceed 512 refuses `too-large` before run matching (fast, as before the unit). (3) Chain tolerances compare with the chain's first block. ## 3. Not in scope
A fallback font for characters the subset lacks (needs a human decision: §1 forbids substitution); joining a line across a font change; paragraphs/reflow over glyph lines; Copy/Cut/Paste/Duplicate of glyph lines; per-glyph blocks inside Forms, under an outer `cm`, on rotated pages, with `Tf` size ≠ 1, non-uniform scale or 2-byte codes; Skia/Chrome "Save as PDF" output (different shape); keeping original kerning offsets on an edited line; scan speed work beyond the D3 caps; a text-size control for fill boxes.
