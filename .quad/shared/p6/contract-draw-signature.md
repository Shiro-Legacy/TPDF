# draw-signature — draw your signature once, place it on any page in Fill forms

Drafted 2026-09-30 by fable51 (lean mode: one Opus 5.5 implementer + one Opus 5.5 reviewer; human-ordered in chat 2026-09-30). Line numbers are from the tree as of 2026-09-30; re-grep before editing. Rollback: `.quad/backup/pre-draw-signature-20260930.tgz`; fixture snapshot `.quad/shared/p6/checks/draw-signature-hash-before.txt` (56 lines). Baseline `npm test` = 626 tests / 625 pass / 0 fail / 1 skip.

**Problem:** the only "picture of a signature" today is Annotate → "Sign…" (`#sign-dialog`, `src/renderer/index.html` :638; `src/renderer/renderer.ts` :7233-7284), which needs an image file and a typed name and writes a fixed 200×60 Stamp. There is no way to draw a signature, nothing is remembered between launches, and the Stamp is not a target on the page.

**Human decision (authoritative):**
- **H1** (2026-09-30, verbatim): "I want to be able to just draw a signature and use that as my signature as a feature". This reverses the 2026-09-22 "draw/type signature pad is dropped" note for the *draw* pad only. A typed signature stays dropped.

## Decisions (fable51; each built as written)

- **D1 (what a drawn signature is in the PDF)** — an **Ink annotation** made from the drawn strokes (vector; no image encode/decode, no new dependency). `annot-add` with `type:"Ink"` takes an optional `signature: true` (`src/renderer/engine.ts` :4905-4990). Without it today's path is byte-identical (every existing sha/style pin stays green unchanged). With it: colour black `[0,0,0]`, border width = `signatureLineWidth(w)` = `clamp(w × 0.0075, 0.6, 4)` where `w` is the width of the strokes' bounds in points (200 pt → 1.5), `/Subj` = a new exported constant `DRAWN_SIGNATURE_SUBJECT = "Drawn signature"` (beside `SIGNATURE_SUBJECT` :121), no `/T`, no `/Contents`, nothing else personal. `strokes` go through the existing `checkStrokes` (:1754) unchanged. Journal label "add drawn signature". `signature` on any other type, or a non-boolean, is refused before `mutate`.
- **D2 (engine: move and resize)** — `annot-move` (:5033) also accepts an Ink whose subject is `DRAWN_SIGNATURE_SUBJECT`: `point` is the new top-left of the rect `listAnnotations` reports for it (`annotRect`, the ink bounds, :1920); optional `width` (finite number) is the new bounds width with the aspect ratio kept. Rules: `width` is clamped to `[24, page width]` and further so the scaled height fits the page; a `width` on a signature whose current bounds are under 1 pt wide is refused; the rect is then clamped inside the page box (the FreeText rule); every ink point is mapped (translate, then scale about the top-left), the border width is recomputed with `signatureLineWidth`, `annot.update()`. One journal op: "move signature", or "resize signature" when the width changed by more than 0.01. Landing on the current rect (every edge within 0.01) replies `noop: true` and journals nothing. `width` on a FreeText is refused (`annot-move: width applies to drawn signatures only`). Every other annotation, including an ordinary Ink, keeps today's refusal text verbatim (`annot-move: only FreeText annotations can be moved` — it is pinned). `OP_PERMISSION["annot-move"]` is unchanged; the request type gains the two optional members; no new engine op, so the op-coverage lists in `tests/p2-shell.test.mjs` do not move.
- **D3 (where the signature is kept)** — new `src/sign/drawn.ts` beside `trust.ts`, same shape: `createSignatureStore(path: string | null)` → `{ get(): DrawnSignature | null, set(value: DrawnSignature | null): void }` plus an exported `checkDrawnSignature(value: unknown): DrawnSignature | null` used on **both** read and write (the file and the IPC payload are trust boundaries). `DrawnSignature = { v: 1, width, height, strokes: [number, number][][] }` in pad CSS pixels with the bounds' top-left at the origin: `width` in [8, 4096], `height` in [0, 4096], 1..64 strokes (`MAX_INK_STROKES`) of 2..2048 points (`MAX_INK_POINTS`), every coordinate finite and inside `[0,width] × [0,height]` (±0.01), coordinates rounded to 2 decimals on write; anything else → `null` (read) or a refused `set`. `path === null` keeps it in memory; a file is written temp + rename with mode `0o600`, read with a 4 MiB cap, and `set(null)` removes it (a missing file is not an error). `src/main.ts` (:463): `createSignatureStore(smoke ? null : join(app.getPath('userData'), 'drawn-signature.json'))` — so under `--smoke`/`--drive` (and therefore every agent/MCP session) the store is memory-only: **a driven session never reads or writes the human's saved signature.** IPC, both guarded by `isTrustedOpen(event)` like `trust-clear` (:932): `signature-get` → `{ ok: true, signature: DrawnSignature | null }`; `signature-set` (payload validated by `checkDrawnSignature`, or `null` to remove) → `{ ok: boolean }`. `src/preload.cts`: `signatureGet()`, `signatureSet(value)`. The renderer reads it once at start-up into a module variable and after every successful set. Never `localStorage` (partition `p0` is in-memory), never logged, never in STATE beyond counts.
- **D4 (the pad)** — one `<dialog id="sigpad-dialog" aria-labelledby="sigpad-heading">` in `index.html` (built on `#sign-dialog`'s markup): heading "Draw your signature"; one sentence "This is a picture of your signature, kept on this Mac. It is not a certificate signature: nothing is verified and the document is not cryptographically signed."; `<canvas id="sigpad-canvas" role="img" aria-label="Signature drawing area">` (about 520×180 CSS px, backing store × `devicePixelRatio`, white with black ink in both themes, `touch-action: none`); `#sigpad-status` (`role="status" aria-live="polite"`); buttons `#sigpad-clear` "Clear", `#sigpad-remove` "Remove saved signature" (disabled when none is saved), `#sigpad-save` "Save" (disabled until the drawing has ≥ 1 stroke and its bounds are ≥ 8 px wide), `#sigpad-cancel` "Cancel". Recording is three plain functions — `padBegin(point)`, `padPoint(point)`, `padEnd()` — called by the canvas pointer handlers (pointer capture; `getCoalescedEvents()` when present) with the Annotate ink recorder's rules (:9535-9562): a sample under 0.5 px from the last is skipped, a stroke stops growing at 2048 points, a stroke of 1 point is dropped, a 65th stroke is refused with the status "A signature can have at most 64 strokes". Save runs one function `saveDrawnSignature()`: translate the bounds to the origin, round, `signatureSet`, cache, close, announce "Signature saved". Remove = `signatureSet(null)`, announce "Saved signature removed". Cancel and Escape write nothing. The pad always opens empty (redraw to replace). Drawing needs a pointer — a stated ceiling; the keyboard path to a signature picture stays Annotate → "Sign…" with an image.
- **D5 (placing it)** — Fill forms panel, beside `#fill-textbox-add` (`index.html` :268): `#fill-sign` "Sign" (`aria-pressed`) and `#fill-sign-draw` "Draw signature…" (opens the pad). Both need `canAnnotate()` and an open document, like `#fill-textbox-add`. `#fill-sign` with no saved signature opens the pad, and a successful Save then arms placement; with one saved it arms directly: `aria-pressed="true"`, focus to the page region, announce "Click the page to place your signature". While armed: the next plain left click on the page places the signature **wherever it lands, including over a field or a text box** (armed placement outranks the hit-layer targets, as armed ink does); Enter on the page region places it at the centre of the shown page (keyboard path); Escape, a mode change, a page-less state or a second press disarms without writing. Placement always disarms. Menu: one item "Place Signature" directly under "Signature Appearance…" (`src/main.ts` :1342), no accelerator, sending `edit-request {op:"sign-place"}`; `OP_MODE["sign-place"] = "forms"`; with no `contents` it behaves as a press of `#fill-sign`.
  One function `placeSignature(page, [x, y], width?)` is shared by the click, the Enter path and the drive op: scale the saved strokes to fit inside `SIGNATURE_SIZE` (200×60 pt, aspect kept; `width`, when given, is the bounds width instead, clamped as D2 clamps it), centre the bounds on the point, shift them inside the page box, send one `annot-add {type:"Ink", page, strokes, signature:true}`, announce "Added signature", focus the new target. Refusals (shown in `#error` and announced, nothing written, document stays clean): a rotated page (`doc.rotations[page] % 360 !== 0`) → "A signature cannot be placed on a rotated page"; no saved signature; `!canAnnotate()`.
- **D6 (the signature is a target)** — in `uiMode === "forms"` every Ink on the shown page with `subject === DRAWN_SIGNATURE_SUBJECT` and `editable` is painted as `button.hit-target.signature-target[data-annot-id]`, `aria-label` "Signature <n>" (1-based order on the page), built on `paintMarkTarget` (:3856) — the one with handles: `addFieldHandles` + `startRectGesture` with `lockAspect: true`, `min: 24`; commit = one `annot-move {page, annotId, point:[rect[0], rect[1]], width: rect[2] - rect[0]}` (`width` omitted for a grip move), announce "Moved signature" / "Resized signature", a `noop` reply announces nothing. A side handle that would break the aspect ratio resizes by its width change (the engine keeps the aspect); shift-drag does **not** unlock the aspect for a signature. Keyboard on a focused target: arrows nudge 1 pt, Shift+arrows 10 pt (`nudgeRect`), `+`/`=` and `-` grow and shrink the width by 10 % about the top-left, Delete/Backspace deletes (`deleteNote(id, "Deleted signature")`), Escape drops focus; Enter and a plain click only focus it. Every gesture is one journal op and undoable; a no-op never dirties. Signatures are not selection members (no Shift multi-select, clipboard or context menu) — the text-box ceiling. In Annotate the signature is an ordinary Ink row in the annotation list (deletable there); no on-page target outside Fill forms.
- **D7 (drive + STATE, same unit)** — two drive ops, known everywhere commands are listed (`src/main.ts` `startDrive`, the renderer `runEditRequest` chain :1647, `READ_ONLY`/`DEFAULT_EDIT`/`OP_MODE` rules, the Drive guard, `docs/agent.md`):
  `{"cmd":"sign-draw","contents":{"strokes":[[[x,y],…],…]}}` — strokes in any y-down box; opens the pad, feeds every point through `padBegin`/`padPoint`/`padEnd` and runs `saveDrawnSignature()` (the pad's own code path, not a second one), then closes it. `{"cmd":"sign-draw","contents":{"clear":true}}` removes the saved signature. Needs no open document, writes no journal op, never dirties. Bad `contents` (not an object, no usable stroke, both keys) → `error`, nothing saved.
  `{"cmd":"sign-place","contents":{"page":0,"x":300,"y":650,"width":180}}` (`width` optional) — Fill forms, that page, `placeSignature`. Errors in `error`: `sign-place: page, x and y are required`, the page-range text `fill-text` uses, `sign-place: no signature has been drawn`, the rotated-page sentence, `sign-place: this document does not permit annotations`. `{"cmd":"sign-place"}` with no `contents` arms placement (the menu path), so an existing `click {page,x,y}` step then places it.
  Move, resize and delete are driven by the existing `drag`, `click` and `key` steps on the target (the fill-anywhere rule, :1520): arrows, `+`/`-`, Delete reach a focused `.signature-target`; `key Escape` disarms / drops focus; `key Enter` while armed places at the page centre.
  STATE — new keys only, inside `fill` (:8430); no existing key changes shape: `fill.signature: { saved: boolean, strokes: number, points: number, armed: boolean, pad: boolean }` (counts of the saved signature, `pad` = the dialog is open; **never the points**), `fill.signatures: [{ id, rect }]` (the drawn signatures on the shown page in page order, `rect` rounded to 2 decimals), `fill.lastSignature: { op: "add"|"move"|"resize"|"delete", id, rect } | null` (`rect` null for delete). `fill.boxes` and `fill.last` are untouched. Grep the tests for a deep-equal pin of `fill` and extend it in place if one exists; list it in the build note.
- **D8 (a signed document saves as a copy)** — every successful place, move, resize or delete of a drawn signature calls `noteFilled()` (:2459), so fill-anywhere H2 applies unchanged: Save offers `<name> (filled).pdf` and never overwrites the original. No change to `save-file`, `saveInPlace` or `safe-write.ts`.

## 3. Not in scope
A typed signature; importing an image into the pad (Annotate → "Sign…" already takes an image); more than one saved signature, initials; pen colour or thickness controls; smoothing/curve fitting of strokes; encrypting the saved file; using the drawing as the visible appearance of a certificate signature; flattening the signature into page content; rotated pages; on-page targets in Annotate mode; signatures as selection members; keyboard-only drawing; Windows packaging.

## 4. Amendments at acceptance (2026-09-30, fable51)
D3/D4: a drawing holds at most 4096 points in all (store check, pad, `sign-draw` → `error`); the pad skips samples under 2 px from the last (was 0.5); a 1-point stroke is kept as a dot (was dropped). Reason: the review measured mupdf's Ink appearance as quadratic in the point count (1.07 s at 4096 points, 16.9 s at 16384). `sign-draw` contents may be up to 4 MiB and are `[redacted]` in reports (review fixes 1–2).
