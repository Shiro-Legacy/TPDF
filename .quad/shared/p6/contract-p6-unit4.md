## 1. Links on the page (Read mode follows, Annotate mode edits)
Today: `link-add`/`link-delete` (engine.ts ≈3980–4030, scheme allowlist `LINK_SCHEMES`, `MAX_URI_CHARS`), `listLinks` (≈2497: `{id: index, rect, kind: page|uri|blocked, page?, uri?}` in `getLinks()` order), the Links inspector tab (index.html ≈355–365, `renderLinks` ≈4892, `followLink` ≈4951 only from panel buttons, `openLinkDialog`/`saveLinkDialog`/`addLink` ≈5034–5090 anchored on the current find hit), drive `link {kind, page|uri}` / `{action:'delete', index}` (≈1153). **No link is clickable or editable on the page today.** mupdf 1.28.1 wasm declares `Link.getBounds/setBounds/getURI/setURI/isExternal` and `Page.getLinks/createLink/deleteLink` (mupdf.d.ts 427–456). `Link.getBounds()`, like widget `getRect()` and redaction rects, is in mupdf page space (y-down, `/Rotate` applied), so the renderer places links with `placeBox` exactly as `paintMarkTarget` does; no `editViewBox` math is needed. **Probe facts that bind this unit (`probe-links-u4.md`, confirmed independently by the engine map M1–M4):** (P1) `Link.setBounds()` takes the RAW `/Rect` space (unrotated, y-up) while `getBounds()` returns page space — a raw `setBounds(pageRect)` reopens mirrored; the proven write is `Rect.transform(rect, Matrix.invert(page.getTransform()))` (through `setBounds` or a `/Rect` put) and only a save → reopen proves it. (P2) `setURI` on a link that carries `/Dest` leaves `/Dest` in place and mupdf reads `/Dest` first, so the retarget is silently lost on reopen: `entry.delete('Dest')` in the same op. (P3) Links are not in `page.getAnnotations()`; their identity is the object number of the `/Annots` entry, and `getLinks()` skips `/Link` entries with no `/Rect` or no `/A`/`/Dest` (index drift). (P4) `setBounds`/`setURI` journal a step even when nothing changes, and a page handle held open returns stale link data — the engine checks no-op itself and destroys the page before reading back. (P5) `setURI` has no scheme policy (`javascript:` → `/S /URI`, `file:` → `/GoToR` that `resolveLink` reports as a page): the allowlist check runs before any write.

### 1.1 Engine — `listLinks` gains a stable id
Every `links` item gains `annotId: number` = the object number of the link's `/Annots` entry (P3; `Link` has no `getObject()`). `listLinks` walks `page.getObject().get('Annots')` in order, considers only indirect entries with `/Subtype /Link`, skips the entries mupdf skips (no `/Rect`, or none of `/Dest`/`/A`), and zips them onto `getLinks()` confirming each pair by `Rect.transform(raw /Rect, page.getTransform())` ≈ `getBounds()` ± 0.01 (on a mismatch advance the `/Annots` cursor; when no entry matches, `annotId: 0`). A direct (inline) Link dict reports `annotId: 0` and `link-set` refuses it with `no-such-annot` (stated ceiling). `id` (index in `getLinks()` order) stays for the panel and `link-delete`. `getLinks()` order is `/Annots` order (probe §5); the fixture test pins that a bare `/Link` dict with no action between two real links does not shift their `annotId`s, and that after `link-delete` of the middle of three links the remaining `annotId`s are unchanged while `id`s renumber. Object numbers survive `garbage=yes` saves (probe §5).

### 1.2 Engine — `link-set`
`{op:'link-set', page, annotId, rect?: [x0,y0,x1,y1], target?: {page} | {uri}}` — at least one of `rect`/`target`. `OP_PERMISSION['link-set'] = 'annotate'` (as `link-add`). Order of checks, each a fixed refusal before any write, via `failLink(token, detail)` (engine-core.ts next to `failRedact`; the reply is `{ok:false, error: detail, reason: token}` exactly as `failRedact` replies): `rect` (not four finite numbers, non-positive area, or off the page — `checkLinkRect` as `link-add`; the renderer clamps with `gestureRect`, the engine refuses, never clamps), `no-such-annot` (no annotation with that object number on the page), `not-link` (the annotation is not `/Subtype /Link`), `target` (target is neither `{page: integer in range}` nor `{uri: string}`), `scheme` (URI scheme not in `LINK_SCHEMES`, or the URI is empty or longer than `MAX_URI_CHARS` — detail names the scheme or the limit). **No-op:** when the requested rect equals the current bounds within 0.01 on every side and the requested target equals the current one (same resolved page, or same URI string) the reply is `{ok:true, noop:true, ...journalState}` and nothing is written or dirtied. Otherwise ONE `mutate(session, doc, 'edit link', …)` on one page handle applies the rect as `link.setBounds(Rect.transform(rect, Matrix.invert(page.getTransform())))` (P1; a `/Rect` put of the same transformed rect on the `/Annots` entry is the equivalent fallback) and/or the target as `entry.delete('Dest')` followed by `link.setURI(uri)` (P2) with `uri = doc.formatLinkURI(fitDest(page))` for a page target, the raw URI for a web link — both journal inside `beginOperation`/`endOperation` as one step (probe §2). The page handle is destroyed before the reply and before any read-back (P4). A rect-only `link-set` on a `blocked` link is allowed (the dict path writes no action); a target change on any link goes through the allowlist first (P5). Reply `{ok:true, ...editState(session)}` as `link-add`. A page target is written as a `/Fit` destination exactly as `link-add` does (no named destinations, no zoom); retargeting a page link to a URI and back is one op each, and a link that carried `/Dest` reads back the new target after save → reopen.

## 3. Cheap backlog (renderer + drive)
### 3.1 Plain-arrow nudge
A focused `.object-target`, `.redact-target`, `.link-target` (Annotate) or field `.hit-target` (editable) moves 1 pt on a plain arrow and 10 pt with Shift, through the existing `nudgeRect`/`nudgeField` commits (one op each, `noop` never dirties); ⌥-arrows keep working (U1/U3) and ⌥⌘←/→ keep resizing objects. Exception: on a radio kid, plain ←/→ still move the selection (ARIA radio-group convention) and only ↑/↓ nudge; ⌥-arrows nudge all four. Page turning is untouched: `pageRegion`'s keydown already ignores events from inside `#hit-layer`; today a plain arrow on a target falls through to the browser and scrolls `#viewport`, so the handlers `preventDefault` the arrows they consume. Inline editors keep plain arrows for the caret. `driveDirectKey` dispatches plain arrows to a focused target the same way it dispatches `Alt+…` today (the `onTarget` branch), and to a focused field target (`directFocusedField` without an editor) via `nudgeField` with the plain amount. Drive: `click` the target, `key ArrowRight` → +1 pt, `key Shift+ArrowDown` → +10 pt; geometry via `pick()` in the test file; a plain `ArrowRight` on a focused radio kid changes `fields.values[group]`, not its rect.
### 3.2 Always-on outlines in Edit mode
A checkbox `#edit-outlines` "Outline objects" in `#context-edit` (next to the add-text arm button — not in `#field-bar`, which is hidden on pages without fields; localStorage `edit-outlines`, default **on**) adds class `outlined` to `#hit-layer` in Edit mode; CSS draws a 1 px dashed `#6558d8` outline on every `.object-target` and every candidate `.text-target` without hover (hover/focus/selected rules unchanged). STATE `direct.outlines: boolean`; drive `outlines {on: true|false}` (one line in `runEditRequest`) mirrors the checkbox and repaints. The default must hold with `localStorage.getItem` returning null (fresh drive udata, the p6-direct child stub) and no new import-time browser API may be added (the child has no `matchMedia`). GUI shot shows the outlines.
### 3.3 Unarmed redact drag
In Redact mode a pointerdown on the page that is not on a `.hit-target`/`.hit-handle` (marks stop propagation in `startRectGesture`) starts an area drag without arming, with the pointermove/pointerup listeners on `window` (as `startRectGesture`, so a drive's window-dispatched events reach it): ≥ 3 px movement → `preventDefault` (no text selection) and, on release, `addRedactArea(page, rect)` exactly as the armed path; less → nothing (a click stays a click: it only drops the mark focus as today, no mark, no `invalid` refusal, no error). The armed path (`redactDrag`, today `#page` listeners + `setPointerCapture`, no threshold) is rewritten onto the same `startAreaDrag` helper as §1.6, so it gets the 3 px threshold (today an armed click sends a degenerate rect the engine refuses) and becomes drivable; "Mark area" stays for a human who wants the explicit tool and still disarms after one drag. Selection in the text layer is not used for marks (ceiling: text marks still come from search). Drive: `mode redact`, `drag` at empty space with `dx 100 dy 30` → `redact.marks +1` (absolute in the script) and `redact.rects[i].rect` = `[x, y, x+100, y+30]`; a `drag` with `dx 1 dy 1` → no new mark; a `click` on empty space → no new mark.
### 3.4 Drive: gestures on empty space
`driveDirectGesture` today returns when no hit-layer element is under `(x, y)`. Change: when neither a `.hit-target` nor a handle is under the point, dispatch the same pointerdown/pointermove/pointerup sequence on the element `document.elementFromPoint(x, y)` (canvas/text layer inside `pageRegion`) so page-level drags (§1.6 draw link, §3.3 area mark) run; page-level drags set `directGestureWork` to the promise of their commit so the STATE line follows the write. `packDrive` needs no new keys.
