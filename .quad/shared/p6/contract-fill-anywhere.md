# fill-anywhere — type on a flat form in Fill forms; a filled document saves as a copy

Drafted 2026-09-30 by fable51 (lean mode: one Opus 5.5 implementer + one Opus 5.5 reviewer; human-ordered in chat 2026-09-30: "work on the queue unit in progress.md use opus 5.5 for build"). Rollback: `.quad/backup/pre-fill-anywhere-20260930.tgz`; fixture snapshot `.quad/shared/p6/checks/fill-anywhere-hash-before.txt` (55 lines). Baseline `npm test` = 601 tests / 600 pass / 0 fail / 1 skip.

**Problem (progress.md §10 "Queued units" 1):** a Firefox Print → Save-as-PDF copy of a form has 0 AcroForm fields; Fill forms shows "No fillable fields on this page." and nothing can be typed. Annotate's "Add text box" opens a modal dialog (`openTextBoxDialog`, `src/renderer/renderer.ts` :8361) and writes a fixed 160×40 pt FreeText (`engine.ts` :4914, `freeTextBox` :1807) that wraps long text, cannot be moved, and is not a target on the page.

**Human decisions (authoritative):**
- **H1** In Fill forms a click on page space that is not a field places a FreeText text box with an inline editor at the click point; the box can be moved, edited and deleted afterwards; real fields fill as today.
- **H2** Once a document has been filled since it was opened (a field fill or a fill-mode text box), Save (⌘S) always makes a copy: the save dialog opens with `<basename> (filled).pdf` in the original's folder and the original is never overwritten. Save As (Save a copy) is unchanged.

## Decisions (fable51; each built as written)

- **D1 (engine: a FreeText that fits its text)** — `annot-add` with `type:"FreeText"` takes an optional `fit: true`. Without `fit` today's path is byte-identical (every sha/rect pin stays green unchanged). With `fit`: `point` is the box's left edge and the vertical centre of its first line (page points, y down); the engine sizes the rect so every typed line (split on `\n`) is drawn on one line with no wrap: width = widest line's Helvetica advance at the box's font size + the padding mupdf's FreeText appearance writer uses, height = lines × that writer's line height + padding. **Probe first** (`.quad/scratch/fill-anywhere/`, headless mupdf): find the writer's padding, line height and wrap rule by reading the generated `/AP` stream for 3 strings, and quote the numbers in the build note; reuse the existing base-14 width measuring (`content-edit.ts` / `engine-core.ts`), never a second metrics or WinAnsi table. The rect is then moved inside the page box (as `freeTextBox` does); a line wider than the page gets width = page width and may wrap (the only wrap case). Font stays `Helv` 12, black, border 0. A character the shared WinAnsi encoder cannot encode refuses before `mutate` with the same detail shape `text-add` uses (`unsupported-encoding` + `missing`); no journal op, not dirty.
  `annot-set` takes the same optional `fit: true`: for a FreeText whose default appearance is Helv it re-fits the rect to the new contents keeping the left edge and first-line centre; any other annotation or font ignores `fit` (today's behaviour). Without `fit`, `annot-set` is unchanged.
- **D2 (engine: move)** — new op `annot-move {page, annotId, point:[x,y]}`: FreeText only (else Error `annot-move: only FreeText annotations can be moved`); `point` is the new top-left; the rect keeps its size and is clamped inside the page box; `annot.update()`; one journal op "move text box"; a move that lands on the current rect replies `noop: true` and journals nothing (the `redact-set` rule). `OP_PERMISSION["annot-move"] = "annotate"`; request type, worker dispatch and the op-coverage lists in `tests/p2-shell.test.mjs` follow progress.md §5 "Code rules".
- **D3 (renderer: click to type)** — In `uiMode === "forms"`, a plain left click on page space that is not a hit-layer target opens an inline editor there. Guards are `clickToAdd`'s (:4029-4049): not Shift/Control/secondary, not `addBlocked`, no open editor, not committing, `layerLive()`, collapsed selection, point inside the page, plus `canAnnotate()` (false → the click does nothing, as `clickToAdd` does without `canEdit()`). A rotated page (`doc.rotations[page] % 360 !== 0`) refuses: `showError("A text box cannot be placed on a rotated page")`, no editor. The editor is `openAddText`'s textarea (:4011) in a text-box variant: Helvetica 12, black, grows with its draft (`growAddEditor`), its left edge at the click x and its first line vertically centred on the click y. `directActive.kind` gains `"textbox"` with `annotId: number | null` (null = new). Enter, Tab and blur commit (`setupInlineEvents(editor, false)`); Escape closes without writing; an empty draft (`addDraft`) writes nothing. Commit of a new box = one `annot-add {type:"FreeText", page, point, contents, fit:true}`, announce "Added text box". A refusal shows the same message `addTextAt` shows (:4060-4065) in `#error` and the announcement, behaves as a refused add does today, and leaves the document clean.
- **D4 (renderer: the box is a target)** — In forms mode every FreeText annotation on the shown page with `editable` true is painted as `button.hit-target.textbox-target[data-annot-id]`, `aria-label` "Text box <n>" (n = 1-based order on the page), built on the `paintMarkTarget` pattern (:3827-3858): a grip drag moves it (one `annot-move`, announce "Moved text box"; no resize handles), arrow keys nudge 1 pt (the mark rule, `nudgeRect`), Delete/Backspace deletes (`deleteNote(id, "Deleted text box")`), Escape drops focus, a click without movement or Enter opens the D3 editor prefilled with the contents and selected (`annotId` set). Commit of an existing box: unchanged → nothing; changed → `annot-set {contents, fit:true}`, announce "Edited text box"; emptied → `annot-delete`, announce "Deleted text box". Every gesture is one journal op and undoable; a no-op never dirties. Text boxes are not selection members (no Shift multi-select, no Cut/Copy/Paste, no context menu) — a stated ceiling. Fields keep every behaviour they have; a click on a field never opens the text-box editor.
- **D5 (keyboard + panel mirror)** — The Fill forms panel gains one button `#fill-textbox-add` "Add text box" (enabled when `canAnnotate()`); activating it opens the D3 editor at the page centre. The empty-panel sentence (:5777) becomes "No fillable fields on this page. Click the page to type." when `canAnnotate()`, else stays as today. `#fill-textbox-add` joins the accessible-name inventory in `tests/p2-shell.test.mjs`.
- **D6 (drive + STATE, same unit)** — Existing `click {page,x,y}`, `type`, `key`, `drag` drive the feature with no new plumbing beyond: `key Enter` on a `"textbox"` editor commits (:1527-1528 treat only `"add"`/paragraph as newline), `key Escape` closes it, arrows/Delete reach a focused `.textbox-target`. New one-step drive op for agents: `{"cmd":"fill-text","contents":{"page":0,"x":72,"y":300,"text":"Jane Doe"}}` — switches to forms mode, runs the same commit function as the editor (same point rule, same refusals in `error`), one journal op; bad `contents` is refused like every guarded op (Drive guard). It is a known command everywhere commands are listed (`src/main.ts` `startDrive`, the renderer `runEditRequest` chain :1617, `READ_ONLY`/`DEFAULT_EDIT`/`OP_MODE` rules, `docs/agent.md`).
  STATE (new keys only; no existing key changes shape): top-level `fill: { filled: boolean, saveAsCopy: boolean, boxes: [{ id, rect, chars }], last: { op: "add"|"edit"|"move"|"delete", id, rect } | null }` — `boxes` = the FreeText annotations of the shown page in page order, `rect` rounded to 2 decimals, `chars` = contents length (never the text); `last.rect` is null for delete. `direct.active` for the editor: `{ kind: "textbox", annotId, page, point, box, draft }`.
- **D7 (H2: a filled document saves as a copy)** — Renderer state `fillSave: "none" | "needs-copy" | "copied"`, reset to `"none"` whenever a document is opened or closed. It becomes `"needs-copy"` (only from `"none"`) on every successful `field-set` (grep every sender: `commitField` :5912, the panel rows, `smokeForm`, drive `fields`/`form`) and every successful D3/D4/D6 text-box op — unless `doc.name` already ends with ` (filled).pdf` (case-insensitive): such a file is itself a filled copy and keeps plain Save. STATE `fill.filled` = `fillSave !== "none"`, `fill.saveAsCopy` = `fillSave === "needs-copy"`. `saveInPlace` (:9737) sends `api.saveFile(bytes, url, { inPlace: true, filled: true })` when `fillSave === "needs-copy"`.
  `src/main.ts` `save-file` (:617-693): `filled` is validated as an optional boolean (anything else → `unreadable`); `const asCopy = inPlace && (untitled || filled)` takes the existing Save-As route (:659-689): GUI dialog `defaultPath` = `join(dirname(current.path), '<name without .pdf> (filled).pdf')` for the filled case; smoke/drive: `saveToArg` if given, else `{ ok:false, reason:'cancelled' }` (the Bugfix 1 D3b rule — nothing is written). Picking the original's own path is refused by `saveCopy`'s existing `same-file`. On success the window is rebound to the written file exactly as the untitled case is (:681-688), the renderer adopts `result.name` (existing code :9789-9793) and sets `fillSave = "copied"`, so the next ⌘S is a plain in-place save of the copy. Undo history survives. Cancel = "Save cancelled", still dirty, nothing written. `src/preload.cts` :38 changes only the option type (`filled?: boolean`). No new IPC channel, no new reason token. `safe-write.ts` untouched.
  Known flip: `tests/p1-save.test.mjs` :530 (`--edit=form --save-in-place`) now pins the rule — save is `cancelled`, the scratch file's bytes are unchanged; its old output assertions move into the new test (D8 c). Grep for any other fill-then-`save-in-place` pin and flip values in place; list each in the build note.
- **D8 (tests, red before fix)** — new `tests/fill-anywhere.test.mjs` (helpers copied from `tests/bugfix1.test.mjs`, never imported from another test file):
