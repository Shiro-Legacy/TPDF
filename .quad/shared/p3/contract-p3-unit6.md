## 1. Deliverable
In Fill-forms mode the Fields panel gains a designer: add a text, checkbox, dropdown (combo) or radio-group field at a typed position on the current page, then fill it **in the same session** with the existing P2 controls; select an existing field to rename it, move/resize it, change its properties, or delete it. Every action is one undo step. Saved files reopen with valid visible appearances in MuPDF, pypdf and Quick Look. Existing P2 fill behaviour is unchanged.

## 2. Engine seam (ds2) — `src/renderer/engine.ts`
### 2.1 Common rules
- Three new ops, each `requireMutable(session, op)` with `OP_PERMISSION[op] = "edit"` (authoring is a document modification; fill stays `form`).
- Refuse before any COS write (probe Ceiling 4): `info.xfa` → `xfa` ("This is an XFA form; fields cannot be authored"); target widget `scripted` (P2 rule) → `scripted`; target `kind === "signature"` → `signature`; push buttons are never listed, so never targeted. Signed/certified/locked/permission refusals come from `requireMutable` unchanged.
- Validation before the one `mutate`; a refused op never dirties (U1 rule). `failReason` tokens: `xfa`, `scripted`, `signature`, `duplicate-name`, `invalid-name`, `invalid`, `too-many`, `stale-target`, `read-only` (existing).
- **Widget cache (probe Ceiling 2):** every op loads its own page wrapper and destroys it before replying, exactly like `field-set`; `listFields` already reloads. The reply after a create is `{ ok, ...editState, widgetId }` and the renderer re-requests `fields`; never return a `FieldItem` built from the pre-mutation wrapper.
- **Names:** `name` is the full field name, 1–128 chars, no `.` (hierarchy separator), no control chars, trimmed non-empty → else `invalid-name`. Uniqueness is document-wide over the fully-qualified names of the whole `/AcroForm /Fields` tree (depth ≤ 8, ≤ 4096 nodes visited, else `too-many`); a collision → `duplicate-name`. Radio kids share the parent name by design (probe Ceiling 3): they are identified by `widgetId`, never by name.
- **Never written:** `/AA`, `/JS`, `/Names /JavaScript`, `/CO`, `/NeedAppearances`, `/XFA`. An existing `/NeedAppearances` is left as found (the new widgets carry their own `/AP`).
- `/AcroForm` is created when absent: `{ Fields: [], DA: "/Helv 12 Tf 0 g", DR: { Font: { Helv: <Type1 Helvetica WinAnsiEncoding> } } }`; when present, only missing `Fields`/`DA`/`DR.Font.Helv` are added (probe `ensureAcroForm`). Every new widget carries its own `/DA /Helv 12 Tf 0 g`, `/F 4`, `/P`, `/Type /Annot /Subtype /Widget`, and is appended to both `/Fields` (top level; parent for radio kids) and the page `/Annots`.
- **Appearances (probe Ceiling 1):** text/combo → after the page reload `widget.update()`; if no `/AP /N` stream results (empty value), write the probe's minimal border stream (`addTextAppearance` with empty text, `/Tx BMC … EMC`). Checkbox/radio → explicit `/AP /N << /Off <stream> /<on> <stream> >>` (probe `addCheckboxAppearance`: white fill, 1 pt black border, X for the on state), `/AS /Off`. **Acceptance: every authored widget has `/AP /N` immediately after create, before any fill.** Move/resize regenerates the button streams (BBox = new size) and calls `update()` for text/combo.
- Rect: request `rect: [x0,y0,x1,y1]` in the same y-down page space `annot-add` uses (`checkRect(pageBox, …)`), converted to PDF y-up `/Rect`; minimum 4×4 pt else `invalid`. Overlap with existing widgets is allowed (stated). Pages with `/Rotate` are allowed; rect is interpreted in the unrotated page space like `annot-add` (state in the hint).
### 2.2 `field-add`
`{ id, op:"field-add", page, kind:"text"|"checkbox"|"combo"|"radio", name, rect?, options?, maxLen?, multiline?, kids? }`
- text: `/FT /Tx`, `/V ()`, `maxLen` (integer 0–4096, 0 = none → `/MaxLen` omitted), `multiline` (`/Ff` bit 13). combo: `/FT /Ch`, `/Ff` `CH_FIELD_IS_COMBO`, `options` 1–256 strings each 1–256 chars, unique → `/Opt`; `/V` = first option (so the appearance shows something; state it). checkbox: `/FT /Btn`, on-state `Yes`, `/V /Off`. radio: `/FT /Btn /Ff 32768` parent `{ T, FT, Ff, Kids, V /Off }` in `/Fields`; `kids: [{ on, rect }]` 2–32 entries, `on` 1–64 chars, unique within the group, never `Off` → each kid a Widget with `/Parent`, its own `/AS /Off` and states `/Off` + `/<on>`. `rect` is ignored for radio (kids carry their own).
- One `mutate(session, doc, "add field", …)` covering `/AcroForm` creation, `/Fields`, `/Annots` and the AP streams (probe §7 proved undo restores both arrays atomically). Reply `{ ok:true, widgetId, widgetIds? (radio kids), ...editState }`.
### 2.3 `field-props`
`{ id, op:"field-props", page, widgetId, name?, rect?, maxLen?, multiline?, options? }` — at least one property. Resolve by `findWidget` (existing; message prefix becomes the op name). `name` → `/T` on the field dictionary (radio kid → the parent), uniqueness check excludes the field itself. `rect` → `/Rect` + appearance rule above. `maxLen`/`multiline` only on text; `options` only on combo, and if the current `/V` is no longer an option `/V` is set to the first option. Anything else for that kind → `invalid`. Existing (non-authored) fields may be edited too, except `scripted`/`signature`. One `mutate(…, "change field", …)`.
### 2.4 `field-delete`
`{ id, op:"field-delete", page, widgetId }`. Removes the widget ref from the page `/Annots` and from `/Fields` (top-level) or its parent's `/Kids`; a radio kid delete leaves the group; deleting the last kid also removes the parent from `/Fields`. A merged field whose `/Parent` is not a radio group we authored (hierarchical existing form) → refuse `invalid` with "Part of a field hierarchy; cannot delete here" (ceiling, `--fields-unique` note in parent §6). `scripted`/`signature` refuse. One `mutate(…, "delete field", …)`. The page `/Annots` may also list a `/Popup`; never touch other entries.
### 2.5 Fill after create
No new code: `field-set` on an authored widget must work unchanged in the same session (probe §1) — this is the unit's first test.

## 3. UI seam (ds2) — inside `#panel-fields`, below `#field-list`
`<details id="field-designer">` summary "Design fields", shown only when `editable() && permitted("edit")` (hidden on signed/XFA/read-only; XFA hint "This is an XFA form; fields cannot be added"). Two groups:
- **Add:** `#field-new-kind` (select text/checkbox/dropdown/radio), `#field-new-name` (`maxlength=128`), `#field-new-x/-y/-w/-h` (number, pt, y-down like `#content-box-*`; defaults 72, 72, 180, 24; checkbox default 16×16), `#field-new-maxlen`, `#field-new-multiline`, `#field-new-options` (textarea, one per line; shown for dropdown), `#field-new-kids` (textarea, one export name per line, stacked 20 pt apart from x/y; shown for radio), `#field-new-add`.
- **Selected field:** `#field-select` (select of every non-signature field on the page, radio kids as "group · on"), `#field-prop-name`, `#field-prop-x/-y/-w/-h`, `#field-prop-maxlen`, `#field-prop-multiline`, `#field-prop-options`, `#field-prop-apply`, `#field-prop-delete`. Inputs not valid for the kind are disabled. Scripted/signature rows are listed but apply/delete are disabled with the reason (`scripted` text from P2: "Runs a script this app does not execute").
- Announce via `#fields-status`: "Added text field name", "Renamed a to b", "Moved name", "Deleted name", or the refusal. `OP_MODE` for the new ops = `"forms"`. Every refusal token gets text in the existing reason map (`duplicate-name` "A field with that name already exists", `invalid-name` "Names are 1–128 characters without dots", `xfa`, `scripted`, `signature`). After each op `refreshFields()` re-lists so the new field is fillable at once. Keyboard: native controls, Enter on Add/Apply; focus returns to the new field's row after add, to `#field-select` after delete.
- **Drive** (`renderer.ts` drive branch): `{"cmd":"fields","contents":{"action":"add","kind":"text","name":"n1","rect":[72,72,252,96]}}`, `{"action":"add","kind":"radio","name":"g","kids":[{"on":"A","rect":[…]},{"on":"B","rect":[…]}]}`, `{"action":"props","name":"n1","rename":"n2","rect":[…],"options":[…]}`, `{"action":"delete","name":"n2"}`, `{"action":"fill","name":"n2","value":"abc"}` (radio: `"value":"B"` → the kid whose `on` is B). Names resolve to `widgetId` from the current `fields` list (radio kid via `name`+`on`). State: `fieldSummary()` gains `defs: { <name>: { kind, rect:[x0,y0,x1,y1] (y-down, kid rects as `<name>.<on>`) } }` and `last: { action, name, detail? }`.
- `tests/drive/field-design.jsonl`: open `fixtures/hello.pdf` (no fields) → add text `n1`, checkbox `c1`, dropdown `d1` (one/two/three), radio `g` (A, B) → fill `n1`=`abc`, `c1`=true, `d1`=`two`, `g`=`B` → expect `fields.values` → rename `n1`→`n2`, move `c1` → delete `d1` → undo (d1 back) → redo → save-to `${OUT}/designed.pdf` → open `fixtures/form2.pdf` → add `name` → expect `last.detail: duplicate-name` → props on `amount` → expect `scripted` → open grok's XFA fixture → add → expect `xfa`.

## 7. Amendments 2026-09-17 10:40 (fable51, from `objections-p3-unit6-opus5.md` — all 14 accepted; override §2/§3/§4/§6 where they differ)
1. **Rect space:** no hand-rolled `/Rect`. After the COS create and the page reload, the engine finds the new annotation wrapper by object number and calls `setRect(rect)` (y-down page space, identical to `annot-add`); `fields`/drive `defs` report `getRect()`. Same wrapper path for `field-props` rect. grok/sol fixture `form-design.pdf` §4: page 0 `/MediaBox [0 0 612 792]` + offset `/CropBox`, page 1 `/Rotate 90`; test: reported rect equals the requested one ±0.5 on both.
2. **Permission bits:** authoring needs `/P` bit 4 **and** bit 6. `OP_PERMISSION[field-add|field-props|field-delete] = "edit+annotate"`; `permitted()` gains that need (both bits); UI visibility uses the same check. Test on grok/sol's `encrypted-edit-noannot.pdf` (edit bit set, annotate clear): `field-add` refuses `read-only`, `field-set` still fills.
3. **Structural radio parent:** a widget's `/Parent` is an editable radio group iff the parent has no `/Parent`, is directly in `/AcroForm /Fields`, `/FT /Btn`, `/Ff` bit 16 set and bit 17 clear, and every `/Kids` entry is a widget without `/T`. Any other `/Parent` → `invalid` "Part of a field hierarchy; cannot change it here" (rename, props, delete).
4. **Rename:** only a merged top-level field or a structural radio parent (kid → parent). Names are checked as given: leading/trailing whitespace → `invalid-name`, never trimmed. `/T` written with `pdf.newString` (UTF-16BE when non-ASCII); pypdf reads it back in the test.
5. **Appearance regeneration:** on rect/options/maxLen/multiline change, delete `/AP` (`N` and `D`) first, then `update()`, then the empty-value fallback stream if no `/AP /N` resulted. Buttons: rewrite every **existing** `/AP /N` state key with the new BBox (not a fixed Off/Yes), drop `/AP /D`. Ceiling: a resized non-authored checkbox is restyled. Test: resize a filled text field → `/AP /N` BBox equals the new size, dark pixels inside the new rect only.
6. **Shared `/Annots`:** if the page `/Annots` is an indirect object, replace it with a direct copy on this page inside the same mutate before appending/removing. Fixture `form-design.pdf` pages 2+3 share one indirect `/Annots`; test: add on page 2, page 3 unchanged.
7. **Fill over the fallback AP:** the first test proves `field-set` on an authored text field grows the dark pixels inside its rect before save. If MuPDF does not regenerate over the fallback stream, `field-set` clears `/AP` for that widget before `update()` — decided by that test, recorded in evidence.
8. `maxLen` below the current value length → `invalid`, never truncate. Combo options without the current `/V` → `/V` = first option and regenerate per #5.
9. No `/CO` edit on delete (non-scripted fields are never in `/CO`). `/AcroForm` stays even when `/Fields` empties.
10. `too-many` (4096 nodes) is a ceiling in §6 with UI text "This form is too large to design fields in". No caching; `large.pdf` timing test only.
11. Drive `props`: with `"on"` it targets that kid's rect; without, the group (rename/`rect` of a merged field). `defs` re-keys every kid after a group rename.
12. New text `/V ()`; verifier `--fields` expects `''`.
13. `#field-select` lists signature rows disabled (reason `signature`), like scripted rows.
14. `form2.pdf` provenance/README gets one line: no `/Names /JavaScript`, only `amount` is scripted, so other fields stay authorable.
