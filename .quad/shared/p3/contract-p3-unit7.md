## 2. Engine (ds2) — `src/renderer/engine.ts`
### 2.1 Requests
`field-add` and `field-props` gain optional keys: `label?: string`, `readOnly?: boolean`, `required?: boolean`, `default?: string | boolean`. `field-props` "at least one property" check includes them. All validation before the one `mutate`; a refused op never dirties; tokens as U6 (`invalid`, `invalid-name` etc.).
- **`label`**: 0–256 chars, no control chars, checked as given (never trimmed, U6 §7.4). Written to the *field* dict (`renameTarget`: structural radio parent for kids, else the widget) with `pdf.newString` (UTF-16BE when non-ASCII). Empty string → `/TU` deleted. `FieldItem.label` already reads `/TU` via `getLabel()`; unchanged.
- **`readOnly` / `required`**: booleans → set/clear bits 1 and 2 of `/Ff` on the *field* dict (parent for radio kids, where U6 already keeps `/Ff 32768`; never on a kid). Other `/Ff` bits untouched. **Read-only governs fill only:** `field-set` keeps refusing `read-only`; `field-props`/`field-delete` on a read-only field are allowed (else it could never be cleared). `FieldItem.readOnly` already reads it; add `required: boolean` to `FieldItem` (mupdf `getFieldFlags() & 2`).
- **`default`** (`/DV`), per kind, always validated against the *resulting* field (options/maxLen/kids after this same request):
  - text: string ≤ 4096 chars and ≤ `maxLen` when `maxLen > 0`, else `invalid`; `/DV` string; `""` deletes `/DV`.
  - combo: must equal one of the resulting `/Opt` strings, else `invalid`; `""` deletes `/DV`.
  - checkbox: `true` → `/DV /Yes`, `false` → `/DV /Off`. A string → `invalid`.
  - radio: string = one kid's `on` export name → parent `/DV /<on>`; `""` deletes `/DV`; anything else `invalid`. A boolean → `invalid`.
  - `/DV` is written on the field dict (parent for radio). **`/V` is never changed by `default`** on `field-props`. On `field-add` with a `default`, `/V` is set to the same value so the first appearance shows it (state in the hint) — combo keeps U6's "first option" rule only when no `default` is given; button `/AS` follows `/V` (`/AS /<on>` on the chosen kid, `/Off` elsewhere) and `refreshAppearance` runs.
- Scripted/signature/XFA/hierarchy/permission refusals unchanged (`checkFieldEditable`, `edit+annotate`).

## 8. Amendments 2026-09-17 12:45 (fable51, from `objections-p3-unit7-opus5.md` — all 13 accepted; override §2/§3/§5 where they differ)
1. **Field-level read-only token:** `field-set` on a read-only widget → `failField("field-read-only", …)`; new `FieldDetail` token `field-read-only`, `FIELD_DETAIL_TEXT` "This field is read-only". Document-level `read-only` (permission) unchanged. Drive step and test §5.3 expect `field-read-only`. Help matrix names both.
2. **Radio group writes must be visible to MuPDF:** `label`/`readOnly`/`required`/`default` on a radio group are refused `invalid` "Part of a field hierarchy; cannot change it here" when any kid carries its own `/Ff`, `/TU`, `/DV` or `/V`. Test on a pypdf-authored group with a kid `/Ff 0`.
3. **No stale `/DV`:** `field-props`/`field-delete` re-check an existing `/DV` against the resulting field inside the same mutate: `options` without the current `/DV` → delete `/DV`; `maxLen` below the `/DV` length → `invalid` (never dirty); deleting the radio kid whose `on` equals the parent `/DV` → delete `/DV`. One test each.
4. **Raw `/TU`:** `FieldItem.tu?: string` = the field dict's own `/TU` (parent for radio kids), present only when the key exists. `defs.label` and the props prefill read `tu`; `label` keeps its `getLabel() || name` meaning. Verifier `tu` = raw key.
5. **Checkbox default on-state:** `true → /DV /<fieldOn(dict)>` (`Yes` for authored boxes), `false → /Off`. `FieldItem.default` for a checkbox = `/DV` is a name other than `Off`.
6. **Add with default:** put `/AS /<on>` into the create dict (checkbox) or the chosen kid (radio) with the parent `/V` **before** the wrapper loads (`refreshAppearance` keeps an existing `/AS`). Text/combo fallback stream draws `/V` as its text when `update()` yields no AP.
7. **`/Ff` absent stays absent:** if the resulting bits are 0 and `/Ff` was absent, do not write it; if present, write the integer even when 0. Test §5.3 also checks key presence.
8. **`help` op:** not in `OP_MODE`; handled before any doc-dependent branch in `runEditRequest`; open while open and close while closed are no-ops; STATE `help.open` reads `helpDialog.open` live.
9. **Escape:** the document `keydown` handler returns early while `helpDialog.open`; native `<dialog>` cancel + focus restore, no hand-rolled focus trap. Review checks focus return.
10. **Required marker:** `aria-required="true"` on the fill control; the `*` span is `aria-hidden="true"` with `title="required"`.
11. **`/TU` control characters** = U+0000–U+001F and U+007F (same set as names).
12. **Help test:** matches `CONTENT_REASON_TEXT` values against the dialog's text with tags stripped; values stay entity-free; duplicate values need one occurrence.
13. **`defs` "only when set"** = when the key exists in the file (form2.pdf already carries `/DV`/`/Ff`); drive `expect` is a subset match so `field-design.jsonl` is unaffected.
