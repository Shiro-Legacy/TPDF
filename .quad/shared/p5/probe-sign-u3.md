**Facts that bind the contract.** (F1) `FieldItem.rect` (engine `fields`, `widget.getRect()`) and `sign-list.rect` are the same page-space rect the hit layer already uses for `.hit-target` signature buttons (renderer.ts:2404-2411), so no new geometry path is needed. (F2) The signing appearance REPLACES any existing `/AP` of the field (Acrobat does the same); an empty field's own AP is only an "empty box" look. (F3) The adopt path is ~25 lines inside `prepareSignature` (branch on `opts.field`), reusing the AP builder and the `/Sig` dict verbatim; the sentinel/exact-once scan and `patchSignature` are untouched. (F4) A field drawn in the session (unsaved) is signed through `serializeDocument(session)` exactly like any other unsaved edit — the signed file is a new file, the open document stays dirty. (F5) Signed documents are read-only (`requireMutable`), so `field-add`/`field-props`/`field-delete` never reach a signed source; the only write on a signed source is the incremental `sign-prepare {field}`.
