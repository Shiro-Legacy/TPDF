## 0. Ground rules (unchanged from P6 U1–U4)
Proven or refused: every write is proven by the scan or refused with a fixed token and detail. One journal op per gesture, undoable; a refused or no-op gesture never dirties. `garbage=yes` saves. STATE stays truthful after every step (drive is the oracle; `expect` is a subset match, so new keys are safe; never change an existing key's shape — `nav.links` and `fields.defs/values/last` are deep-equalled in tests/p3-drive.test.mjs). Every new engine op joins `OP_PERMISSION` (none is added by this unit: `field-add`/`field-props`/`field-delete`/`sign-prepare` exist). Signing never touches the open document: the signed output is a new file (U1), the session's journal, `dirty` and `revision` are unchanged by a `sign` step.

## 1. Engine (`src/renderer/engine.ts`, `engine-core.ts`, `sign-prepare.ts`)
### 1.1 `fields` — signature items carry `signed`
Every `FieldItem` of kind `signature` gains `signed: boolean` = the widget's field dict has a `/V` (the test `countSignatureField` uses, engine.ts:5129, applied to the widget's own dict and, when absent there, its `/Parent` chain up to 8 levels — a merged field/widget is the common case; hierarchy is a ceiling). Other kinds never carry the key. Read-only; nothing here writes.
### 1.2 `field-add {kind:'signature'}`
`field-add` accepts `kind: "signature"` (the allowlist at engine.ts:3352 and its message become "text, checkbox, combo, radio, signature"). `name` may be omitted or `""` for this kind only: the engine assigns the first `Signature<n>` (n from 1) that no field in the document uses (the U1 rule, sign-prepare.ts:27-30, applied to `existingFields(pdf)`); a given name goes through `checkFieldName`/`checkNameFree` as today. `rect` is required (no default), checked as a text field's rect is, plus the appearance floor: width < 40 or height < 20 pt → `failField("invalid", "field-add: a signature field is at least 40 × 20 pt")`. `label`/`readOnly`/`required` as for text; `default`, `maxLen`, `multiline`, `options`, `edit`, `kids` → the existing "is a … property" refusals. Widget dict: `{Type: "Annot", Subtype: "Widget", FT: "Sig", T, Rect, F: FIELD_F_PRINT, P, DA: FIELD_DA, MK: {BC:[0], BG:[1], R?}}` — **no `/AP`, no `/V`**, `/Ff` from the flags; appended to `/Annots` and `/AcroForm /Fields` inside the one `mutate(session, doc, "add field", …)`; `/SigFlags` is not written (U1 sets 3 at signing time). The reply gains `name: string` (the name used) beside the existing keys. After the op `fields` lists the item with `kind:"signature", signed:false`, `info.signatures` stays 0 and the document stays writable (probe G3).
### 1.3 `field-props` / `field-delete` on an EMPTY signature field
`checkFieldEditable` (engine.ts:2252-2262) refuses `signature` only when the field is signed (`/V` present, §1.1's test): message `${op}: a signed field cannot be changed`. An empty signature field takes `field-props {rect | rename | label | readOnly | required}` and `field-delete` exactly like a text field (one journal op each; `rect` keeps the §1.2 floor with the same `invalid` message; a rename keeps `checkNameFree`). `field-set` on any signature field keeps refusing before any write; its message becomes `field-set: click the signature field to sign it`, and `driveFields` reports it as today's `fields.last {action:'fill', detail:'signature'}` (the plain-Error branch is unchanged in shape — the tests role pins the message only in the new script).
### 1.4 `sign-prepare {field}` — sign an existing field in place
`SignPrepareOptions` gains `field?: string` (absent or `null` = U1's new-widget path, byte-for-byte unchanged). With `field` a string: `rect` must be `null` and `page` the field's page index, else `failReason("invalid", "sign-prepare: a field signature takes rect null and the field's page")`. Check order (each a fixed refusal before any write, `SaveReason` gains `"no-such-field"`): the existing checks up to and including `already-signed` for `certify` on a signed document (engine.ts:3999-4018) → **the certified-visible refusal (4020) is skipped for a field signature** (probe G6: filling an existing field is a permitted P=2 change; a certified P=1 document was already refused at 4015) → page (4021) → `no-such-field` (`sign-prepare: page ${page} has no signature field ${field}`) when no widget on that page has `getFieldType() === "signature"` and the `name` `listFields` reports for it → `already-signed` (`sign-prepare: ${field} is already signed`) when `signed` (§1.1) → `invalid` (`sign-prepare: ${field} is too small for a signature appearance`) when `widget.getRect()` is under 40 × 20 pt. Then `prepareSignature(mupdf, source, opts, incremental)` with the same `source`/`incremental` rule as today (`signedSource` else `serializeDocument(session).bytes` — an unsaved field drawn in this session is therefore signable, probe F4) takes the field branch: find the widget by page + name in the reopened source (the object number is stable across `garbage=yes`, probe G3/G1; the branch fails `invalid` if the name is not found in the reopened bytes), `rect = widget.getRect()` (page space, as the hit layer), put `/AP {N: <U1 appearance stream for rect w/h, /Matrix by /Rotate>}` replacing any existing `/AP` (D2), put `/V = <the U1 /Sig dict>` (hole, sentinel, `/Name`, `/M`, `/Reason`, DocMDP `/Reference` when `certify`), `/AcroForm /SigFlags 3`, `/Perms` when certifying, save with today's option string, `scanSignature` unchanged. The widget's object number is unchanged (asserted in §1.5); no widget is created, `/Fields` is not touched. Reply: today's keys plus `field: string` and `rect: number[4]` (page space). Certify through a field is allowed on an unsigned source (same rules as U1's invisible certify).
