# P2 unit 3 — page organisation: rotate, delete, move, all undoable

Self-contained: read `progress.md` §9 then §1, §6, §7 (P2 paragraphs), `.quad/shared/p2/contract-unit1.md` (spine: ops, journal, dirty, Save, seam), `contract-unit2.md` (edit-request payload, `P2_EDIT`, verify script), `p2-unit2.md`. No new dependencies, no nested agents, never `--no-sandbox`. Claim before editing; hand off with `done:` broadcast + direct message to fable51 with paths and the `npm test` count.

## Why this unit
Rotate a scanned page, drop a blank one, put the cover first: the three page operations every reader needs. They reuse the journal/dirty/Save spine unchanged; the new work is the page tree in the engine, and a renderer that survives its page count and order changing under it. Insert/merge/extract are later units.

## Decisions (fixed)
- Three ops, one journal operation each: `{op:'page-rotate', page, by: 90 | -90}` ("rotate page": page object `/Rotate` = (current + by) mod 360, existing rotation respected), `{op:'page-delete', page}` ("delete page": `deletePage`; refused when the document has one page), `{op:'page-move', page, to}` ("move page": `rearrangePages` with the permutation; refused when `to === page` or out of range). No insert, blank, merge, extract, or multi-select this unit.
- Gate (ds2, tests before UI): the journal must cover all three — `undo()` restores count, order and rotation, `redo()` reapplies; a rotated page's `getBounds()` swaps width/height and its render is rotated; an annotation on a moved page is listed at the page's new index; a deleted page's annotations vanish and return on undo. If the journal does not cover `rearrangePages` or `deletePage`, stop and hand off with the measurement — the fallback is a decision, not ds2's to build.
- Every mutation/undo/redo reply keeps `{ok, revision, dirty, canUndo, canRedo}` and gains `pageCount` and `pages` (sizes after rotation) so the renderer never reopens. ds2 measures the cost of `pages` on large.pdf (500 `loadPage`+`getBounds`) and, if a reply exceeds 50 ms, keeps a cached size list invalidated only by page ops and undo/redo (`ponytail:` comment naming the ceiling).
- Coordinates: MuPDF page space already includes `/Rotate`, so search quads and annotation points stay "what the user sees"; ds2 proves it once on `rotated.pdf` (add a note at the visible top-left, reopen, it is at the visible top-left in Preview — reviewer checks Preview).
- Shortcuts are owned by the menu (unit 1 B3 rule): main gets a **Page** menu — Rotate Right `Shift+CmdOrCtrl+]`, Rotate Left `Shift+CmdOrCtrl+[`, Move Page Up `Alt+CmdOrCtrl+Up`, Move Page Down `Alt+CmdOrCtrl+Down`, Delete Page `Shift+CmdOrCtrl+Backspace` — each `edit-request {op}` with ops `rotate-right`, `rotate-left`, `move-up`, `move-down`, `delete-page`, applied by the renderer to the current page. No confirmation box for delete: it is one Undo away; the status line says so.
- Read-only rule unchanged (signed, certified, encrypted refuse with `read-only` before touching the document).
- Side effects are measured and stated, not fixed this unit: form fields on a deleted page (pypdf `/AcroForm /Fields` dangling refs?), outlines/links whose destination page was deleted. ds2 records what MuPDF does; the reviewer decides if a follow-up is needed.

## A. Engine / worker / renderer (ds2) — `src/renderer/*`, `tests/p2-edit.test.mjs` (or new `tests/p2-pages.test.mjs`)
1. The three ops as above; validation before `mutate` (page integer in range, `by` ∈ {90, −90}, `to` integer in range and ≠ page); the reply slice with `pageCount` + `pages`. Undo/redo replies gain the same two fields.
2. Renderer:
   - `#page-tools` toolbar at the top of the thumbnails sidebar (`#thumbs`, shown when the sidebar is open; also reachable when it is closed via the Page menu): buttons `Rotate right`, `Rotate left`, `Move up`, `Move down`, `Delete page`, each acting on the current page, labelled with it (`aria-label="Delete page 3"` refreshed on navigation); enabled iff writable and applicable (Move up disabled on page 1, Move down on the last, Delete when one page).
   - After a page op or undo/redo: take `pageCount`/`pages` from the reply, rebuild the thumbs (`buildThumbs`), clear the page and thumb caches (revision already changes every key), `clearSearch()` (hit indices are stale), refresh the annotation list, then set the current page: rotate → same page; move → follow the page to its new index; delete → `min(page, pageCount-1)`; undo/redo → clamp. Status line: "Rotated page 3", "Moved page 3 up", "Deleted page 3 — Undo restores it", "Undid delete page".
   - Thumbnails of rotated pages use the new size box.
   - `edit-request` ops `rotate-right|rotate-left|move-up|move-down|delete-page` on the current page; the smoke op `pages` runs a fixed script and logs: on page 1 rotate right; go to page 3, move up twice; go to the last page, delete it; then `P2_EDIT {"revision","dirty","canUndo","notes","annots":{…},"pages":{"count":n,"rotate":[deg per page]}}` (`pages` is the new fixed key). `undo`/`redo` log the same line (with `pages`).
3. Tests: the gate tests above on a 3-page scratch built in the test (reuse `fixtures/textpdf.mjs` or `minipdf.py` for distinct text per page: "one", "two", "three"; no new committed fixture); rotate ×4 returns to 0 and `rotated.pdf` starts from its own `/Rotate`; delete refuses the last page; move refusals; save → validate → reopen keeps order (text per page), rotation (`/Rotate`), and a note on the moved page; every fixture still opens/renders/saves; large.pdf: rotate p1 + delete p500 + move p3→1 timings and reply sizes.
