# Independent review: page font declaration loading

Reviewed `src/font_resources.rs` for resource inheritance, document membership, identity/cache scope, ToUnicode precedence, and cumulative failure work. One diagnostic-context issue was found and fixed by the owner: resolving an indirect Differences element, or exhausting its incoming-name budget, lost the original array index. `FontResourceError.difference_index` now preserves that index without replacing nested Document/ReferenceCycle/Limit errors. Regression tests cover missing-reference and name-budget failures at index 2.

Four independent tests in `tests/review_font_resources.rs` pass; targeted Clippy/rustfmt pass. Malformed CMap parsing consumes reserved entry/payload allowances on every failed attempt, charges decoded source input, and publishes neither fonts nor maps. Successful aliases and distinct fonts sharing one ToUnicode stream share the same immutable Rc map, avoid repeated decoding/parsing, and still charge calls and actual reference work. An authoritative valid map loads despite an unused dangling Encoding reference. Separate loaders with identical object numbers retain their own encoding overrides, including undefined and unknown outcomes.

Code review confirms nearest whole Resources selection (no ancestor Font merging), explicit resolved-null inheritance, bounded page membership from accepted page inventory, ordinary-dictionary requirements, full final indirect identities, and stable direct binding provenance. Type0 and unsupported declarations remain lazy failures, allowing supported selected bindings to load. One-byte horizontal ToUnicode validation is authoritative; a rejected map never falls back. Encoding Differences resolve individual values under session accounting and retain S0 transactional bounds. Stream filter/parameter metadata is preflighted and charged for both traversal and conservative decoder traversal. Decoder failure keeps its reserved work; parser failure or unsupported width/writing mode keeps its reserved parse allowances. Success refunds only conservatively measured unused allowance.

Root owns the independent native inventory/corpus comparison. The corrected measured page scope is 572 resource tables, 582 registrations, 575 successful simple-font bindings and seven Type0 refusals, covering 53 page-bound simple identities: 50 explicit encodings (12,800 slots) and three ToUnicode maps (54 entries). The earlier all-object total of 54 also included an appearance/Form-only font, outside F0; this is a scope correction rather than expanded coverage.

No remaining blocking issue found in the declared mapping-only stage. Returning declared name-derived Unicode does not prove embedded glyph identity, correct Hebrew extraction, font metrics, reading order or text execution. Font loading inside Forms and appearance streams remains separate work. Native resolved-null inheritance differences are documented by the design rather than silently substituted into the strict loader policy.

`tools/mutation-smoke.py` completed 1,600 cases (400 each for `--document`, `--fonts`, `--content`, and `--path`) with seed 2026100309. Input is capped at 16 KiB and each subprocess at two seconds. Document/font mutations include rebuilt valid xref tables and stream lengths around corrupted dictionary, CMap, resource and content payloads, allowing mutations to reach the new layers rather than all stopping at file offsets. All baseline cases passed first. No panic, signal, timeout, non-atomic error output or malformed successful JSON was observed; the binary hash remained unchanged. The slowest case took 0.004144 seconds. Full reproducible input hashes and outcomes are recorded in `reference/mutation-smoke-r9.json`. Acceptance of mutated data is not treated as semantic correctness or native parity, and this bounded smoke test is not exhaustive fuzzing.
