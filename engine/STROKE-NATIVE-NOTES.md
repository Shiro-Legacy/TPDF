# R21 stroke reference policy

This policy is fixed before running R21 production raster results. R19 and R20 source and reference artifacts remain frozen; R21 uses new tooling and reports.

The primary geometric gate is an independent rational model of true stroke membership: analytic line bodies/caps/joins and interval-certified cubic normal-offset boundaries. It never consumes the production expanded polygons. Generated cases cover positive solid widths, each admitted cap and join, closed seams, shear/reflection/nonuniform scale, clipping and paint order. Exact-boundary or unresolved samples are counted explicitly. Each resolved channel is checked against the interval obtained from certified sample colors plus0..255 only for unresolved samples, followed by exact `(sum+8)/16` rounding. Entire uncertain pixels are not blindly excluded; even thin strokes without fully certified edge pixels retain certified ink constraints. The model's device-space uncertainty margin is 1/32 pixel, covering the production's declared 1/64 expansion allowance and later 1/256 quantization with conservative headroom. Exact orthogonal controlled cases avoid boundary samples and require byte equality to both the model and native4xAA0. No general native AA or hinted text parity is claimed.

All 572 readable fixture pages are attempted at 18 DPI. All 43 R20 accepted render pages are additionally checked at 72 DPI, plus stress pages 1, 250 and 500 at 72 DPI. The 500-page stress fixture must have 500 successful Rust renders and native comparisons before its rendering capability is claimed. Width and height are checked independently from native page bounds at each DPI. Existing parser/font/color/dash/hairline/fold refusals remain explicit. A crash, unexpected process exit, partial output, diagnostic on success or malformed envelope is a gate failure, including when the other side reports an expected refusal.

Native rendering uses original native path commands and their saved full affine matrix. Stroke width, caps, joins and miter limit are applied in user space by MuPDF, then the full affine transform is applied once. It does not pretransform the centerline and substitute an isotropic device width. Glyph fills use the independently extracted unhinted canonical outlines retained by R20. Native rasterization is recorded at 4x with AA0 plus integer box resolution, and separately at target size with AA8.

Pinned MuPDF `draw-device.c` sets effective stroke width so `width * expansion >= max(configured_minimum, 2/(AA_level+2))`, with `expansion=sqrt(abs(det(CTM)))` (and its tiny-expansion fallback). Its flattening tolerance is `max(0.001, 0.3/expansion)` in user units. The wrapper explicitly sets configured minimum width to zero. Every diagnostic records which events native would widen; width clamping is a native policy difference, not a production geometric model. The stress fixture's 1-unit curve is exactly one native supersample pixel at18DPI/4xAA0 and is not enlarged by that minimum.

For arbitrary native stroke curves and slants, differences are diagnostic and must lie within a predeclared conservative boundary region. Native minimum-width widening and native flattening are recorded separately from the independent geometric certificate. The existing R19 one-device-pixel fill boundary band remains unchanged for filled glyphs/paths. For strokes, an independent true-stroke model queries each pixel center with device margin `1.5 + affine_Linf_norm * (maximum_native_user_flatness + maximum_half_width_increase)` across the4xAA0 andAA8 runs. Unknown certificates form the diagnostic band; the1.5term combines a half-pixel box and the existing1pixel diagnostic distance. This is a fixed investigation threshold, not a theorem about native curve flattening. Conservative component certificates can also mark internal seams, so uncertainty counts are reported. The band is derived from original path/style/native policy before examining any mismatching pixels, and never from production polygons. A16-entry immutable cache amortizes repeated stress-path masks while every page pixel output is still compared.

The new native wrapper remains font-free and resource-free. Input is at most4MiB, dimensions at most4096, pixels at most16,777,216, heap128MiB, lexical work500,000tokens, graphics depth128 and CPU/wall30/45seconds. It accepts only the required filled/solid-stroked geometry vocabulary, validates full state before rendering, rejects warning/recovery, and publishes pixels only after success. Meaningful dash patterns and text/resource loading are excluded from this raster wrapper.


## Reference artifacts and implementation

The fixed policy is archived separately as `reference/stroke-raster-policy-s0.json` and `reference/stroke-raster-policy-notes-s0.md`. Final source maps include the immutable policy, while this note can add measured results. `tools/build-stroke-raster-reference.sh` verifies the pinned PDF lexer/interpreter, draw-device/path/rasterizer/paint/blend implementation and affine geometry helper before linking the separate `mupdf-stroke-raster-oracle`. Previous native raster tools and reports are unchanged.

`tools/stroke_raster_reference.py` emits each original stroke inside an isolated graphics save with the complete saved matrix, original width/cap/join/miter and original user-space path. Filled paths and unhinted glyphs retain their prior independently extracted geometry. `tools/stroke_raster_model.py` composes the independent review model's sample certificates with exact clip masks, opaque event order, and integer resolution. `tools/stroke_raster_cases.py` supplies24 controlled orthogonal cases,24 analytic line cases,24 join/seam cases,24 true-cubic cases,2 native minimum-width diagnostics and12 clipping/paint-order cases.

The independently certified stroke diagnostic mask is cached by exact path, transform, style, canvas and margin, with at most16 cached byte masks and a2,000,000-pixel per-mask bound. Cache reuse never skips a page render or pixel comparison. Generated sample modeling is bounded to64x64, with32million logical work,200,000 interval nodes and100,000 queries per stroke. Corpus diagnostic membership uses64million work and200,000 queries per stroke. A model resource or domain refusal fails the gate; it cannot silently become an accepted production refusal.

Validation has seven positive checks,53 rejected mutations,33 native wrapper checks and three actual Rust atomic-suffix refusals. Real rendered PDF mutations alter width, cap, join, full-affine width behavior, paint color, clipping and the closing seam, then compare against the original independent certificates. Thin-curve deletion is rejected even when all ink pixels contain uncertain samples. Invalid native-wrapper cases require their exact documented exit: semantic/preflight failures use2 and a nonempty `stroke raster oracle:` diagnostic; argument/input-limit failures use1. Signals and unexpected exit codes are explicitly rejected.

## Explicit post-observation color-policy amendment

The first complete R21 run failed the original outside-geometric-band check on every stress page. The native orange rectangle was `(229,102,51)` while Rust produced `(230,102,51)`. Raw outside-band differences were157 pixels per18DPI stress page (78,500 total) and4600 per72DPI representative (13,800 total). Investigation reproduced this with a standalone native `.9 .4 .2 rg` rectangle. Pinned `draw-device.c` `resolve_color`, including line634, assigns `colorbv[i] = colorfv[i] * 255`, truncating toward zero; the engine's previously declared R19 policy rounds to nearest. This is a color conversion policy difference, not evidence that the stroke geometry band should expand.

The reviewed amendment is separately frozen in `reference/stroke-color-policy-s1.json`. It was adopted after observing that discrepancy; the original `s0` policy and notes remain unchanged. `tools/stroke_source_color.py` supplies a deliberately narrow independent certificate for the pinned self-authored stress PDF. It validates the complete input digest, indirect page tree, each content reference and stream length, and tokenizes literal strings, names, exact rational numbers and operators. The prefix admits only balanced text operations. The entire remaining stream must structurally be the expected blue line, exact orange opaque rectangle, then the green cubic and end of content. No matrix, clipping, graphics-state, text-clipping or later-paint operator can hide in the prefix or tail. The native state/path records are checked against that independently parsed structure.

For each candidate pixel, the full pixel box must be strictly inside the exact source rectangle. The independent true-cubic model must certify exclusion from the only later paint using the unchanged native-policy diagnostic margin. Earlier text is overwritten by the opaque rectangle. The exact pair is computed independently from source operands `9/10,2/5,1/5`: the target rule gives `(230,102,51)` and pinned native float-to-byte truncation gives `(229,102,51)`. Every certified pixel must match both exact colors, even if Rust/native happen to agree on the same incorrect color. An unchanged-looking equality cannot bypass the proof.

Raw native difference counts, bounds and outside-band totals remain in the final report. Exact source-color classification and proof-violation counts are separate fields; every other outside-band discrepancy fails. There is no global plus-or-minus-one channel tolerance and no enlarged geometric band. Mutation tests reject changed source color/rectangle/order/clip/matrix/graphics-state/text-clipping/later paint; wrong Rust/native/channel pairs; the same pair outside the certified region; altered native geometry/clip/later curve; and source or baseline-report digest tampering. Independent review found no blocker in this bounded classification. Acceptance combines independently certified geometry/color behavior with explicitly scoped native diagnostics and does not claim general native pixel parity.

## Final measured R21 gate

The frozen CLI completed the final amended gate in 309.05 seconds with four bounded corpus workers. All 110 generated pages passed: 36 matched the independent baseline bytes and 74 satisfied certified channel intervals. The 24 controlled orthogonal cases matched the independent model and native 4x output exactly. Across 7,040 generated pixels, 1,456 stroke samples remained uncertain in 700 pixels; 10,709 inside samples and 118,871 outside samples were independently certified. The compositor imposed 4,694 certified nonwhite channel constraints and observed zero channel-interval violations. Its uncertainty baseline differed at 510 pixels; these were checked against sample-derived channel bounds rather than discarded. The model made 161,792 stroke queries with 9,498,277 logical work and 18,642 nodes. Native 4x and AA8 differed from Rust at 516 and 1,452 generated pixels respectively, all within the fixed diagnostic band. Each native mode widened two explicitly identified thin-stroke events.

All 572 readable fixture pages were attempted at 18 DPI: 543 rendered and passed the scoped native diagnostic comparison, and 29 produced explicit refusals. All 500 stress pages rendered successfully. The 43 pages accepted by R20 were preserved at 72 DPI, and stress pages 1, 250 and 500 also passed at 72 DPI. These are 618 corpus invocations, comprising 589 successful renders over 38,644,128 pixels and 29 refusals. The additional 72 DPI runs are repeated pages, not extra fixture coverage. No corpus stroke triggered native minimum-width widening.

That certificate verifies the exact Rust/native pair at 120,733 interior pixels per mode, including pixels inside the geometric band. There were zero source-proof violations and zero unexplained outside-band differences. The acceptance therefore establishes the declared independent geometry/color contract plus bounded native diagnostics; the reported native differences are not pixel parity. The 29 native refusal categories were 19 operators outside C0, five font subtypes outside PP1, four inputs outside the C0 lexical subset, and one unclosed text/graphics state. Rust refusal diagnostics remain in each report row.

All 589 rendered corpus rows have identical Rust PPM, native 4x RGB, native AA8 RGB, native trace and input hashes between the original failed run and the amended rerun. The amendment changed classification only. The original failed report remains at `/private/tmp/r21-raster-final.json`; final raw evidence remains under `/private/tmp/tandem-r21-raster-evidence`. The final differential report has 18 verified evidence hashes; the validation report has 17. Validation passed seven positive checks, 53 rejected mutations, 33 native wrapper checks and three real Rust atomic-suffix refusals. All evidence hashes were rechecked after saving the final report.

Remaining scope limits are explicit: the complete corpus was checked at 18 DPI, with the declared prior-page and stress subset at 72 DPI. Dashed, zero-width, degenerate and unproved folded/cusped strokes remain outside this increment. Independent curve certificates can conservatively remain uncertain at component seams; a model domain/resource refusal fails the gate rather than silently accepting a production result. Native hinting, AA, flattening and color-conversion policies are not generalized into exact rendering parity.
