# R23b image loader implementation contract

2026-10-06. The user explicitly authorized continuation until the full Rust rebuild is complete or stopped. Implement the document-bound opaque Gray8/RGB8 image loader specified in R23-IMAGE-PROPOSAL.md. The R23a sampling checkpoint remains preserved; no dependency or app change.

`ImageLoader::new(&Document, ImageLimits)` binds immutable document identity and cumulative ceilings. `begin_page(ImageLimits)` intersects remaining session capacities with new per-page capacities; it never resets usage or caches. `load(ObjectId)` requires an actual indirect image stream in that bound document and returns `Arc<ImageAsset>`. Later scoped Do resolution supplies this authenticated ID; direct loading is also useful for independent decode tests. Assets own compact samples, exact dimensions, component layout, Decode inversion flags and typed filter metadata. Sampling returns checked RGB values without expanding Gray storage.

Prepare FilterSpec descriptors once through the loader's metered metadata resolver, then call the existing low-level decoder. References have a hard 64-hop bound and cycle checks; stream-valued metadata is invalid. Unknown filter names do not allocate cloned diagnostic data. The existing stream-object decoder remains unchanged; there is no duplicate unmetered metadata traversal. Fixed-key lookups and parameter iteration charge conservative string-comparison work and metadata items before visits.

Structural caps: dimensions 16384; pixels 4194304; row bytes 49152; retained per-image samples 12 MiB; 8 filters; per-stage 16 MiB; cumulative decode phase 64 MiB. Configurable limits may tighten but cannot exceed these structural values. Eight-bit nonidentity predictor metadata must match image width/components, and decoder validation still applies to identity predictor metadata. Positive dimensions and exact final length are mandatory. Masks, interpolation, nondevice color, external sources and other listed unsupported rendering semantics refuse. SMaskInData 0 is allowed; nonzero refuses. Type, when non-null, must be XObject.

The twelve cumulative counters are attempts, unique images, metadata items, reference hops, lookup work, encoded bytes, decoded work bytes, decoded rows, decoded pixels, retained samples, allocation reservations and retained filter specs. Per-page caps are absolute ceilings derived from the start usage and intersected with session caps. A cache hit rechecks the current structural caps and charges lookup/attempt work, without fictitious repeated decode. Validated output only enters the cache after exact length and storage admission. Failures preserve all admitted attempts, intended row/pixel/sample reservations and allocation reservations.

Before decoding, reserve remaining bounded decode work and three times the sum of possible output-stage capacities for allocation. Each filter and nonidentity predictor is one output stage (identity-copy is one). `Budget::reserve` grows geometrically with a possible last cap-truncated allocation: sum of requested capacities is below three times that stage's admitted output cap, including Flate's initial speculative buffer and predictor output. Reserve metadata/filter/Arc/cache storage separately. Retain allocation reservations conservatively; after successful decoding only decoded-work unused capacity is refunded from DecodeUsage's measured intermediate-output count. Failed decoding retains the whole reservation. This is a logical conservative reservation ledger, not actual RSS. Known identity copies use their exact length as their stage/total cap. All arithmetic is checked and defaults fit 32-bit wasm.

Required verification: actual PDF dictionaries/references, every lossless filter, both LZW EarlyChange modes, TIFF/PNG prediction, inverted/normal component values, malformed/extra/truncated data and metadata, caches with stricter later limits, owned lifetime, exact/one-less counters and repeated failures. Native decoded-byte evidence and page integration remain required for whole R23 acceptance.
