## Latest accepted milestone: R17 embedded glyph selection

The new allocation-free format4 TrueType cmap reader validates an explicitly
selected record and every covered GID before publishing it. Record identity and
absolute font-byte ranges are retained. It does not guess an encoding policy.

The separate PDF loader owns FontFile2 bytes and requested-font/resolved-program
identities. It implements the supported symbolic, Unicode and MacRoman selection
branches with raw-byte seeds, private-use retry and explicit encoding overrides.
ToUnicode is never read for glyph selection. Potential unimplemented name-table
or fuzzy fallback is an explicit per-code unsupported result. GID0 is missing;
it is not silently turned into a rendered replacement glyph.

`EmbeddedOutlines` binds each map to its own validated immutable font. Source
bytes can be decoded through existing O0 unhinted simple outlines, with missing,
unsupported and valid empty nonzero glyphs distinguished. Failed code attempts
and failed stream reservations remain bounded by their explicit budgets.

New inspection commands: `--tt-cmap=all` or `--tt-cmap=N` for raw font records,
and `--font-glyphs=N:G` for all256 slots and supported outlines of a PDF font.
Output is atomic under the existing cap. This does not execute page glyphs or
render text pixels. No native runtime dependency or additional font is bundled.
Design: `GLYPH-SELECTION-DESIGN.md`; review: `REVIEW-R17-G0.md`.
