# Annotations op group (annots, annot-add, annot-set, annot-move, annot-delete)

October 15, 2026. Design notes and every difference from MuPDF 1.28.1 and engine.ts for the annotation ops on `AppSession`. Read with `../APP-ENGINE-DESIGN.md`.

## Layout

- `src/app/annots/mod.rs`: helpers every group that touches annotations shares (redaction next).
  - `PageSpace::of(doc, page)`: MuPDF page space (y down, top left of the bound page, /Rotate and /UserUnit applied), computed as the view's `PageFrame`. `to_page`/`to_user` for points, `rect_to_page`/`rect_to_user` (MuPDF `setRect`: bounds of the transformed corners), `quad_to_user` (corner order kept), `bounds()` (MuPDF `getBounds`), `upright()` (the rotation that turns content upright on the page).
  - `list(doc, page) -> Vec<Annot>`: MuPDF `getAnnotations` (Links, Popups, Widgets and entries without a /Subtype name left out; an object listed twice listed once). `Annot { id: Option<ObjectId>, dict, subtype }`, `number()` is the app id (object number, generation ignored; 0 for a direct dictionary). `find(doc, page, number)` matches only object numbers > 0.
  - `add(target, page, dict) -> ObjectId` (new object appended to /Annots), `append(target, page, id)` (after `own_annots`: a page whose /Annots array other pages list gets its own direct copy first, `app-accept-annots.md`), `edit_annots(target, page, |items|)` (the array in its own object, in the page, or in a page written into /Kids), `put_appearance(target, &mut dict, &form) -> ObjectId` (the form as a new stream, /AP /N pointing at it; a FreeText's CJK fonts become objects), `remove(target, page, id)` and `remove_many(target, &[(page, id)])`. All generic over `edit::Edit`, so a journaled `Transaction` or a `Builder`.
  - `remove_many` takes any number of annotations on any pages with one `pagetree::cut_references` pass (redact-apply's 2,000 marks, edit-batch's deletes): each, the /Popup it names when that is a Popup whose /Parent is it or absent, and any Popup on its page naming it as /Parent leave that page's /Annots; every other reference to those no page lists any more is then cut (`cut_unlisted`, shared with link-delete: app-core.md). The catalog, page-tree nodes (in the tree, or typed /Page or /Pages) and streams are never cut, whatever names them: listed as an annotation, such an object only leaves the page's /Annots. `AnnotError::NoPage` for a page index out of range.
  - Readers: `Color::read` (MuPDF `pdf_annot_color`: 1, 3 or 4 numbers), `rect` (`pdf_to_rect`), `quads`, `points`, `ink_list`, `line_points`, `border_width` (/BS /W, else /Border[2], else 1), `border_dash`, `opacity` (/CA), `text` (/Contents, /Subj decoded), `rect_differences` (/RD, ISO order), `inset(rect, rd)`, `design_rect` (/Rect less /RD for every kind, MuPDF `pdf_annot_rect`), `grow_by_rd` (its inverse: the /Rect whose design box a moved rect is), `page_rect` (the `annots` reply box, engine.ts `annotRect`; for an annotation the view synthesizes, the /Rect and /RD that synthesis derives, as MuPDF lists it).
- `src/app/annots/appearance.rs`: Form XObjects as MuPDF's `pdf_update_appearance` writes them: `note` (eight icons, others Star), `highlight`, `text_line` (Underline, StrikeOut, Squiggly), `rectangle` (Square, Circle), `line` (with the line endings), `poly`, `ink`, `stamp` (MuPDF's label table) and `icon_fit` (its 190:50 box fitted inside the rect), `image_stamp`, `caret`, `redact`, `free_text` and `free_text_lines` (MuPDF's `write_variable_text` runs through `forms::scripts`, `app-accept-annots.md`). Each returns the `Form` (/BBox, /Matrix, /Resources, content) and, where MuPDF derives it, the /Rect. Numbers are printed by `serialize::compact_real` (MuPDF's `fz_grisu` printing of the float), so a content stream is byte-identical to MuPDF's for the same geometry wherever MuPDF's own float arithmetic agrees.
- `src/app/annots/fonts.rs`: WinAnsi encoding (`win_ansi`, `encode`) and the Helvetica, Times-Roman and Times-Bold advances of codes 32..255 measured from MuPDF's base-14 fonts (Courier 600); DA font names (Helv, TiRo, Cour, HeBo, ...) map to `Base14`.
- `src/app/annots/view.rs`: `synthesize(doc, annot)` (the appearance MuPDF makes from an annotation's entries), `synthesized_box` (the /Rect and /RD that synthesis derives, for the listing) and `fix`, which `view_fixes` calls for every annotation View usage draws.
- `src/app/ops/annots.rs`: the five ops, engine.ts's checks in its order with its messages; `default_appearance` (/DA parsing, Helv 12 black by default) and `free_text_form` (laid out in /Rect less /RD) are public for the forms group; `find_annotation` (engine.ts `findAnnotation`: "<op>: id must be an integer", "<op>: no annotation <id> on this page") is `pub(crate)` for redaction and edit-batch.
- Shared files: `ops/mod.rs` routes, `app/mod.rs` module, `serialize::compact_real` made `pub(crate)`, `ops/pages/images.rs` gained `store` (the image objects `add_page` wrote, now reusable), `overlay::NewStreams` and `join_redefined(.., streams)` (the view's redefinition update can add streams), `view_fixes::redefinitions` returns the streams too, `document.rs` passes them. The adapter adds `today` (the worker's local `YYYY-MM-DD`) to `annot-add` requests.

## Ops

- Every write is one `AppSession::mutate` step through `Transaction`; refusals come before it, so nothing is journaled. Step names as engine.ts: `add note`, `add text box`, `add highlight` (`add <type lowercased>`), `add signature`, `add drawn signature`, `edit annotation`, `move text box`, `move signature`, `resize signature`, `delete annotation`.
- Object numbers: the annotation first, then (a note) its popup, then images, then the appearance, as MuPDF numbers them (note 6, popup 7, appearance 8 on hello.pdf).
- Dictionaries in MuPDF's key order and values (/F 4, a note /F 28, colours, /BS /W, /RD for Square, Circle and Ink, /QuadPoints in MuPDF's corner order, flipped to user space, /L, /InkList, /DA `(/Helv 12 Tf 0 0 0 rg)`, a FreeText's /Rotate on a rotated page). No /T, /M, /NM or /CreationDate, as MuPDF.
- `annot-set` sets /Contents (removing /RC as MuPDF does) and writes a new FreeText appearance; the refit is engine.ts `freeTextFit` from the current top left. `annot-move` keeps a FreeText's size; a drawn signature's strokes are rescaled and its width and appearance recomputed; an image signature changes /Rect only (its unit-box appearance stretches).
- Appearances are new stream objects; the previous one becomes unreferenced (a save drops it; undo restores the reference).

## View (display only, never saved)

- An annotation without a normal appearance, of a kind `synthesize` draws (Text, FreeText, Highlight, Underline, StrikeOut, Squiggly, Square, Circle, Line, Polygon, PolyLine, Ink, Stamp, Caret, Redact), gets one in the view's redefinition update, with the /Rect and /RD MuPDF derives: a note 20 x 20 at the top left of /Rect, a stamp the 190:50 icon box fitted inside /Rect about the centre (user space; before the acceptance fixes it kept the width, which MuPDF does only for rects narrower than 190:50), a caret 20 x 14 about the centre, a Square or Circle without /RD half its border as /RD, a Redact mark its quads grown by a point. `annots` lists that box and `annot-set` writes it, as MuPDF (measured on 1.28.1: getRect and the saved /Rect and /RD). MuPDF synthesizes into its local xref; neither save writes it until the annotation is edited (measured: MuPDF's `garbage=yes` save of such a file has no /AP).
- hayro maps an appearance onto /Rect with the translation left unscaled (`rect.x0 - box.x0` where ISO 32000-2 12.5.5 gives `rect.x0 - box.x0 * scale`), so a transformed box off the origin drawn at another scale (a stamp turned upright on a rotated page, a foreign /Matrix or /BBox) lands displaced. The view then draws it through a wrapper form at scale 1 (identity /Matrix, /BBox the placed box) whose content invokes the appearance under the correct placement. Widgets are left to the forms group (`fix` skips them; the same wrapper would serve).
- A Text annotation, or one flagged NoZoom, is drawn at its appearance's own size with /Rect's top left fixed (MuPDF draws a 16 x 16 note icon in a 20 x 20 rect at 16 x 16, which hayro stretched). A Text annotation, or one flagged NoRotate, on a rotated page stays upright, turned about that corner: a wrapper form invokes the appearance under the counter-rotation (ISO 32000-2 12.5.3; MuPDF draws both).
- Hidden, NoView, Popup and /OC-off annotations get nothing. One view synthesizes at most 100,000 appearances and 32 MiB of content; one synthesized appearance draws at most 16,384 quads and 131,072 points, and a Squiggly's zigzags take at most 32,768 points together (beyond that its steps widen from MuPDF's h/7 so every quad keeps a zigzag; MuPDF's are unbounded. Measured through the adapter, render at 0.25 of one Squiggly of 590 x 0.001 quads: 80 quads (3.5 KB) took 26.8 s and 709 MB of WASM memory before, 50 ms and 30.5 MB now; 600 quads (23 KB) 60 ms).
- An /Annots array object several pages share is fixed once, for the first page listing it (its direct annotations follow that page's rotation); before, every page re-fixed every item, quadratic in pages times items. (The view build stays quadratic for such files in code outside this group: 4,000 pages sharing a 4,000-item array take 8.4 s, 8.6 s at the parent commit.)

## Measured

`reference/app-annots-20261015/summary.json` (`tools/compare-annots.mjs`): MuPDF draws every Rust-written appearance exactly as it draws its own (100% of pixels at scale 2) for all 25 created kinds and variants on unrotated pages but one (FreeText move, below), and for the edits of foreign FreeText with a symmetric /RD, a bare Stamp and a bare Text. `viewOfOwnSave` (Rust's view against MuPDF drawing Rust's own save) measures the view regardless of deliberate differences: on pages turned 90, 180 and 270 icon stamps 89.5% exact (as unrotated: the label's text rasterization), image stamps 100% within 16 levels, signatures 78.8% (the gray image's resampling, as unrotated). Foreign appearances with a turning /Matrix, a /BBox off the origin or a translating /Matrix: 100% against MuPDF. Bare Caret 93.5% (curve antialiasing, as Circle), bare stamp in a square rect 89.5% (text). Rust's own render against MuPDF's, in the annotation's region: Text, rotated Text, Square at scale 2, MuPDF-made notes and AP-less Square and Redact 100% exact; Highlight 98.8-99.4%; Underline, StrikeOut, Line, Ink, Polygon, PolyLine 88-99% exact and 99.9-100% within 16 levels; text-bearing kinds (FreeText 62-83%, icon Stamps 81-94%) at the level of plain page text in the same fonts (controls 65-86%), which is hayro's base-14 rasterization; image stamps by resampling (100% within 16 for RGB, the gray signature image 61-79%). Costs (WASM, large.pdf page 250): add 3-11 ms, set 5 ms, delete with references cut 8 ms, undo 5 ms.

## Differences from MuPDF and engine.ts

- FreeText: no /CL (MuPDF writes a callout line from the page corner nothing draws) and no /RD [0 0 0 0].
- A FreeText appearance is laid out in /Rect less /RD with /Rect, /RD and /BBox kept; MuPDF's update shrinks /Rect to that inner box, sets /RD [0 0 0 0] and uses the inner box as /BBox, dropping the margin a callout (Acrobat's FreeTextCallout) draws in. The box is drawn identically (measured 100% with a symmetric /RD). Lines wholly below the box, which its clip hides, are not written (MuPDF writes them).
- Image stamps carry no /Name /Draft and no /C [1 0 0] left from MuPDF's Stamp defaults. PNG samples are Flate-compressed, JPEG kept as DCT (MuPDF stores samples unfiltered). The JPEG EXIF orientation is applied in the appearance (MuPDF places the stored pixels). An identical image is shared with the stamps that already show it (`app-accept-annots.md`); MuPDF reuses one XObject per image digest across the whole document.
- A note's popup opens beside the note (top right of the 20-point icon, 200 x 100, moved inside the page); MuPDF puts every popup at the page's top left corner ([32 12 232 112] in page space).
- On a rotated page an icon stamp takes the 190:50 aspect in page space (as the user sees it) and its appearance's /Matrix turns the label upright; an image stamp's /Matrix turns the image upright. MuPDF fits the aspect in user space and draws both turned with the page.
- FreeText text takes MuPDF's fonts: WinAnsi in the DA font, Greek and Cyrillic in its re-encoded `<DA>GRK`/`<DA>CYR`, Han, kana and Hangul in the non-embedded CJK fonts; Latin letters WinAnsi lacks in `<DA>LAT` (MuPDF embeds a Nimbus Sans program for those); `?` for what none has (`app-accept-annots.md`; before, every non-WinAnsi character was `?`). CR LF is one line break (MuPDF breaks twice). Callout lines and rich text are not drawn.
- FreeText and widget text (`forms::scripts::drawn`, round 3 of `app-accept-annots.md`): default-ignorable code points (zero-width spaces and joiners, the byte order mark, variation selectors, other format characters), C1 controls and U+2028/U+2029 draw nothing, as in MuPDF; a combining mark after a letter is composed with it when a font has the composed letter (NFD text such as macOS file names: e + U+0301 is é, z + U+0307 is ż, s and t + U+0326 are ș and ț, Greek tonos and dialytika, Cyrillic й, ё, ї), where MuPDF draws the base letter and nothing for the mark; a mark that composes with nothing is `?`. A no-break space and a soft hyphen are WinAnsi 0xA0 and 0xAD in the DA font, as MuPDF writes them.
- FreeText /DS (default style) is not applied when the appearance is regenerated: the DA governs font, size and colour. MuPDF's rich path takes the DS colour and size (and sets the baseline about 1.1 pt lower). Corpus (round 3, the review's diag4/diag5): 35 of 313 FreeTexts carry /DS, 9 of them with a DS colour other than the DA's (2 files: pdfjs `file_pdfjs_test.pdf` 851fb6bfa414, `freetexts.pdf` fe9585ddd465); the original appearance used the DA colour in 5 of those 8 cases, so the edit keeps what most of them showed.
- DA font names beyond MuPDF's five (Helv, TiRo, Cour, Symb, ZaDb): HeBo, HeOb, HeBO, TiBo, TiIt, TiBI, CoBo, CoOb and CoBO draw the named base 14 face (`fonts::Base14::from_resource_name`), where MuPDF's `full_font_name` falls back to Helvetica; /Symb and /ZaDb draw Helvetica, where MuPDF draws Symbol and ZapfDingbats glyphs for the text's codes. Kept: the author's chosen style shows, and typed text stays readable rather than turning into symbols (the review measured 40-56% different renders; ed62a16 the same).
- `annot-set` keeps an existing appearance except a FreeText's, and writes one when there is none; MuPDF regenerates every kind it synthesizes on any contents change, replacing a foreign annotation's own appearance (a custom note icon, a scanned highlight).
- `annot-move` of a FreeText moves /Rect and keeps its appearance, which maps onto the new rect; MuPDF regenerates it, losing a foreign box's rich text. MuPDF draws the two 82% pixel-identical (sub-pixel text phase).
- `annot-move` of a signature whose geometry is empty (a drawn signature without stroke points, whatever its /Rect; a stamp without /Rect) is refused ("this annotation has no geometry to move"); engine.ts computes NaN. A stamp signature's box is /Rect less /RD both when read and when written, so moves keep its size (MuPDF's getRect and setRect).
- `annot-delete` cuts every reference to the annotation and its popups once no page lists them, so no save writes them (a reply's /IRT, a structure OBJR); another page that lists it keeps it whole (app-core.md); MuPDF removes it from the page's /Annots only, so `garbage=yes` still writes it when anything else reaches it. A /Popup naming anything but a Popup annotation of its own (another annotation, a Popup whose /Parent is another note, the page) is left alone; MuPDF takes whatever it names out of the page's /Annots.
- `annots`: an object listed twice in /Annots is one item (MuPDF lists it twice); an entry without /Subtype is skipped and an unknown subtype is reported by its name, not editable (MuPDF reports both as an editable "Text"); a direct dictionary is listed with id 0 and is not editable or addressable (in MuPDF id 0 names the first direct one).
- `annots` rect: Polygon and PolyLine report their vertices' bounds, and a markup without /QuadPoints or a Line or Ink without points reports /Rect less /RD (MuPDF: an empty rect). /RD is read in ISO order (left, top, right, bottom); MuPDF normalizes it as a rect, which differs only when its top and bottom differ (measured: a FreeText with /RD [20 10 30 40] drawn 91% alike). A FileAttachment or Sound without an appearance lists its /Rect; MuPDF synthesizes its icon and lists 20 x 20 at the top left.
- Reply numbers are doubles (`192.8`); MuPDF's are float32 (`192.79998779296875`).
- The signature appearance's date comes from the adapter's `today` (the worker's local date, as engine.ts); a native caller without it gets the UTC date.
- `sign: null` is refused as a bad signature name; engine.ts throws JavaScript's TypeError text. An unreadable stamp image says "the app" where engine.ts said "mupdf", with the Rust decoder's reason.
- The view draws no synthesized FileAttachment or Sound icon (MuPDF does). Squiggly zigzags, synthesized quads and points are bounded (View, above).
