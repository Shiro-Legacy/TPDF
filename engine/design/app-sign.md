# App ops: sign-list, sign-prepare, incremental save

October 15, 2026 (review fixes the same day). `src/app/ops/sign.rs` (sign-list, sign-prepare's checks), `src/app/ops/sign/prepare.rs` (sign-prepare.ts `prepareSignature`), `src/app/ops/sign/widgets.rs` (page transform, widget rects, field names) and the core writer `src/incremental.rs`. Tests: `tests/app_sign.rs`.

## Design

- **Neither op journals or writes the session document.** sign-list reads it; sign-prepare edits a private copy (`Document`, no journal) and returns bytes. Revision, journal position, undo/redo state, content state and snapshot bytes are unchanged after every reply, success or refusal (tested).
- **sign-list** checks in engine.ts order: no document, locked (`encrypted`), encrypted with a `/FT /Sig` node within 8 levels (`encrypted`), the field walk (`too-many` past 4096 visits), any signed entry without `signed_source` (`too-large`). Entries are engine.ts's: `{field, page (1-based, 0 = no widget), rect (getRect, float32, y down) | null, empty}`, plus `status/reason: unsupported/malformed` or `subFilter, filter, name?, reason?, location?, contact?, m?, byteRange, contents, docmdp?`. `certified` is the last DocMDP reference's `Number(P) || null`; `versions` counts xref sections as `detect` does; `bytes` is a copy of the retained source.
- **`contents` crosses as `{"$bytes": n}`**, a new reply marker: an output buffer the adapter hands over as a `Uint8Array` (engine.ts's `asByteString()`; `verify.ts` requires `instanceof Uint8Array`). `{"$buffer": n}` stays an `ArrayBuffer`. Both share one output index space. Built in sign.rs from `Buffers::put` (no change to `Buffers`).
- **sign-prepare** checks in engine.ts order: no document, locked, `sourceBytes` > 50 MiB, signer fields (`name` 1..200 UTF-16 units, `reason` ≤ 200 without C0/DEL, strict boolean `certify`, finite `when`), `field` (non-empty string with `rect: null`), `encrypted`, DocMDP P=1 (`certified`), `certify` after a signature (`already-signed`), a new visible field on a certified document (`certified`), page, rect (4 finite numbers or `null`), then `checkSignatureField` (no-such-field, parent /V, hierarchy, not in /Fields, own /V, read-only, < 40x20). Messages are engine.ts's.
- **Source.** A document opened signed or certified (≤ 50 MiB) keeps its bytes in `AppSession::signed_source` (set by `open`); the output is an incremental update after those bytes, unchanged (checked again: `incremental save changed source bytes`). The copy edited is that file opened strictly, else, when the strict reader refuses only its layout, the file rebuilt from its own xref (`repair::rebuild` with a report that is not `damaged`: a hybrid /XRefStm, a linearized first-page section with a forward /Prev, xref offsets or startxref on the whitespace before their target, text after %%EOF), which keeps every object number and generation. A file that needs real repair is refused (below). Otherwise (unsigned) the copy is the app save of the current state (unsaved edits included, plaintext, `save`'s refusals and messages), reopened, and the output is a full app save (`WriteOptions::APP`, plaintext) of the edited copy.
- **New widget path** (MuPDF numbering): widget, then font and appearance (visible only), then the /Sig dictionary, then a new /AcroForm when there was none. Widget `<</Type/Annot/Subtype/Widget/P page/F 4/FT/Sig/T(Signature<n>)/Rect[...]/AP<</N ap>>/V sig>>`, `n` the first number no top-level /Fields /T uses. The page gets a direct /Annots array, its entries plus the widget, as MuPDF's `createAnnotation` writes it, so an array object it named (other pages or the form's /Fields may share it) stays as it is; the widget is pushed onto /Fields in place, or onto a direct copy when that array object is also a page's /Annots (app-accept-sign.md); /SigFlags 3; certify puts `/Perms<</DocMDP sig>>` on the catalog. A visible rect is clamped to `getBounds()`, refused under 40x20, and stored through the inverse page transform (`setRect`, float32 reals).
- **Field path**: the named empty top-level field keeps its object number; `/AP` is removed and re-added as `<</N ap>>`, then `/V`; the form gets /SigFlags 3. The reply's `rect` is the field's `getRect()`, and `field` is echoed.
- **Appearance and /Sig dictionary** are sign-prepare.ts's byte for byte, except the SubFilter: since October 19, 2026 it is `ETSI.CAdES.detached` (PAdES baseline B-B; /M is the claimed signing time, and tandem-sign writes no signing-time attribute): `q 0.93 0.95 1 rg 0 0 w h re f ... BT /Helv 9 Tf 0 0 0.15 rg 8 h-13 Td (Digitally signed by <name>) Tj 0 -11 Td (<YYYY-MM-DD HH:MM>) Tj [0 -11 Td (Reason: <reason>) Tj] ET Q\n` (numbers as JavaScript prints them, WinAnsi bytes with `?` and `( ) \` escaped), `/BBox[0 0 w h]`, `/Matrix` from the inherited /Rotate taken modulo 360 the JavaScript way (90, 180, 270, else identity), `/Resources<</Font<</Helv font>>>>`, a new Helvetica WinAnsi font per signature. `/Type/Sig/Filter/Adobe.PPKLite/SubFilter/ETSI.CAdES.detached/Contents<16384 zeros>/ByteRange[0 1000000000 1000000000 1000000000]/Name/M(D:...Z)/Reason?/Reference?` (`P 2`, `/V/1.2`), so `scanSignature` and `patchSignature` find `/Contents<` and `/ByteRange[` with no space.
- **Local time.** Rust has no time zone. The adapter adds `timezoneOffset: new Date(when).getTimezoneOffset()` to sign-prepare requests; the stamp is `when` shifted by it (whole minutes, |offset| ≤ 1440, else UTC). Native callers without it get UTC. /M is UTC as before. Dates follow ECMAScript (proleptic Gregorian, years printed unpadded).
- **Placeholder scan** is `scanSignature`: the sentinel and `/Contents<` + 16384 `0` + `>` each exactly once (past the source in an incremental output), `contentsAt` = the first hex digit, `byteRangeAt` = the `[`, `revisions` = every `/ByteRange` of an incremental output, else 1. The hole check stops at the first non-`0`, so the scan is linear.
- **Page geometry** (`widgets::Frame`) is MuPDF's `pdf_page_transform` in float32 with `info::page_size`'s box rules (CropBox within MediaBox, Letter when empty, unit square for a sliver, UserUnit, /Rotate rounded half up and snapped); rects go through `fz_transform_rect` (two corners on an axis-aligned matrix, four otherwise) and `fz_invert_matrix`.
- **Widgets** are the page's /Annots entries that resolve to `/Subtype /Widget` dictionaries; field type and full name are inherited through /Parent with a cycle check (a cycle makes the name unmatched, as MuPDF's throw does); read-only is bit 1 of the inherited /Ff.
- **Incremental writer** (`incremental::write_incremental(doc, changed, limits, entropy)`, or `write_incremental_after(doc, Original { bytes, size }, ...)` when `doc` is a rebuild of `bytes` with the same object numbers): the original bytes, a newline if they lack one, each object in `changed` (current value and stream, or a free entry when it is gone) in ascending order, one classic xref section, and a trailer `Size, Root, Info, ID, Encrypt, Prev` with /Prev = where the original's last `startxref` (in the final kilobyte before trailing whitespace, NUL included, which the strict reader also reads past) lands, past any whitespace (a classic table or an xref stream; tested with an object-stream original, read back by the core parser, hayro, MuPDF and pyHanko). /Size is the largest of every section's /Size, `Original::size`, the next free number and the largest written number + 1. /ID keeps its first element and gets a second one from SHA-256 of the update (deterministic). An encrypted document's changed strings and streams are encrypted with its own handler and key (`OutputCipher`, AES IVs from `entropy`, required), signature /Contents and /Type /XRef exempt; /Encrypt is repeated as the original has it. Refused: /Encrypt without an authenticated handler, /Encrypt removed, the /Encrypt object itself changed, offsets past ten digits, and output (original included) past `limits`.
- **Object numbers** for new objects start at the largest /Size of any section (at most MuPDF's 8,388,608) or past the largest object, as MuPDF allocates at its xref length, so a number the file listed (even as free) is never redefined. A rebuilt source's trailer lacks the numbers its object streams, xref streams and linearization dictionary had, so the floor there is the original chain's `RepairReport::xref_size` (largest /Size, /XRefStm included, or listed number + 1); a chain past 8,388,608 is refused (MuPDF repairs such a file). Regression: `hybrid_and_linearized_signed_sources_take_an_update_after_their_bytes` (numbers 8 and 9 would have redefined the object stream holding the font and the xref stream).
- **`RepairReport` gains `xref_sections` and `xref_size`** (core, additive): the sections of the file's own chain (an /XRefStm counted with its table) and the numbers it accounts for, set whenever the chain could be read.
- **sign-list `versions`** is `AppDocument::versions`, MuPDF's `countVersions` of the file as opened (app-core.md): its own sections, less a linearized file's first-page one (`xref_sections - linearized`) when the session document is a rebuild, or 1 when it needed repair (MuPDF repairs it into one section). Measured with MuPDF on hybrid, linearized and offset-quirk files, each signed once by pyHanko: 2, as here.
- **Bounds** on hostile files: the field walk is engine.ts's (4096 visits, 8 levels) but skips kids below the last level unvisited; the encrypted-form check visits a shared node once per depth and answers yes past 65,536 queued nodes; the widget page map stops after 2^20 /Annots entries; copied /Contents stop at 50 MiB (`too-large`); dates outside the ECMAScript range are refused. No `unwrap`, `expect`, indexing or unchecked arithmetic on document or request data.
- **Wire tests.** `tests/rust-engine-sign-wire.test.mjs` (default suite): `$bytes` decodes to a transferred `Uint8Array` sharing `$buffer`'s one-take index space; sign-prepare alone gets `timezoneOffset = new Date(when).getTimezoneOffset()` (America/Chicago: 300 in October, 360 in January), replacing a caller's value; and, on whichever engine `engine.js` resolves to, the appearance shows the Chicago stamp (`2026-01-14 21:30` for 03:30 UTC) and /M stays UTC.
- **Verified** (scratch harness through the WASM adapter, outputs signed with `fixtures/p5/leaf.p12` by `cms.ts`): MuPDF opens every output without repair and renders every page; `scripts/verify-sign.py` (pyHanko) reports INTACT, trusted and docmdp-ok for every signature of: Signature1/2/3 signed in place and incrementally (ENTIRE_REVISION for earlier ones), the rotated field, certify then fill (DocMDP 2), an authored field, second signatures on signed-intact (visible and invisible) and certified-p2-filled (an xref-stream original), fresh visible/rotated/Unicode/certified signatures and a twice-signed fresh file. certified-p2-annot.pdf fails pyHanko's DocMDP check before and after (the fixture's own annotation revision violates P=2); the new signature itself is INTACT and docmdp-ok. Second signatures on pyHanko-signed hybrid (MS Office layout) and linearized files and on an offsets-one-byte-early file: MuPDF opens them without repair (countVersions 3, as MuPDF's own outputs); pyHanko (non-strict, which hybrid files need) reports the first signature INTACT ENTIRE_REVISION and ours INTACT ENTIRE_FILE, trusted, as for MuPDF's outputs. Objects written match MuPDF's object for object on hello.pdf, empty-sigfield.pdf and signed-intact.pdf except the bullets below.

## Differences from MuPDF and engine.ts

- An invisible signature widget has `/Rect[0 0 0 0]` (ISO 32000 requires /Rect); MuPDF writes none (p5-sign's invisible-widget regex expects it).
- sign-list reads /ByteRange numbers exactly; MuPDF reads them through float32 (`pdf_to_real`), so offsets past 16 MiB came out rounded. A non-number entry is `malformed`; MuPDF read it as 0.
- A widget without /Rect reports the page-space image of [0 0 0 0]; MuPDF transforms its empty rect into `[2147483520, 2147484416, -2147483648, -2147482752]`.
- Direct (non-indirect) field and widget dictionaries are never matched to pages; MuPDF files every direct one under object number 0, so a direct field got the page of whichever direct widget came last.
- The encrypted-form check, the widget map and the /Contents copies are bounded (above); engine.ts recursed and copied without bounds (a shared /Kids or /V could make it exponential or copy one /Contents per field).
- `when` beyond ±8.64e15 ms is refused as `invalid` (the signer check's message); engine.ts wrote `NaN` dates.
- A pending or acknowledged `aes-256` security setting refuses sign-prepare as `encrypted`: engine.ts serialized the copy encrypted and reopened it without the password. A pending `none` signs a plaintext copy as before.
- prepareSignature's bare `invalid`/`too-large` errors carry messages (`sign-prepare: the signature needs at least 40x20 pt of the page`, `... the signed copy would exceed the 52428800 byte save ceiling`, `... the signature placeholders are not each written exactly once`); the reasons are unchanged. The renderer shows `error` to the user.
- A signed source that needs real repair (the rebuild's report is `damaged`: xref offsets inside objects, a lost xref, junk before the header, recovered stream lengths, catalog or page tree) is refused as `invalid` ("the signed file needs repair ..."), where MuPDF refuses with a plain error ("Can't do incremental writes on a repaired file"); the layouts measured that MuPDF reads without repair are signed as MuPDF signs them (hybrid, linearized, offsets or startxref on a line end, text after %%EOF; pyHanko INTACT for both signatures, MuPDF opens the output without repair). Before this fix the strict reader's refusal of those layouts was taken for damage.
- The update's /Prev is the original's last xref section itself; MuPDF copies the `startxref` value, which may land on the line end before `xref`.
- Objects a signature rewrites in a rebuilt source (page, catalog or form) carry the rebuild's fixes, e.g. a dangling /Annots entry dropped or a stale reference generation corrected; MuPDF writes them as it read them.
- open's `info.versions` counted the rebuilt session document (0 for a hybrid or linearized file signed once, where engine.ts reports 1); fixed in core: `AppDocument::versions` (app-core.md).
- When the form's /Fields array object is also another page's /Annots, the form gets a direct copy holding the new widget; MuPDF pushes onto the shared array, so its widget also shows on those pages, and pyHanko cannot compare MuPDF's revisions there ("Error in diff operation"). A page's own /Annots is written as MuPDF writes it (above).
- A signed source with more than 1 KiB of whitespace (NUL included) after %%EOF, which the strict reader opens without repair, takes an update after its bytes. MuPDF repairs such a file (its startxref search window) and refuses incremental writes; MuPDF opens the output without repair, and pyHanko, which cannot read the source, reports both signatures INTACT (the first ENTIRE_REVISION). Other text after %%EOF that puts the last `startxref` keyword more than 1,024 bytes before the end (after trailing whitespace) is the documented "needs repair" refusal, as MuPDF refuses it ("Can't do incremental writes on a repaired file"); up to 1,024 bytes the file signs on both. `sign-prepare` refuses a rebuilt file whose keyword the incremental writer does not find, so the two windows cannot disagree (round 3, `app-accept-sign.md`).
- A new widget on a page written directly into /Kids is refused (`invalid`): MuPDF would copy the page dictionary into the widget's /P. Signing an existing field there works.
- An /AcroForm whose /Fields is missing or not an array gets a new /Fields; an /AcroForm that is not a dictionary is replaced; a page /Annots that is not an array becomes one. engine.ts failed with MuPDF's "not an array".
- The update's trailer is a clean classic trailer; MuPDF copies an xref-stream original's `/Type/XRef/W/Index/Filter/Length` into its classic trailer (measured on certified-p2-annot.pdf).
- The update's /ID[1] is a digest of the update (same input, same bytes); MuPDF writes a fresh one. There is no `% Written by MuPDF` comment and no blank line before the first object.
- The unsigned source is the app save, which differs from MuPDF's save only as the APP-ENGINE-DESIGN Differences say (trailer /Size and /ID, garbage rules).
