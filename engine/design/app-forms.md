# Forms op group (fields, field-set, field-add, field-props, field-delete)

October 15, 2026. Port of engine.ts's form ops onto `AppSession`. Code: `src/app/forms/` (model, appearance synthesis, writing, the view's synthesized appearances) and `src/app/ops/fields.rs` (the five ops). Tests: `tests/app_forms.rs`. Evidence: `reference/app-forms-20261015/`.

## Design

- **Model** (`forms/mod.rs`). Widgets are the /Subtype /Widget dictionaries of the page's /Annots, in order, each object once. Attributes are read as MuPDF's accessors read them: /FT, /Ff, /V, /MaxLen, /Opt, /TU, /T inherited along /Parent (`pagetree::inherited`, 64 levels); full names joined over the /T chain (empty parts skipped, empty on a /Parent cycle); `widget_type` is `pdf_field_type` (unknown /FT is a push button). The engine.ts walks bounded at 8 nodes (`fieldValueName`, `fullFieldName`, `widgetScripted`) keep their bound.
- **Ids.** A widget's id is its object number. A widget written directly into /Annots lists as id 0, as engine.ts reports it, and cannot be filled, changed or deleted (`stale-target`).
- **Page space.** `PageSpace` is MuPDF's page transform (CropBox within MediaBox, UserUnit, snapped /Rotate) computed as `info::page_size` and the view's `PageFrame` compute it. `fields` reports /Rect mapped into page space; field-add and field-props write the request rect mapped back (`pdf_set_annot_rect`). Integral values are written as integers.
- **Journal.** Every write goes through `AppSession::mutate`'s `Transaction` (`Edit` and `Place` for values inside objects): one step per op, named `fill field`, `add field`, `change field` or `delete field`. Validation comes first and writes nothing, in engine.ts's order with its messages, reasons and details; a refusal never changes the journal. Batch modes work through `mutate` (edit-batch's plan runs the checks only). `fields::add_field(session, request, value)` is engine.ts `addField` with clip-paste's value override.
- **Appearances** (`forms/appearance.rs`). MuPDF 1.28's synthesis (`pdf_write_tx_widget_appearance`, the check box, radio and push button writers), measured on 59 recorded cases (`reference/app-forms-20261015/synthesis.json`, `tools/app-forms-oracle.mjs --synthesis`): every stream has MuPDF's operators, strings and numbers (to single precision) except the 11 deliberate differences below, asserted by `synthesis_matches_mupdfs_recorded_streams`. Text: border width from /BS /W or /Border (default 1), /MK /BG and /BC, clip inside the border, padding twice the border, baseline 0.8 and line height 1.116 of the size, DA size 0 meaning the height shrunk to fit the width (12 pt for multiline), quadding from /Q or /AcroForm /Q, comb cells across the whole width with dividers when /MK /BC is set, /MK /R turning the form. Check boxes draw ZapfDingbats `3` at the box size; radio buttons MuPDF's circles. Numbers are printed as MuPDF prints them (shortest single-precision digits, no exponent, `.5`).
- **Fonts.** Text is WinAnsi bytes. The DA font is the /DR font when it is a simple WinAnsi font (Type1, TrueType, MMType1), measured with its /Widths over its base 14 family's advances; otherwise a new base 14 font of its family (Helvetica when /DR lacks the name) under the DA's name, one object per op. ZapfDingbats is /DR's when /DR has it without an /Encoding, else a new one without /Encoding.
- **Writing** (`forms/write.rs`). A `Sink` allocates streams and fonts: `TxSink` in the journaled document, the view's in its private update. `refresh` replaces a widget's /AP with new objects and gives a button a name /AS (Off) when it has none; the replaced streams become unreachable and leave with the next save.
- **When appearances are written.** field-set of a text or choice field redraws every widget of the field (the node with /T and every widget below it, 4,096 at most). field-add draws every new widget but a signature's. field-props redraws when rect, maxLen, multiline, edit or options change, and drops a signature field's /AP instead. A fill of a check box or radio button writes /V and /AS only, as MuPDF does.
- **View** (`forms/view.rs`, hooked into `AppDocument::view`). As MuPDF does for display only, a widget without /AP /N, and every widget when /AcroForm /NeedAppearances is true, is drawn with a synthesized appearance: the widget redefined with /AP (and /AS when it has none) in the view's private update, the streams and fonts new objects numbered from the allocation floor. `overlay::join_redefined` writes new streams for this. Saves and `snapshot_bytes` never contain them. Signature fields, signed or not, and widgets without /FT keep what they have. Bounded at 20,000 widgets and 32 MiB of content per view; a drawn value is cut at 65,536 characters and multiline lines stop below the box.
- **Parser depth.** The app's parse limits allow 256 nested arrays and dictionaries (was 64): MuPDF reads a structure tree 81 levels deep (p6-tabs "debt1 row 4").
- **Bounds.** Field tree walks are bounded as engine.ts bounds them (4,096 nodes, depth 8); fills of a radio group visit 4,096 nodes at most; structure order stops at 50,000 nodes or 64 levels. No op code panics on hostile input (`hostile_fields_never_panic`: cycles in /Parent and /Kids, odd /DA, /Ff, /MaxLen, /Rect and /MK values).

## Measurements

- `fields` on all 54 fixtures (30 pages each at most): the same items as engine.ts on MuPDF on every page, compared as values.
- Op sequences (add of each kind with labels, flags, defaults and edit combos, fills, undo and redo, renames, props, deletes, refusals) on hello.pdf, form2.pdf, p6/tabs.pdf and the rotated and cropped pages of p3/form-design.pdf: the same replies (errors included) and the same listing after every step as engine.ts, object numbers aside (MuPDF allocates more objects).
- Widget pixels (`reference/app-forms-20261015/summary.json`, render op at scale 2, 8 scenarios, 54 widgets). Rust (hayro) against engine.ts (MuPDF), exact / within 16 levels: text 93.45 / 96.87%, checkbox 93.85 / 96.97%, combo 98.27 / 98.92%, radio 83.60 / 89.33%, list 79.61 / 80.27%, signature 97.14 / 97.19%. The remainder is the renderers (glyph programs, anti-aliasing of curves and strokes) plus the differences below. The two engines' saved files drawn by MuPDF alone (the appearance streams, without the renderer difference): checkbox, combo, radio and signature 100%, text 99.44% (the two props fields where engine.ts falls back to its single-line stream), list 80.47% (the selection highlight).
- App tests on Rust (`node tests/run-rust.mjs`): 162 → 213 passing, no test that passed before fails.

## Differences from MuPDF and engine.ts

- A widget written directly into /Annots lists with id 0 but cannot be filled, changed or deleted; engine.ts would act on the first such widget for id 0.
- The listing names each widget object once; MuPDF lists an object /Annots repeats once per entry.
- A fill sets the wanted state instead of toggling: a check box whose /V says on but whose /AS is missing turns off on `false` (MuPDF's toggle reads only /AS and would turn it on).
- A choice fill writes /V on the field (the nearest node with /T), like a text fill, and removes any /V on the nodes between it and the widget; MuPDF writes /V on the widget dictionary. A text or choice fill redraws every widget of the field, not only the one filled (engine.ts calls `update()` on one widget).
- field-props redraws with the full synthesis whatever changed; engine.ts's `refreshAppearance` falls back to its own single-line stream when no `setRect` dirtied the widget (a maxLen, multiline, options or edit change without a rect), so a multiline field changed there is drawn on one line until its next fill.
- New streams replace a widget's /AP; MuPDF rewrites its own earlier appearance stream in place. Text appearances name the /DR font object; MuPDF adds a separate Helvetica font object.
- field-delete also drops every other reference to the deleted widget, and to a radio group its last kid emptied (structure OBJRs, another page's /Annots), so a save never writes them; MuPDF keeps them reachable through the structure tree. Deleting the kid the group's /V names sets /V to Off (engine.ts leaves /V naming a kid that is gone). A missing /AcroForm /Fields is left alone (engine.ts throws a TypeError and abandons).
- field-add replaces a non-array /AcroForm /Fields with a new array (engine.ts fails pushing onto it). A page dictionary written directly into /Kids is refused with a plain error.
- Password fields draw one `*` per character; MuPDF draws the value in clear.
- A combo box draws the display text of the selected option (/Opt pairs); MuPDF draws the export value.
- A list box highlights its selected options (Acrobat's colour, behind each selected option's lines); MuPDF draws no selection.
- Check marks and radio dots take the DA colour, and a one-character /MK /CA chooses the ZapfDingbats mark (a radio's `l` keeps MuPDF's dot); MuPDF always draws a black `3` and a black dot.
- The push button background fills the whole box; MuPDF 1.28 writes `0 0 0 w re` and fills nothing. A push button's automatic size is at least 1 pt.
- A DA font /DR lacks keeps its name in the appearance's resources; MuPDF renames it Helv. Characters WinAnsi lacks are drawn as `?`; MuPDF switches to a fallback font (a CJK value draws in its Song font). Bytes outside printable ASCII are written as octal escapes.
- Numbers are computed in double precision and printed at single precision, so a few last digits differ from MuPDF's single-precision arithmetic (`3.2` for `3.1999994`).
- The view draws nothing for an unsigned signature field without /AP; MuPDF draws its "SIGN" marker (the known view difference).
- A /MK /R that is not a multiple of 90 is read as 0.
