# App CJK fallback font (M9)

October 15, 2026; review fixes October 16. The Rust build ships Droid Sans Fallback and draws CJK text in fonts a PDF does not embed, and the app's own CJK form values, with it. Read with `app-view.md` (the view's CJK route: `view::set_cjk_font`, `cjk_font_wanted`, `has_cjk_font`, the cue and its latch) and `app-worker.md` (build, policy, packaging). This note supersedes the install-time augmentation `app-view.md` described (it now points here).

## How the font ships: a committed copy (decision)

- `assets/fonts/DroidSansFallback.ttf`: 3,451,900 bytes (1,650,174 gzip -9; the repository's packs were 15.3 MB), sha256 `21b96a03…0b0949`, the pin of `docs/third-party/fixture-fonts.md`. `assets/fonts/README.md` records source, licence and pin. Unmodified.
- `scripts/cjk-font.mjs` holds the pin and `readCjkFont()` (sync read, sha256 check, a loud error naming the file when it is missing or differs). `scripts/build.mjs` checks it before `build/` changes, so a Rust build without the font fails; a MuPDF build neither checks nor carries it.
- Chosen over a fetch-and-cache build step because:
  - a fresh clone builds offline, CI included; with a fetch, every new checkout and CI runner needs the network once, and `npm test` (which runs `npm run build`) would too, where the tests never download today;
  - the fixtures' source URL is a moving branch (`aosp-mirror/.../raw/master/...`): the pin would keep a changed file out, but a moved or removed one breaks every new checkout;
  - the source at a release tag is then the whole build input (M10's reproducible build instructions);
  - the cost is one 1.65 MB compressed blob in history, once.

## Wiring

- **Build** (`scripts/build.mjs`): Rust copies the font to `build/renderer/fonts/DroidSansFallback.ttf` and its licence (`docs/third-party/droid-sans-fallback-NOTICE.txt`, Apache-2.0 with the AOSP copyright) beside it; `build/renderer/fonts` is emptied on every build, so a MuPDF build after a Rust one carries neither.
- **Policy** (`src/policy.ts`): Rust only, `/fonts/DroidSansFallback.ttf` as `font/ttf`. The CSP is unchanged (`connect-src 'self'` covers the read). The licence file is not served; the package drops it from `build/` and ships it under `licenses/`.
- **Package** (`scripts/package.mjs`, Rust): `licenses/third-party/droid-sans-fallback-NOTICE.txt` and a `NOTICE.txt` line naming the font, its copyright and licence. The font itself is in `app.asar` (`build/renderer/fonts/`), staged because it is served.
- **Adapter** (`src/renderer/engine-rust.ts`): `engine.useCjkFont(route, read)` (`route`: the package's module-wide `set_cjk_font`, `cjk_font_wanted`, `has_cjk_font`; `read`: the font's bytes, synchronously, or null). After every dispatch, when the engine raised the cue, the adapter reads the font once, installs it and, when `set_cjk_font` returned true and the op is `render`, `thumbnail` or `compare-render` with an ok reply, dispatches the same request again and answers with that reply. Renders are not journaled, so repeating one is safe; no other op is repeated (one that raised the cue just installs the font for the next render). Before `redact-apply` the font is installed when none is (its pixel check draws pages whose pixels are not returned, so it cannot be repeated). A read that fails, throws or is refused settles the route: never read again, nothing drawn twice (the engine's latch covers a refusal; the adapter's covers a failed read, which the engine cannot see). A trap in `set_cjk_font` stops the app like a trap in an op (`reason: "worker"`). `renderMs`/`paintMs` are the whole dispatch, read and first draw included (what the user waited; the status bar shows it).
- No renderer-visible change: the render reply that raised the cue is replaced by the second draw before it leaves the worker.
- **Worker** (`src/renderer/worker-engine-rust.ts`): `read` is a synchronous `XMLHttpRequest` (`responseType` `arraybuffer`, allowed in a worker) for `./fonts/DroidSansFallback.ttf`, synchronous like the dispatch that asks; a failure warns once on the console. `createRustEngine({ RustApp })` is unchanged (the Electron trap test patches that call), the route is set after it.
- **Node** (`tests/rust-engine.mjs`, so `tests/run-rust.mjs` and every tool on it, `engine/oracle/app-forms-oracle.mjs` included; `engine/oracle/corpus-run.mjs`): `useCjkFont(wasm, () => readCjkFont())` from the same committed file, so tests and the corpus run the app's behaviour. The corpus runner takes `--no-cjk-font` (or `TPDF_CORPUS_NO_CJK_FONT=1`) to run without it, for runs comparable with summaries made before, and records the choice as `meta.run.cjkFont`; `engine/reference/corpus-20261015/README.md` says so.

## Lazy, not at startup (measured)

- Node, WASM release build: `readCjkFont` 2.8–4.2 ms (0.6–0.9 ms of it the read); `set_cjk_font` 0.6 ms (it checks the tables and keeps the bytes; WASM linear memory 4.1 → 9.9 MB); the first render in each collection builds that collection's font (`by_cid`, below): GB1 79 ms, Japan1 35 ms, Korea1 28 ms, CNS1 37 ms for a two-character page (a later render 2–3 ms); memory 19.8 MB after one collection, 30.2 MB after all four (wasm32 memory never shrinks). The first version (augmentation at install): `set_cjk_font` 30 ms, 22.5 MB after install, 2–4 ms first renders.
- Electron 44, macOS arm64: first page through `--smoke --open` of a 200 × 120 pt page of two GB1 characters 70–78 ms with the first version, 98 ms now (read, install, GB1 build, two draws), against 2–4 ms for the same page in Helvetica; the tab's working set +20 MB (first version, one collection).
- At startup every worker would pay the read, the install and up to four builds (about 180 ms, 26 MB); on demand only a worker that meets such text does, once per collection it meets. The smokes on hello.pdf and form.pdf (source and packaged) never request the font.

## Engine font hook (`src/view/fonts.rs`): a font per collection, by CID

- **Why.** hayro draws a CID font without a program by Unicode first (the code's ToUnicode entry, or the collection's UCS2 CMap by CID when there is no ToUnicode) through the fallback font's cmap, and otherwise takes the glyph numbered like the CID. A code takes the second route when the ToUnicode lacks it (hayro then never tries the UCS2 CMap), maps it to several characters, to U+FFFF or to a lone surrogate, or when the cmap lacks the character. The first version installed one augmented Droid Sans Fallback (a total cmap: URW Latin and empty glyphs for every other character), which covered characters but not that route: Droid's glyph numbered like the CID, an unrelated character, was drawn (review; pdf.js-style synthetic page: IoU of ink against MuPDF 0.24–0.41 in those cells, 0 ink without the font). MuPDF draws by CID: the collection's UCS2 character through the font's Unicode cmap.
- **Now.** `set_cjk_font` keeps the font as given. The first render that needs a collection (GB1, CNS1, Japan1, Korea1) builds its font once (`Installed::font_for`, `by_cid`): glyph i is Droid's glyph for the UCS2 character of CID i (for a variation sequence its base character, as MuPDF draws it; other multi-character entries, such as Japan1's fractions and two-digit numbers, none, as MuPDF leaves them blank), URW Helvetica's at URW's advance where Droid lacks it, else empty; CID 0 and every CID the UCS2 CMap leaves out are empty. Its cmap (one format 12 subtable) maps each drawn character to its first CID. Both of hayro's routes then give the collection's glyph, and a CID past the collection is past the font: nothing.
- Droid composes 30,959 of its 49,775 glyphs from components; a component needs its own glyph id, and every id below the collection's CID count is a CID's, so composites are flattened into simple glyphs (offsets, scales, 2 × 2 transforms, point matching; 4 levels; coordinates are integers in Droid, so the outlines are exact). Built fonts: GB1 30,284 glyphs (4.8 MB), CNS1 19,179 (3.6 MB), Japan1 23,060 (3.9 MB), Korea1 18,352 (2.8 MB); natively 16–54 ms each.
- Every glyph has a long horizontal metric (Droid's own, URW's advance for its glyphs; hayro stretches a CID font's fallback glyph to its /W width by its advance, so URW Latin past `numberOfHMetrics` drew squeezed in the first version). Kept tables: OS/2, cvt, fpgm, gasp, name, prep, post as 3.0; GSUB, GPOS, GDEF and vmtx/vhea index glyphs and are dropped (hayro reads none of them for these fonts).
- Bounds: 32 MiB font; at most 2^20 cmap entries and 2^16 UCS-4 groups read; built glyph data at most four times the font's plus 1 MiB; flattening reads at most 2^24 points and component records in all. Past a bound, or for a font that is not TrueType (no glyf), the installed font is used as it is (its CID route then draws the font's glyph numbered like the CID).
- **Text of clipped runs.** Structured text keeps a run that leaves the clip by each glyph's ink. The empty font has no ink and Droid has, so the text kept depended on whether any render in the worker had installed the font (review: 日本語文 before, 日本 after; `text-all`, render text, `compare-text`, edit targets and redaction checks read it). A glyph of the CJK fallback (the installed, built or empty font, by pointer: `fonts::is_cjk_fallback`) now counts by its em box, whitespace by none, with or without the font. MuPDF gives 日本語 here.
- WASM 12,740,874 → 12,786,397 bytes (+45.5 KB, mostly the UCS2 CMap parser's copy for this call site).
- Tests: `view::fonts` unit tests `a_collection_font_puts_the_collections_glyph_at_each_cid` (CID order, a flattened composite with a component past the font, short metrics, URW advance, empty CIDs, cmap, dropped tables), `a_collection_font_maps_the_fonts_characters_past_the_bmp`, `a_collection_font_stays_within_its_budget`, `composite_glyphs_flatten_with_their_offsets_and_transforms`, `a_cid_draws_the_base_of_a_variation_sequence_and_no_other_sequence`, `only_a_truetype_font_is_rebuilt`. `tests/view_cjk_font_metrics.rs` (own binary; reworked from the first version's): with a test font whose glyph numbered like 日's GB1 CID is a bar, codes for that CID with no ToUnicode entry, with 日A, with U+FFFF and with a lone surrogate all draw the square; U+20000 for a CID neither font has and a CID past the collection draw nothing; URW 1 as wide as Helvetica's with and without /W; a clipped run's text the same before and after the install. It fails at the parent on the text and on the CID cells (the bar drawn). The three unit tests of the first version's augmentation are replaced (behaviour changed deliberately); `tests/view_cjk_font.rs` (view group) passes unchanged.

## Differences from MuPDF and engine.ts

- The font is read on the first render that needs it and each collection's font built on its first render (about 100 ms for the first GB1 page in Electron); MuPDF's WASM has it from startup. The reply that needed it is answered after the second draw.
- Latin, digits and symbols in a CJK font are URW Helvetica's (at URW's advance) where MuPDF draws them from a Droid Sans-like Latin; two veraPDF test pages are `render-pixels` for it.
- A code whose ToUnicode character is in the collection draws that character (hayro's rule) where MuPDF draws its CID's; they differ only when the ToUnicode contradicts the CID, and then the ToUnicode is the better guess when a producer wrote glyph ids as CIDs. A code with no usable Unicode, or whose character is outside the collection or missing from both fonts, draws by CID as in MuPDF.
- CID 0, and a CID whose UCS2 character neither Droid nor URW has, draw nothing; MuPDF draws some of them from its other fallback fonts (CID 0 as U+FFFD's replacement glyph).
- A clipped run of CJK text drawn without its font keeps the glyphs whose em boxes meet the clip (日本 of 日本語文 clipped at 70 pt); MuPDF keeps 日本語.
- A CJK character past the BMP that the font lacks draws nothing, as in MuPDF; one the font has (5 in Droid Sans Fallback) draws.
- A Type0 font with `90ms-RKSJ-H` whose CID font has no /FontDescriptor: MuPDF ("missing font descriptor") reads the codes as one-byte Latin and draws Latin letters; Rust decodes the CMap and draws, and extracts, the CJK characters. Rust is right; the file stays `render-pixels` and `text-differs`.
- `redact-apply` installs the font before it runs (one read, even for a document without CJK text), so its pixel check sees CJK text as MuPDF would draw it.

## Open

- Memory: each collection's built font stays for the life of the worker (2.8–4.8 MB each, the installed font 3.5 MB); a worker that meets all four collections holds about 30 MB of WASM memory. Dropping the built fonts with the last document that used them would need a hook in the session's close.
- Vertical forms: a vertical CMap's CIDs draw their UCS2 character as hayro maps it (often the horizontal form); MuPDF substitutes vertical presentation forms for a few punctuation characters. Unchanged by this work.
- hayro keeps one outline per glyph per render, so a glyph used with two /W widths in one render is stretched by its first (upstream).
- Packaging and the synchronous read are verified on macOS arm64 only (Electron 44); Windows and Linux packages are M10.
