# App ops: stamp, batch-file, compare

October 15, 2026. `src/app/ops/stamp.rs` (stamp, batch-file) and `src/app/ops/compare.rs` (compare-open, compare-close, compare-render, compare-text), ported from engine.ts `stampPages`, `batchFile` and the `compare-*` cases.

## Design

- **stamp** checks in engine.ts order: `require_mutable("stamp")`, `check_stamp_action` (kind, text length and WinAnsi, align, batesPad, batesStart, `bates-start-required`), page selection (`pages::check_pages`, then sorted and deduplicated; absent means every page), `check_bates_range`, then one `mutate` step named `add watermark`, `add header` or `add footer`. Reply: `bates?` then `edit_state`.
- **Contents budget**: before any write the stamp loop sums, over the pages it marks, the /Contents entries each keeps plus its two new streams, and refuses past `MAX_STAMP_CONTENTS` (2,000,000) with `too-large` (`stamp: the pages would list more than 2000000 content streams`; batch-file `too-large` without detail). Every page gets its own copy of a shared /Contents array, so 3,000 pages sharing 99,000 entries (a 949 KB file) asked for 297 million copies and aborted the WASM engine. At the budget (1,000 pages sharing 1,998 entries, WASM, M-series) the stamp takes 0.09 s, the next render 0.6 s, undo 0.01 s, and the save is 12 MB.
- **What a page keeps** (`kept_contents`): an array's items, a lone stream, nothing for a missing, null or dangling /Contents, and any other value kept between the stamp's streams as engine.ts keeps it, but only on a `/Type /Page` dictionary. Any other dictionary is refused as `stamp: not-a-page: page N has a /Contents that is not content` (`invalid`; batch-file `stamp-error`, detail `not-a-page`): the brute-force page list of a tree without /Kids (`info::pages`, as hayro) also lists annotations and signatures, and stamping one replaced its text with a content array.
- **Writes**, all through the step's `Transaction`: per page a `q\n` stream and the stamp stream (`tx.allocate`, unfiltered, `<</Length n>>` as MuPDF's `addStream`), `/Contents` becomes the direct array `[head, ...own streams, tail]`, and `/PDF4AllF` goes into the page's font resources unless they name one. The font is `<</Type/Font/Subtype/Type1/BaseFont/Helvetica/Encoding/WinAnsiEncoding>>` (MuPDF `addSimpleFont` order). Undo, redo and abandon restore exactly (tested byte for byte on full rewrites).
- **Stream text** is MuPDF's: `Q\n/PDF4All <</Kind /Watermark|Header|Footer>> BDC <fill> BT /PDF4AllF <size> Tf a b c d x y Tm (<bytes>) Tj ET EMC\n`, numbers as JavaScript prints them, positions `round2`. On an unrotated page a header, footer or right-aligned footer is byte-identical to MuPDF's (measured: `1 0 0 1 502.08 36 Tm (ACME-000007 1)` on nav.pdf).
- **Text**: `{bates}`, `{page}`, `{pages}` (the document's count), `{label}` (`labels::items`, the 1-based index when empty), in that order; the result is WinAnsi bytes with `?` for anything else and `(`, `)`, `\` escaped. Bates numbers are `start + position` in the sorted page list, zero-padded to `batesPad` (6).
- **Placement**: the page's visible area (inherited CropBox within inherited MediaBox, as `info::page_size`, Letter when empty) in unrotated user space, and its display rotation (/Rotate snapped to a quarter turn). Headers and footers use engine.ts's visual-to-page mapping and upright matrices, 36 units from the visual top or bottom, 36 from the left or (right-aligned) ending 36 from the right by Helvetica advances (`builtin_metrics`). Watermarks are 48 pt, centred on the area, rotated 45° past the display's upright.
- **batch-file save**: `saved` maps the writer's result: past the ceiling (the writer's output limit or a longer result) is `too-large` without detail, any other writer error `stamp-error` with detail `save` and the writer's message (unit-tested on synthetic errors; a 51 MiB unfiltered stream checks the ceiling end to end, since p6-batch "batch (d)" patches MuPDF and cannot run on Rust).
- **batch-file** never touches the session: refusals are `Ok` replies `{id, ok:false, reason, detail?, error}` with no journal fields, in engine.ts order (no bytes, too large, the stamp action with its token as `detail`, too few bytes, unreadable, encrypted, signed, no pages, bad pages, Bates range, stamp, save, save ceiling). The file opens with `AppDocument::load` (the same tolerant open as `open`); its own journal only provides the `Transaction` the shared stamp loop writes through. The output is the app save (`WriteOptions::APP`, plaintext) under the 50 MiB ceiling.
- **Compare slot**: `CompareDocument` holds an `AppDocument` (never journaled or written), its name, source size and a process-wide serial. `compare-open` checks name, at least 5 bytes, the pair rule `bytes + session.source_bytes > MAX_PDF_BYTES` before opening, then the same tolerant load as `open`, encryption and page count; a refusal keeps the old slot. `open`'s pair rule reads `CompareDocument::source_bytes`; `close` keeps the slot.
- **compare-render** is `view::render_page` on the compare document's cached view (same pixels, text and lines as `render` of those bytes), reply `{page, width...renderMs}` with no `revision`; the adapter times it as it times `render`.
- **compare-text**: refusals in engine.ts order (no document, locked, the main document's copy bit via `info::permissions`, no compare document, `checkPage` on each side), lines from `StructuredText::line_summaries` (the preserve-spans layout, whole-point y-down bbox `[x, top, x+w, top+h]`), more than 2000 lines on either side is `too-many`, then engine.ts's suffix-LCS walk on `trim` + whitespace-collapsed keys (u16 table, at most 2001² cells, built after the line check).
- **`CompareDocument` value**: a `const CompareDocument` (an empty slot) keeps the unit placeholder this type replaced constructible, so the existing session tests that store `Some(CompareDocument)` and expect `{}` from `debug_json` compile and pass unchanged; dispatch never creates it. compare-render and compare-text treat it as no compare document, `open` as 0 bytes, `session_debug` shows it as `{}` and the harness, which keys slots by `serial`, as `session.compare === null`. Removing it means editing `tests/app_core.rs` and `tests/app_dispatch.rs` (a test constructor opening a fixture), which needs approval.
- **Test harness**: `session.compare` is `{doc, name, pageCount, sourceBytes}`, one object per slot (keyed by the serial in `session_debug`). `doc` is a MuPDF copy of the bytes Rust compares (bridge `compare_bytes`), opened on first read and destroyed when the slot is replaced or emptied, checked after every `open`, `compare-open` and `compare-close` dispatch, as engine.ts destroys the slot's document. p6-compare "compare (c)" is no longer skipped.

## Differences from MuPDF and engine.ts

- Inherited /Resources: the stamp font joins the resources dictionary the page draws with, where it lives (the page's own, or an ancestor's through a direct or indirect /Parent, as `pagetree::inherited` walks 64 levels, or the shared object a reference names); engine.ts gives such a page its own `/Resources << /Font << /PDF4AllF >> >>`, hiding every inherited font and XObject (§8.7). A /Resources or /Font that is not a dictionary (a number, a dangling reference) is replaced by one on the page.
- Placement box: the inherited CropBox within the inherited MediaBox; engine.ts reads only the page's own /CropBox, else its own /MediaBox, else Letter, so a page with an inherited 400 pt MediaBox got its header at y = 756, off the page.
- Rotation: /Rotate snapped to a quarter turn, as MuPDF and hayro display it; engine.ts places by the truncated raw value, so /Rotate 45 (displayed as 90) was placed as 0.
- UserUnit: the layout is in user space (margins, sizes and the right edge scale with the page); engine.ts mixed MuPDF's UserUnit-scaled bounds with unscaled placement.
- Watermarks read upward along the diagonal on the display for every /Rotate; engine.ts ignores /Rotate (upside down at 180, downward at 90). Unrotated pages keep engine.ts's matrix.
- Watermarks are centred by the Helvetica advances of the drawn text; engine.ts estimates half an em per UTF-16 unit (a 45-digit Bates watermark sat 60 pt off centre along its line). Right alignment measures the bytes drawn, so a label character drawn as `?` is measured as `?`; engine.ts measured MuPDF's glyph for the original character.
- `{label}` is inserted literally; engine.ts's `replaceAll` expands `$&`, `$$`, `` $` `` and `$'` in a label.
- Stamps share one font object across operations by finding an existing /PDF4AllF resource equal to the stamp font on any page (MuPDF's per-document font cache shares it while the document is open). After an undo removed it a new one is made, so the freed-object case engine.ts patches (bugfix B1) cannot occur.
- A page written directly into /Kids is given its own object in the stamp's step, after the page-tree normalization page ops use (ISO 32000 /Kids holds references); MuPDF edits it in place.
- batch-file writes plaintext explicitly (encrypted inputs are refused before); messages for an unreadable file or a failed save carry the Rust loader's or writer's text.
- compare-open and batch-file open with the app's tolerant load (strict, then junk before the header skipped, then repair); their "could not be read (...)" detail is the Rust loader's.
- Rust opens only PDFs, so a file MuPDF opens as another format (PNG, XPS, EPUB...) gets `compare-open: the file could not be read (...)` / `batch-file: the file could not be read (...)`, never engine.ts's `...: the file is not a PDF`; the reason (`invalid`, `not-pdf`) is the same.
- Stamp work is bounded (`MAX_STAMP_CONTENTS`); engine.ts copies a shared /Contents array into every page without a limit.
- A dictionary that is not `/Type /Page` and whose /Contents is not content (a brute-force "page" that is really an annotation) is refused instead of having its /Contents replaced; engine.ts never sees such a page, as MuPDF's repair lists only /Type /Page dictionaries.
- compare-text of a page refused as too complex (see the view's limits) is a plain `compare-text: page is too complex: ...` error; MuPDF reads it however long it takes.
- compare-text lines are the view's preserve-spans lines, so the view's text differences apply (for example ActualText keeps "Alpha" one line where MuPDF splits it).

## App tests

- p2-decorate 14/14, p6-compare 9/9 (with "compare (c)" unskipped), p6-batch 7/8 (+2 Electron skips), p6-bates 0/0 (2 Electron skips).
- p6-batch "batch (d): every call leaves no transient document alive" fails by design of the test: it counts MuPDF `Document.openDocument`/`destroy` calls and replaces transient documents' `saveToBuffer` (`failSave`), which a Rust engine never calls. It belongs on the `tests/run-rust.mjs` skip list.
