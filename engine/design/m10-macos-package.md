# M10: the packaged build on macOS ARM64

> Licence note (October 18, 2026): the Rust engine and the app are now MIT, and no MuPDF code ships. Where this document says engine code is AGPL or MuPDF-derived, or that a build owes AGPL obligations, it records the state before the clean-room relicense (see the Licence section of [`PROVENANCE.md`](../reference/PROVENANCE.md)).

October 17, 2026. Branch `app-p10-pkg` from `de398ab` (`rust-engine-app`). The completion plan's M10 item "real packaged builds on macOS ARM64 ... WASM startup, fonts and assets, dialogs, filesystem recovery, printing, high-DPI, attribution and reproducible build instructions", checked on the package `npm run package:rust` makes, not on the dev build. darwin-arm64 only; Windows and Linux are below.

## How it was checked

- **Package**: `npm run package:rust` (`scripts/package.mjs`) under memcap, 2 min 05 s, peak 546 MB: `out/Tandem PDF-darwin-arm64/Tandem PDF.app`, 342 MB, `app.asar` 18.9 MB with 352 entries, ad-hoc linker signature (unsigned). `ENGINE` is `rust`, the packaged WASM is the `engine/web/pkg` one (sha256 `651fa243…e762`), and no file in `app.asar` names MuPDF.
- **Checklist tool**: `scripts/check-macos-package.mjs --work=<dir>` launches the packaged binary (`Contents/MacOS/Tandem PDF`) about 25 times, each with its own userData, through the app's existing `--smoke` and `--drive` paths, and writes a JSON report. It exits 0 only if no item fails. `tests/m10-package.test.mjs` runs it when `TPDF_PACKAGE_CHECK` names a work folder and the package exists. Otherwise that test skips; the file's other tests always run.
- **Drive harness**: `scripts/drive.mjs` gained `--app=<binary>` (default `TPDF_DRIVE_APP`), which drives a packaged binary instead of `electron .`. It runs from the repository folder, so relative fixture paths in scripts resolve as before. A test that runs `drive.mjs` therefore drives the package when the variable is set. The shipped agent folder's `scripts/session.mjs` already drives the packaged binary it sits in.
- **Smoke**: the plain `--smoke` report gained `startup` (`firstPageAtMs` since the process's Node timeOrigin, `firstPageEpochMs` wall-clock, `mainStartedAtMs`), set when the renderer reports the first page drawn. It is smoke-only and has a dev-build test in `tests/m10-package.test.mjs`.
- **Native dialogs are not exercised.** Every open, save, Save As, export and print path ran with its picker pre-answered (`path`/`to` in a drive line, `--save-to`/`--print-to` on a smoke), as in all the app's tests. The AppKit open and save panels, the print dialog and the About window were never shown. Their wiring (`dialog.showOpenDialog`/`showSaveDialog`, `webContents.print`) is unchanged code shared with the dev build.

## Bugs and gaps found

1. **Missing licence files (fixed).** wasm-bindgen 0.2.129 and wasm-bindgen-shared are compiled into the shipped WASM, and the JavaScript glue comes from wasm-bindgen-cli. The build-time crates wasm-bindgen-macro, wasm-bindgen-macro-support and bumpalo had no folder in `engine/reference/licenses` and were not named in `engine/NOTICE`; every other crate of the WASM's tree had one (95 crates). Added their `LICENSE-MIT` and `LICENSE-APACHE` files verbatim from the crates.io sources, plus an `engine/NOTICE` paragraph. `tests/m10-package.test.mjs` now fails when any crate of `cargo tree --target wasm32-unknown-unknown -e normal` lacks a folder, and the checklist checks the package's copy. The October 14 hash record `reference/app-view-20261014/license-files.json` is a dated record and was not changed.
2. **The WASM depended on the checkout path (fixed).** It held 120 absolute checkout paths and 225 `$HOME/.cargo/registry` paths, which also carried the builder's user name. Remapping alone was not enough. cargo hashes path dependencies outside the bridge's workspace (the engine and the vendored hayro crates) by absolute path into `-C metadata`, which changes symbol names and code order. That is also why the gates' `6e900969…` differed from builds here. `build-workflow.sh` now remaps the paths, and `tools/rustc-stable-metadata.sh` (a `RUSTC_WRAPPER` for the wasm32 build only) gives those crates a path-independent hash. The WASM hash changed once: `651fa243…` became `31e0f62b…`. The wrapper ignores dependencies' cargo hashes, so a cached host proc macro cannot change the result. A remap named after the wrapper's hash makes cargo rebuild when the wrapper changes. A package built before this change still passes the `sources.sha256` check, because `tools/` is not listed, so rebuild it once.
3. **Electron fuses are at their defaults (reported).** The packaged binary honours `ELECTRON_RUN_AS_NODE=1` (it runs as plain Node) and `--inspect` (a debugger port opens). `ElectronAsarIntegrity` is written to `Info.plist`, but its check is off: the repacked `app.asar` in the M9 run loaded without complaint. For a signed release, set the fuses (RunAsNode, EnableNodeCliInspectArguments off; EnableEmbeddedAsarIntegrityValidation, OnlyLoadAppFromAsar on). That needs `@electron/fuses`, a new dev dependency, so it was not done here. Unsigned builds are unaffected in practice. **Owner decision** (the dependency).
4. **The source URL in `NOTICE.txt` does not exist yet.** It points to `https://github.com/Shiro-Legacy/TPDF/releases/tag/v0.1.0`, and nothing is pushed. The AGPL source offer holds only once that tag and its source are published with the release. **Owner decision**: when and where to publish the tag and the source.
5. Packaging prints `WARNING: Could not find icon "assets/icon.icns" with extension ".icon"`. @electron/packager looks for a macOS 26 Icon Composer file first. The `.icns` icon is used; harmless.

## Windows and Linux

Not covered. `npm run package:rust` was run for darwin-arm64 only. `scripts/package.mjs` accepts `win32-x64` and `linux-x64`, but cross-packaging a Windows or Linux Electron on this Mac proves nothing about running it, and nothing is pushed, so `release.yml` has never run a Rust package. The installer scripts (`installer.iss`, `make-linux.sh`, `install-*.{ps1,sh}`) are unchanged and untested with the Rust engine. The checklist tool is macOS-specific: bundle layout, `cp -c`, `codesign`. On the other platforms the binary path and the clone step would differ, while the drive and smoke steps carry over. `app-p9-mobile-release` prepares the release workflow for Rust (not merged). Its `scripts/check-package.mjs` was not used here.

## Costs

The checklist takes about one minute for about 25 launches, each peaking at 600–750 MB under memcap. The drive suite on the package takes about 1–2 minutes for 51 scripts, peaking at 1,087 MB. The WASM builds peaked at 1,283 MB (cached target directory) and 1,257 MB (empty target directory, 2 min 47 s).
