# Core: journal cost, text strings, document info, reference cutting

October 15, 2026. Cross-cutting fixes the op groups recorded, in `object.rs`, `document.rs` and `src/app/{journal,document,edit,info}.rs`, with the helpers they share. Read with `../APP-ENGINE-DESIGN.md`; where this file and that one disagree (Journal and transactions, Differences), this one describes the code.

## Journal cost

- **Copy-on-write dictionaries.** `object::Dictionary` keeps its entries behind an `Arc` (`Ordered(Option<Arc<Vec<Slot>>>)`, `Sorted(Arc<BTreeMap>)`). Cloning is O(1); every method that writes (`insert`, `get_mut`, `remove`, `retain`, `iter_mut`, `values_mut`) unshares first (`Arc::make_mut`; `clear` starts afresh), so a write copies the dictionaries on its path, each shallowly (keys, scalars, strings and arrays it holds directly; nested dictionaries stay shared). `get_mut` and `remove` of an absent key copy nothing. An empty dictionary allocates nothing (`Dictionary::new` stays `const`). `shares_entries` tells whether two dictionaries share their entries; equality returns early when they do. The public API, ordering and sorting rules are unchanged.
- **In-place updates.** `Document::update_value(id, edit)` edits an object's value where it lives. A stream's value must stay a dictionary: the edit runs on the live value and, when it breaks that, the value is put back from an O(1) copy and the write refused (the old message). `Transaction::update` and `Builder::update` use it; both used to clone the whole value, edit the clone and write it back, once per call, so an operation that updated one large object n times copied it n times.
- **One state per object and step.** A step stores, per touched object, the state the document does not hold: the befores while it is applied, the afters once it is undone. Undo and redo swap them with the document's (`Document::exchange`, `exchange_trailer`), copying nothing; `end` takes no after snapshots. Abandon moves the befores back. `untouch_if_unchanged` compares with `Document::is_in_state`, without a snapshot.
- So an operation pays the first-touch snapshot of each object (O(1) for a dictionary, a shallow copy for an array object) and the path copies of its writes, and a step keeps what its writes changed: before and after share every dictionary the edits did not reach, with each other and with the live document.
- **Reference cuts.** `pagetree::cut_references` used to rewrite every holder in place, visiting (and now copying) every container in it. `Cut::cut` builds the holder's new value from the paths to its cuts, each container visited once, the others left shared. It recurses at most 256 levels (the parser's nesting limit); a value an op nested deeper is cut in place as before.
- **Not shared.** Arrays and strings are plain values: writing a dictionary copies the arrays it holds directly (`/Kids`, `/Annots`, `/Nums` written inline), and a top-level array object is copied by its first-touch snapshot, once per operation. Making `Object::Array` shared would change a public enum variant used in about 230 places; left for when a measured case needs it.
- **Memory.** A non-empty dictionary costs one more allocation (the `Arc` header, 40 bytes). Opening 200,000 objects of two dictionaries each (25.7 MB): WASM memory 228 MB before, 237 MB after; open time unchanged within noise (1.1-1.4 s either way).

## Text strings

- `object::decode_text_string` reads a text string as MuPDF's `pdf_new_utf8_from_pdf_string` does: a byte order mark picks UTF-16BE, UTF-16LE or UTF-8; without one, bytes that are valid UTF-8 holding a non-ASCII character are UTF-8, and the rest PDFDocEncoding. Measured with MuPDF 1.28.1 through mupdf.js on outline titles, /Info, annotation /Contents, field /T and /V, page label prefixes, layer names and `asString`: every reader uses the same rule.
- `object::decode_text_prefix(bytes, max)` decodes at most `max` bytes and says whether bytes were left out; a character the cut splits (UTF-8, or the first half of a UTF-16 surrogate pair) is left out, and a cut UTF-8 string still reads as UTF-8. The forms listing (`text_prefix`), page label prefixes and the nav group's titles and URIs clip with it.
- Every caller now reads with the rule: annotation /Contents and /Subj, field names, values and defaults, rich-text /V streams, signature names and reasons, sign widgets' field names, grafted field names, page label prefixes, layer names, attachment names (`info`), outline titles, URIs and destination names (nav), the edit scan's ActualText checks, and the view's ActualText (`stext::text_string`, which read Latin-1 without the PDFDocEncoding table). The password table (`password.rs`) decodes single bytes, which no UTF-8 rule touches.
- nav's private decoder is gone: `target::decode_text` is `decode_text_prefix(bytes, MAX_TEXT_BYTES)`.
- Through the adapter against engine.ts on MuPDF, `outline`, `annots`, `fields`, `labels` and `layers` of a page whose strings are UTF-8 without a mark, CJK UTF-8, Latin-1, PDFDocEncoding specials, UTF-8 with a mark and UTF-16LE: 30 of 30 replies the same (22 of 30 before: annotation contents, field names and values, label prefixes and layer names of the two UTF-8 cases differed).

## DocumentInfo

- **versions.** `AppDocument::versions` is MuPDF's `countVersions` of the file as opened, kept from the load: the strict reader's xref sections; for a layout the strict reader refuses and the repair rebuilds without damage (hybrid, linearized, offsets on whitespace, text after %%EOF), `RepairReport::xref_sections` less the linearized first-page section; 1 after a repair (MuPDF rebuilds one section). `info.versions` is that less one; sign-list's `versions` is it (sign-list no longer rebuilds the source a second time to count).
- **algorithm** is read as the security handler reads /Encrypt (`EncryptionInfo::from_dictionary` on /Encrypt resolved three levels deep), as APP-ENGINE-DESIGN's rule says (the code still had engine-core.ts's): V5 or AESV3 `aes-256`, AESV2 `aes-128`, RC4 `rc4-40` for R2 or a 40-bit key and `rc4-128` otherwise, Identity or an unknown crypt filter `unknown`; /Encrypt that is not a dictionary `unknown`.
- Checked through the adapter against engine.ts on MuPDF: every fixture (54/54 same `info`) and 20 generated layouts (classic, xref stream, hybrid, linearized and a stray /Linearized dictionary, each with 0-2 incremental updates; junk before the header; offsets moved in the first or last section; a truncated file; a truncated update): 18/20 same, the two below. Before: 14/20 (every hybrid and linearized file with an update reported 0 versions).

## Reference cutting after an annotation leaves its page

- `annots::cut_unlisted(target, groups)`: after annotations left page /Annots arrays, cuts every other reference (structure OBJRs, another annotation's /IRT or /Popup, other arrays and dictionaries) to each annotation no page lists any more, by its /Annots entry or the object that resolves to, in one pass over the document. A group any page still lists stays whole. The catalog, page-tree nodes (in the tree, or typed /Page, /Pages or /Catalog) and streams are never cut.
- `annots::remove_many` (annot-delete, and what removes annotations through it) and `links::remove_many` (link-delete) both end with it. annot-delete used to cut everything, other pages' /Annots included; link-delete used to cut without the structural guard, so a page that also called itself a link left the page tree when deleted as one.
- annots `remove_many` also removes /Annots entries that reach the annotation through a reference chain (they were left in place).

## Compare slot

- `CompareDocument::open(name, bytes)` opens bytes as compare-open does (the tolerant load, no password) and takes the next serial; compare-open uses it and keeps its own refusals (size of the pair, encrypted, no pages). The placeholder value (`const CompareDocument`, an empty slot) and its `Option` are gone: a slot always holds a document. `tests/app_core.rs` and `tests/app_dispatch.rs` open hello.pdf instead; the debug JSON test now expects the slot's fields.

## Differences from MuPDF and engine.ts

- Text strings: UTF-8 overlong forms, encoded surrogates and code points past U+10FFFF read as PDFDocEncoding; MuPDF takes them as UTF-8 and passes the invalid bytes on (mupdf.js shows U+FFFD per byte). PDFDocEncoding's undefined codes (0x7F, 0x9F, 0xAD) keep their Latin-1 value, as pdf.js reads them; MuPDF maps them to U+0000, which mupdf.js shows as two U+FFFD. The nav group read 0x9F and 0xAD as one U+FFFD; its tests (`target.rs` unit test, `app_nav.rs` `text_strings_read_as_utf8_when_they_are_and_pdfdoc_otherwise`) now expect U+009F and U+00AD. A NUL ends nothing; MuPDF's C strings stop there.
- `algorithm`: V4 with RC4 crypt filters is `rc4-128` (engine.ts `aes-128`); Identity or an unknown /CFM is `unknown` (engine.ts `aes-128`); V2 R3 without /Length is `rc4-40` (engine.ts `rc4-128`); an AESV3 filter not named StdCF is `aes-256`.
- `repaired` and `versions` are decided at open for the whole file: an update section whose offsets are wrong makes the open a repair (`repaired: true`, versions 0). MuPDF loads objects lazily and reports `repaired: false` and the sections at open, then repairs on the first access to a bad object (after a render: `repaired: true`, one version), so the values agree once MuPDF has read the page.
- A truncated incremental update (objects appended after the last %%EOF without their xref section): MuPDF opens the last complete revision unrepaired; the repair scan here takes the appended objects and reports `repaired: true`. Left to the repair module's owner: which revision such a file should show is a repair-policy decision.
- annot-delete of an annotation that another page also lists removes it from this page only and cuts nothing else (link-delete's rule); the second page keeps it whole, and its references are cut when the last page's entry goes. The annotations group's note said every page lost it; `tests/app_annots.rs` `delete_takes_the_popup_and_cuts_references_once_no_page_lists_it` now deletes it from both pages. MuPDF removes the page's entry and cuts nothing.
- link-delete never cuts the catalog, a page-tree node or a stream that an /Annots entry names as a link: it only leaves the page's /Annots.
