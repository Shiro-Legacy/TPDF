# Remaining CID font work after the image foundation

Read-only inventory,2026-10-06. This does not implement or accept Type0 support. It records an independent next work package in REWRITE-ROADMAP.md after the reviewed opaque-mask extension.

The final R23 refusal census has five documents blocked first by Type0 fonts: cjk.pdf:1,p0b/edit-embedded.pdf:1,p0b/edit-subset.pdf:1,p3/edit-subset2.pdf:1 andrtl.pdf:1. Direct original fixture dictionaries show /Encoding /Identity-H and descendant /CIDFontType2 in each. The first four name DroidSansFallback variants; rtl.pdf has NotoSansHebrew andNotoSansArabic descendants. Each declares ToUnicode and indirect /W data. This identifies source structure, not a claim that their embedded glyphs, metrics or subsequent operators are already supported.

The current architecture is deliberately one-byte: TextFont::validate_unicode rejects non-one-byte mappings; advance() takes u8; CodePlacement stores u8; simple HorizontalMetrics owns at most256code widths; embedded glyph APIs use byte Encoding and simple-font cmap selection. Type0 cannot be added by merely widening an integer or treating ToUnicode scalars as glyph IDs.

A concrete design must separate original width-preserving source code, encoded CID, optional Unicode mapping, declared CID advance and embedded glyph ID. Identity-H can be the first explicit encoding profile, with exactly two source bytes per code, declared /DW and /W parsing, validated CIDToGIDMap semantics, actual descendant/descriptor/program ownership, bounded sparse metrics and checked font/glyph identities. Existing simple-font paths and byte provenance must retain their behavior. Missing Unicode, missing glyph, valid empty outline and valid default advance remain distinct conditions.

Native reference behavior can be inspected in pinned source/pdf/pdf-font.c: CIDToGIDMap handling around1243–1260 and DW/W handling around1320. These are investigation entry points, not an accepted substitute for an explicit strict Rust contract. The current outline decoder separately refuses composite glyphs; inventory the actually selected embedded GIDs and outline formats before deciding whether Type0 integration also depends on composite TrueType support. No unsupported glyph may disappear behind successful text decoding or font-load status.

Required work remains: independent original-code→CID→GID/advance/Unicode traces; full source-byte and output-span lifetime; multibyte text positioning/spacing and TJ cases; scoped resource inheritance/rebinding and cache budgets; malformed descendant/maps/width ranges; native versus exact unhinted outline placement; original-page raster evidence and preservation of all prior accepted results. RTL Unicode display order or shaping is not inferred from the fixture filename or from successful two-byte decoding. General CMaps, vertical writing, CFF CID fonts and external substitutions remain separately explicit capabilities.
