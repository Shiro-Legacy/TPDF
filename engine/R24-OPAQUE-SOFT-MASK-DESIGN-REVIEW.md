# R24 opaque-soft-mask design review

2026-10-06. Design-only review of `R24-OPAQUE-SOFT-MASK-DESIGN.md` following the R23 adapter audit. No R24 implementation is authorized to begin before the R23 acceptance checkpoint is preserved.

The proposed invariant is sound within the stated restricted profile: a fully validated effective Gray8 mask plane containing only 255 contributes full opacity at every selected texel, so the existing opaque sample compositor need not change. The proposal correctly validates all samples, retains mask provenance, excludes Matte/interpolation/nested mask semantics, avoids recursive publication, and distinguishes this from general transparency. Both measured corpus masks are uniformly 255; they provide no evidence for nonopaque alpha behavior.

Implementation should make these points explicit:

1. **A cached base still traverses its dependency contract.** The current R23 fast cache-hit return checks only that asset's shape/filter count. An R24 base-cache hit must charge the mask-dependency attempt/lookup and recheck the retained mask under the current structural caps and semantic role. In particular, a base with no filters may reference a filtered mask; lowering `max_filters` after caching must not bypass mask validation. Unique/certificate/decoded-work ceilings of zero may still permit a valid cache hit, without fictitious new certification or decoding.
2. **Resolve SMask as an authenticated stream edge.** R23's ordinary metadata resolver deliberately rejects stream-valued metadata. Add a metered stream-aware path for this one field; preserve actual final ObjectId, bounded reference/cycle handling and null-after-resolution semantics. Do not weaken the generic metadata resolver or perform a second unmetered resolution. A mask loaded as an ordinary image must not satisfy the role check solely through object identity, and a cached base with its own mask must never become a mask operand.
3. **Define the exact reservation meaning of new counters.** State whether `certified_masks` counts successful published certificates or conservatively admitted certificate attempts, and whether `opacity_scan_samples` is visited work or a full-scan reservation. Either bounded interpretation can work, but tests must assert that interpretation consistently. Reserve a complete scan before access when using a conservative ledger; repeated failed scans must not reset it. Precharge certificate-table growth and result/cache handles; cloning an existing Arc does not allocate a new Arc header.
4. **Opacity proof must precede dependent publication.** The base enters its usable cache only after base decode, mask role/shape validation and complete effective-byte scan succeed. Independently valid mask samples may remain cached after base failure, but the failed attempt must not publish an opacity certificate or bypass the next attempt's dependency admission. Early/middle/last nonopaque bytes and errors after successful mask decode need explicit regressions.
5. **Make unsupported mask-role fields an explicit allow/refusal list.** The design mentions transfer functions, while the current R23 image loader only rejects its enumerated rendering-changing keys. The mask-role validator must explicitly enforce the intended `/TR` or other transfer-function exclusion rather than assuming unknown metadata is rejected by the ordinary image loader. Keep malformed/null/reference handling consistent; do not broaden allowed ColorSpace, Decode, Matte, nested masks or external sources accidentally.
6. **Preserve failure identity without unreserved allocation.** The final error should identify both the originating base SMask field and the failing mask stream/phase. The existing page-level image error-box allowance uses `size_of::<ImageError>()`; verify it remains sufficient after representation changes. A failed allowance must return an inline bounded refusal. Direct-loader errors must not acquire new uncharged boxes or dynamically copied diagnostic strings.

Add cache-order tests beyond the listed gates: ordinary mask image → masked base; masked base → direct mask draw; shared mask under two distinct bases; successful cached base followed by tighter mask filter/shape ceilings; failed scan followed by unrelated valid image; and same object numbers in different documents. Separate dependency depth from reference-hop depth. Test exactly one admissible soft-mask edge even when user caps are larger.

For native evidence, prove the original SMask reference and its decoded effective alpha bytes before comparing masked versus unmasked output. A constant-255 sample check plus an independently observed source dependency is stronger than a native output-only match, which could miss ignored masks. Include nonopaque negative controls whose native rendering differs from the unmasked base. No R23 accepted page hash should change, and removing the mask refusal must not imply acceptance of later unsupported marked-content operators.

These are contract clarifications and regression requirements, not evidence of implemented support. General alpha compositing, differing mask resolutions, soft-mask groups, transfer functions and image masks remain outside this proposed stage.
