## Latest accepted milestone: R16 document page traces

`PageProgramSession` connects the document reader, exact logical page-content
joining, used-font preparation, typed page geometry and persistent C0 mixed
interpreter. Owned results retain joined bytes, occurrence segments, font
identities and original operation/source provenance. `project_range` preserves
synthetic padding and repeated stream occurrences without inventing file offsets.

Every selected Tf is prepared, even without a show. Font caches persist across
pages; execution immutably borrows frozen caches. Library policy defaults to
DeclaredOnly; CLI modes explicitly enable and report AllowPinnedBase14. Malformed
mapping/metric data never falls back. Missing Encoding retains M1's strict refusal.

`--page-program=N` emits a full trace for one-based page N and fails with no
partial stdout. `--page-programs` processes all pages in one cumulative session,
emitting compact traces and precise per-page refusals. A bad geometry result is
isolated to its page. Successful outputs outlive the session/document/input.

Cumulative phase budgets are admitted before work, including both parser passes.
Failure reservations remain charged. Exact joined-buffer allocation requests are
measured; inventory, font/cache, parser and prior Document work are explicitly
separate partitions. These are not process-RSS or universal allocator claims.
Unsupported page groups and default device-color overrides refuse explicitly.

## Remaining work and limitations

This is a page-content trace milestone, not a complete renderer or MuPDF replacement.
The page path still refuses Type0/CJK fonts, Forms/images, marked content, named
color spaces, transparency and unsupported text/state operations. Encrypted PDFs
remain unsupported. Annotations are not executed. Native callbacks cannot recover
resource alias identity; Rust identity/provenance is tested separately. Tr3 color
is independently tested because native ignore_text does not expose it.

Next bounded design work should connect source codes to actual glyph IDs/outlines
and then rasterize the supported font subset; Form/image execution and broader
font/PDF coverage require separate milestones. Do not imply the standalone outline
reader already renders PDF text. App integration and full UI regression testing
remain future work.
