# Independent review: optional integer orthogonal rasterizer

Reviewed `src/raster.rs`, the P0-to-raster boundary and CLI publication, the pinned backend audit, and resource planning. No blocking issue remains within the explicitly narrowed R0 scope. This review does not extend acceptance to general PDF rendering or arbitrary tiny-skia inputs.

The pre-implementation native probe exposed incompatible fractional, degenerate and slanted-edge conventions. Only 16 of 200 random integer triangles matched the candidate backend, while all 50 nondegenerate integer rectangle probes matched. That evidence justified the approved restriction to simple nondegenerate orthogonal contours with exact integer device coordinates inside the canvas. Fractional source coordinates remain valid if the final transform produces accepted integer device coordinates. General slanted polygons were not admitted by merely requiring integer vertices.

`tools/differential-raster.py` records 304 passing programs and 311,296 exact pixels in `reference/raster-differential-r0.json`. Each output agrees byte-for-byte with both the independent mask expectations and pinned native oracle under the endpoint RGB palette. The generated cases include signed/compound rectangles, concave L and U contours, winding and even-odd fill, overlap/cancellation, clipping, q/Q restoration and old-clip paint ordering. Four targeted cases cover fractional-source scaling, reflection, quarter-turn and noncommuting transform composition. Twelve unsupported geometry/paint/suffix cases refuse with empty stdout. The dedicated feature executable and native oracle hashes stayed unchanged.

The review also found that native interior color conversion does not match the chosen Rust policy. Root explicitly retained the documented round-half-up Gray/RGB byte quantization and limited native color parity to components 0 or 1. Eight separate strips, totaling 2,042 pixels, validate all byte centers and nominal quantization ties plus values just below/above them for both Gray and RGB. All independent expectations pass. Native differences are recorded per strip, not hidden behind tolerances. These tests check the specified f64 quantization operation; they are not an exact-real-arithmetic or color-management claim.

Five tests in `tests/review_raster.rs` pass, along with feature-specific strict Clippy and rustfmt:

- Lines after an explicit close continue from the original subpath start and form the intended subsequent contour, under both fill rules.
- Separate contours sharing an edge produce no pixel seam.
- Initial page-space clipping receives the page-to-device transform, including axis exchange.
- Sibling clips consume every retained mask even when maximum ancestry depth is only one.
- Unsupported geometry/paint remains an error even when an initial Empty clip makes it invisible.

Resource review confirms target dimensions/pixels/output limits precede pixel allocation; every paint/clip transforms and validates its geometry; per-path and cumulative command caps bound pairwise contour validation; scan planning includes height times squared edges and pixel passes; all retained clip masks and ancestry are bounded; and the entire plan must succeed before rendering. Flat masks and contours avoid recursive ownership. P0's immutable private events prevent forged arena references through the public API. Empty move/close runs are removed before backend traversal, and accepted contours contain nonzero axis-aligned edges with nonzero area and no self-intersections. Unsupported suffixes cannot publish a partial image.

The source-derived backend audit was checked against pinned `edge_builder.rs` and `scan/path.rs`: bounded integer in-canvas geometry avoids the line clipper, uses exact vertical-edge fixed-point values, and limits path/edge/sort storage. The owner's isolated capacity instrumentation records a maximum reported single allocation plus sort allowance of 73,120 bytes among its four probes, below the adapter's reserved 1 MiB backend allowance. The source caps and restricted execution path, not that sample maximum alone, support the bound. Planned storage is a conservative requested-capacity account, not exact allocator RSS.

This optional boundary retains internal dependency unsafe code and infallible backend allocations. Our adapter remains safe Rust, but process OOM recovery and a universal positive backend-success signal are not provided by stock tiny-skia. Those limitations are explicit in RASTER-DESIGN.md; they must not be described as an unsafe-free dependency tree or general all-allocation-fallible rendering. Root owns the full feature/core/MSRV/notice gates. Dedicated raster validation used `target/raster-gate` to avoid concurrent default-build collisions.
