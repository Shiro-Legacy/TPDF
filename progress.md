## 3. Architecture

1. Small main process: native dialogs, approved file handles, validated narrow IPC, safe writes, lifecycle. No document content executed as code.
2. Sandboxed renderer: no Node, context isolation, restrictive CSP (no inline styles), no remote content, permissions/navigation denied.
3. MuPDF module worker inside that renderer: one authoritative document, render/text/annotation/edit ops, engine journaling for undo/redo. No FS or network. All saves `incremental=no,garbage=yes`.
4. Disk: originals untouched by edits; PDF is the interchange format; small OS-native settings files only. No database, custom format, plugin system, backend.
5. Alternatives only on demonstrated failure with user approval: native MuPDF/helper; PDFium/PDF.js never as a second default engine; QPDF only for a proven gap; Ghostscript/veraPDF/LibreOffice only for P6 gates. QA tools may be installed locally without shipping.

## 5. Process

**Unit pipeline as practised (Agent session, Drive guard; Agent tool, no Workflow):**

4. Backup `pre-<unit>-review-<date>.tgz`.
5. One Opus 5.5 reviewer, refute-first (may fix small issues itself, §1; each fix with a test that fails on pre-fix code) → `review-<unit>.md`.
6. Gate, one lock hold, outside the sandbox (osascript), in the background: `zsh .quad/shared/p6/scripts/accept-unit.sh <unit> <new drives, comma list> <shot.mjs under checks/> '<png glob under checks/review-out/>' <new test files, comma list, or -> <baseline>`. **Contract ground rules (§0, unchanged since P6 U1):** proven or refused — every write is proven by the scan or refused with a fixed token + detail; one journal op per gesture, undoable; a refused or no-op gesture never dirties; `garbage=yes` saves; STATE stays truthful after every step (never change an existing key's shape — `nav.links` and `fields.defs/values/last` are deep-equalled in `tests/p3-drive.test.mjs`; new keys are safe); fixture hashes unchanged; no new dependency; no new renderer `.js` file; content-edit bounds still enforced; every new engine op has an `OP_PERMISSION` entry (coverage test) and a renderer `OP_MODE` entry where it is a mode op; human-and-AI parity (§1). Drive `expect` rules: exact values, absolute `revision`, click before key, geometry via `pick()` in the harness.

**Ownership and briefs:** one owner per file per unit; other seats make additive edits only where the contract says; implementers get reset, so briefs must stand alone (resend direct briefs after a reset). Reviewer fix authority per §1. Every finding needs an owner or it falls to the orchestrator.

**Gate first:** probe the mupdf primitives with tests before any write path; stop the unit on an unproven operator mapping, non-atomic journal, COW leak, corrupted appearance, lost semantics, permission leak, mutation during inspection, changed save options, security regression, exceeded budget or an unexpected existing-test failure; never grow a parser, add a library, raise caps or go native without a new decision (picking a fallback is the orchestrator's or the human's call).

## 7. Cross-cutting release gates

- **Save semantics:** work on a copy; default save-as; atomic replace only after validated reopen; preserve encryption; no plaintext recovery files for encrypted docs; journaling for undo, separate snapshots for crash recovery; signed docs read-only or permission-aware incremental; redaction output purges history and never keeps prior revisions; disk-full/permission/external-modification/cancel/crash-in-write tests mandatory.
- **Hostile PDFs / privacy:** no automatic JavaScript, launch actions, rich media, external fetches, shell execution or attachment opening; protocol-allowlisted links; extraction cannot escape its destination; engine under a real sandbox with bounded IPC payloads and timeouts; no telemetry/crash upload/remote fonts/update pings without opt-in; prove no network attempts with a network present and offline; logs never contain document text, secrets or full sensitive paths.
- **Fidelity corpus:** grow from real failures; provenance/licence for every fixture; no private documents; every mutation reopened by our engine **and** an independent parser/renderer (pypdf, `qlmanage`; later PDF.js/PDFium/QPDF/veraPDF as QA only) with tolerances, not byte identity; redaction proof needs independent extraction and object inspection.
- **Accessibility/packaging:** keyboard-only for every shipped flow; canvas alone is not accessible reading; same pinned commit builds on every supported OS; record matrix, sizes, ceilings, notices; public release needs signing/notarization, hardened-runtime review, install/uninstall checks, opt-in updates.
