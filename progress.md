## 3. Architecture

1. Small main process: native dialogs, approved file handles, validated narrow IPC, safe writes, lifecycle. No document content executed as code.
2. Sandboxed renderer: no Node, context isolation, restrictive CSP (no inline styles), no remote content, permissions/navigation denied.
3. MuPDF module worker inside that renderer: one authoritative document, render/text/annotation/edit ops, engine journaling for undo/redo. No FS or network. All saves `incremental=no,garbage=yes`.
4. Disk: originals untouched by edits; PDF is the interchange format; small OS-native settings files only. No database, custom format, plugin system, backend.
5. Alternatives only on demonstrated failure with user approval: native MuPDF/helper; PDFium/PDF.js never as a second default engine; QPDF only for a proven gap; Ghostscript/veraPDF/LibreOffice only for P6 gates. QA tools may be installed locally without shipping.

## 5. Process

**Unit pipeline as practised (Agent session, Drive guard; Agent tool, no Workflow):**
1. Under the lock (§0): backup `.quad/backup/pre-<unit>-<date>.tgz` and fixture snapshot `.quad/shared/p6/checks/<unit>-hash-before.txt` (56 lines).
2. Contract `.quad/shared/p6/contract-<unit>.md`: ground rules below, decisions D1…, exact ops/STATE/drive steps, ownership of **every** file the unit can touch (incl. `scripts/drive.mjs`, `src/main.ts`), acceptance. The human approves it (or orders the decisions in chat) before any build.
3. One Opus 5.5 implementer via the Agent tool with a standalone brief (agents get reset; resend the brief, no time budgets — phrase waits as file/lock conditions). It writes `<unit>-build.md` and `.quad/shared/p6/acceptance/<unit>-red-before.log` (new tests run against pre-fix code: the gate needs ≥ 1 `not ok`).
4. Backup `pre-<unit>-review-<date>.tgz`.
5. One Opus 5.5 reviewer, refute-first (may fix small issues itself, §1; each fix with a test that fails on pre-fix code) → `review-<unit>.md`.
6. Gate, one lock hold, outside the sandbox (osascript), in the background: `zsh .quad/shared/p6/scripts/accept-unit.sh <unit> <new drives, comma list> <shot.mjs under checks/> '<png glob under checks/review-out/>' <new test files, comma list, or -> <baseline>`. With `-` the new tests live in existing files and `<baseline>` is the expected `# pass` count; otherwise pass must reach baseline + new tests. It runs tsc, build, `npm test` (`# fail 0`, `# skipped 1`), the red-before log, new drives ×3 plus the regression drive list, a secrets grep, 9 OK in `fixtures.sha256`, hash-after = hash-before, the GUI script with real osascript keystrokes, `npm run package`, and ends `== result: fail=0`. When the human is at the machine use `zsh .quad/shared/p6/scripts/accept-unit-nogui.sh` (same arguments, GUI step deferred) and run the shot script later. Logs land in `.quad/shared/p6/acceptance/<unit>-*`.
7. View the PNG with Read.
8. Write `.quad/shared/p6/acceptance/acceptance-<unit>.md`; update this file's state line, the §6 index (full record appended to `docs/history.md` Part 1) and §10 leftovers; update memory.

Windows for a reset: after the implementer returns and after the reviewer's file exists; never mid-run. Write every contract/review/evidence file to disk immediately. Earlier units used the Workflow tool with the generic `.quad/shared/p6/scripts/unit-build.js` → `unit-review.js` → `unit-fix.js` (still usable; `p6u4…p6u8-*.js`, `accept-u4…u8.sh` and `*-objections.js` there are superseded per-unit templates). The full-mode pipeline (objection lenses, three-lens review, integrator), lean mode and the quad-bus rules are in `docs/history.md` Part 2. ## 7. Cross-cutting release gates

- **Save semantics:** work on a copy; default save-as; atomic replace only after validated reopen; preserve encryption; no plaintext recovery files for encrypted docs; journaling for undo, separate snapshots for crash recovery; signed docs read-only or permission-aware incremental; redaction output purges history and never keeps prior revisions; disk-full/permission/external-modification/cancel/crash-in-write tests mandatory.
- **Hostile PDFs / privacy:** no automatic JavaScript, launch actions, rich media, external fetches, shell execution or attachment opening; protocol-allowlisted links; extraction cannot escape its destination; engine under a real sandbox with bounded IPC payloads and timeouts; no telemetry/crash upload/remote fonts/update pings without opt-in; prove no network attempts with a network present and offline; logs never contain document text, secrets or full sensitive paths.
- **Fidelity corpus:** grow from real failures; provenance/licence for every fixture; no private documents; every mutation reopened by our engine **and** an independent parser/renderer (pypdf, `qlmanage`; later PDF.js/PDFium/QPDF/veraPDF as QA only) with tolerances, not byte identity; redaction proof needs independent extraction and object inspection.
- **Accessibility/packaging:** keyboard-only for every shipped flow; canvas alone is not accessible reading; same pinned commit builds on every supported OS; record matrix, sizes, ceilings, notices; public release needs signing/notarization, hardened-runtime review, install/uninstall checks, opt-in updates.

## 11. Session protocol

1. Read §0, §5, §11, then the unit's record in `docs/history.md`. Confirm repo contents before assuming anything exists (`npm test` must print `# tests 626`, `# pass 625`, `# fail 0`, `# skipped 1` until the next unit changes the baseline).
2. The orchestrator is whoever the human names (if a seat is down, the orchestrator also reviews); the human picks every unit and approves every contract before a build. Never start a build on an unapproved contract.
3. After each unit: one line in §6, the full record (decision, changed paths, checks with actual outcomes, ceilings, next) appended to `docs/history.md` Part 1, leftovers in §10, the state line updated; durable lookup facts go into `docs/gotchas.md`; per-unit evidence goes under `.quad/shared/<phase>/` (build/review/rerun `.md` files ≤ 40 lines: paths, numbers, what was not done) and `acceptance/acceptance-<unit>.md`; update memory.
4. Never reintroduce OCR or proprietary SDKs. Never pass `--no-sandbox`. Never redistribute `out/`. Never kill the human's Electron. Never `save-in-place` a fixture.
